## 〇、一句话

**参考工程的 SD 卡通信链（4 个文件、872 行）可以一个字不改地搬过来**，但它的对外协议是"电平 + 两种脉冲"混用，且有 3 个会让人卡死的坑。所以建议**包一层**，把接口变成干净的 `req / done / byte_valid`，你们上层只跟这一层打交道。

## 一、整体层次与"谁驱动 SD 卡"

```
你的模式状态机（W2 自写）
        │  只需要："把第 k 张图载入缓冲区 B"
        ▼
🔧 img_loader（建议封装 B，对标参考工程的 sd_card_bmp，但接口做干净）
        │
        ├── bmp_read.v（第4站，可照搬）   ← 解析 BMP 头、按像素输出
        │
        └── sd_card_top.v（第5站四层，可照搬）
                ├── sd_card_sec_read_write.v
                ├── sd_card_cmd.v
                └── spi_master.v
                        ▼
                   SD 卡 4 根线（A12 / A14 / A13 / B14）
```

> 🔴 **单一所有者原则**：SD 卡是**独占资源**，`sd_card_top` 只能有一个驱动者。
> 参考工程里驱动者是 `bmp_read`（它自己举 `sd_sec_read`），`sd_card_bmp` 只提供参数。
> **你们不要让两个模块都去举 `sd_sec_read`** —— 要么用 🔧 `img_loader` 统一收口，要么自己做仲裁。
>
> 🔧 `sd_sec_reader`（封装 A）只在**你不用 `bmp_read`、自己写扫描/解析**时才需要。两条路选一条，别混用。

## 二、层次 0：`sd_card_top` 原接口（✅ 已存在，可原样搬）

### 2.1 参数

| 参数 | 默认值 | 含义 |
|---|---|---|
| `SPI_LOW_SPEED_DIV` | 248 | 初始化阶段分频。`spi clk = clk / ((DIV+2) × 2)` |
| `SPI_HIGH_SPEED_DIV` | 0 | 读数据阶段分频，同上公式 |

**本板 `clk` = `sd_card_clk` = 100 MHz**，所以：

| 阶段 | DIV | 实际 SPI 时钟 |
|---|---|---|
| 初始化（CMD0/8/55/41/16） | 248 | **200 kHz** |
| 读数据（CMD17 之后） | 0 | **25 MHz**（卡的上限） |

**默认值直接可用，一个字都不用改。**

### 2.2 端口（逐字抄自源码，共 17 个）

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---|---|
| `clk` | in | 1 | **必须给 100 MHz 的 `sd_card_clk`** |
| `rst` | in | 1 | **异步、高有效**（源码是 `always@(posedge clk or posedge rst)`） |
| `SD_nCS` | out | 1 | → 板卡 **A12** |
| `SD_DCLK` | out | 1 | → 板卡 **A14** |
| `SD_MOSI` | out | 1 | → 板卡 **A13** |
| `SD_MISO` | in | 1 | ← 板卡 **B14** |
| `sd_init_done` | out | 1 | ⚠️ **电平**，但见第 4.2 节的坑 |
| `sd_sec_read` | in | 1 | ⚠️ **电平，必须举着**，见 4.1 |
| `sd_sec_read_addr` | in | 32 | 扇区号（LBA，1 扇区 = 512 B） |
| `sd_sec_read_data` | out | 8 | 字节流 |
| `sd_sec_read_data_valid` | out | 1 | **重复脉冲**，一次读来 512 次 |
| `sd_sec_read_end` | out | 1 | **一次性脉冲，只高 1 拍** |
| `sd_sec_write` | in | 1 | 写请求 —— **你们的方案用不到，接 `1'b0`** |
| `sd_sec_write_addr` | in | 32 | ↑ 接 0 |
| `sd_sec_write_data` | in | 8 | ↑ 接 0 |
| `sd_sec_write_data_req` | out | 1 | 悬空即可 |
| `sd_sec_write_end` | out | 1 | 悬空即可 |

> **写路径不用删**：综合器会把没被使用的逻辑优化掉。这是分层的额外好处。

### 2.3 两个不能碰的细节

| 细节 | 值 | 说明 |
|---|---|---|
| `CPOL` / `CPHA` | **`1'b1` / `1'b1`** | 在 `sd_card_top.v` 第 119~120 行**硬编码**。这是 SD 卡 SPI 模式必须的 **Mode 3**，**不要去改** |
| 卡的模式 | **SPI 模式** | 靠 `nCS` 在 CMD0 期间拉低进入，**不需要任何跳线**。TF 卡座 6 根线全引出，参考工程只用其中 4 根 |

## 三、一次"读扇区"的完整时序

驱动方（你们）只需要做 4 件事：

| 步 | 时刻 | 你要做的 |
|---|---|---|
| 1 | 上电后 | 给 `rst`（异步高有效）足够长的复位脉冲；然后**什么都不用做**，`sd_card_top` 自己跑初始化序列 |
| 2 | 想要读 | 先把扇区号放到 `sd_sec_read_addr`，然后**把 `sd_sec_read` 拉高并一直举着** |
| 3 | 读的过程中 | 每个 `sd_sec_read_data_valid` 脉冲取一个字节 `sd_sec_read_data`，**自己数到 512** |
| 4 | `sd_sec_read_end` 来的那拍 | **立刻把 `sd_sec_read` 拉低**（除非你还想马上读下一个扇区） |

### 3.1 内部初始化序列（你看不到，但要知道它走了什么）

```
S_IDLE → CMD0 → CMD8 → CMD55 → CMD41（循环重试）→ CMD16 → S_WAIT_READ_WRITE
                                                              ↑
                                              到这里才开始看 sd_sec_read / sd_sec_write
```

| 命令 | 作用 |
|---|---|
| （不发命令） | **上电先空发 11 字节 `0xFF` = 88 个时钟**，满足规范"≥74 个时钟"，且这期间 **CS 保持高**。实现位置是**层2 `sd_card_cmd.v` 的 `S_INIT`**，不是层3 |
| CMD0 | 复位卡进入 SPI 模式（**同时把 CS 拉低**才是进入 SPI 模式的关键） |
| CMD8 | 查询电压，判断是否为 SDHC |
| CMD55 + CMD41 | **循环重试**直到卡就绪 —— 这是协议要求，不是 bug。耗时几百毫秒 |
| CMD16 | 设置块长度 = 512 字节（⚠️ **对 SDHC/SDXC 是空操作**，块长本来就固定 512） |

### 3.2 `sd_init_done` 比"真正就绪"早一拍命令（⚠️ 坑 2）

源码里 `sd_init_done <= 1'b1` 是在 **CMD41 应答成功时**置起的，而**紧接着还要发 CMD16**。

所以：**`sd_init_done` 变高 ≠ 可以立刻发读了**。此时状态机还在 `S_CMD16`，它**不看** `sd_sec_read`。

**正确做法**：不要"看到 `init_done` 就打一拍读请求"，而是**把请求举成电平**（第 2 步就是这么做的）。只要你举着，状态机走到 `S_WAIT_READ_WRITE` 自然会看见它。

## 四、三个会让人卡死的坑（务必写进你们的规范）

### 4.1 🔴 坑 1：`sd_sec_read` **必须举着**，不能打一拍

源码在 `S_WAIT_READ_WRITE` 里是 `else if (sd_sec_read == 1'b1)` —— 它只**采样电平**。

- ✅ 正确：`sd_sec_read <= 1'b1;` 然后**一直保持**，直到 `sd_sec_read_end` 才拉低
- ❌ 错误：读之前打一拍窄脉冲 → 状态机可能还在 `S_CMD16`，**脉冲被漏掉** → 你永远等不到 `sd_sec_read_end` → **死等**

> 参考工程 `bmp_read.v` 的写法（`ST_SCAN` 状态）就是标准答案：
> `sd_sec_read <= 1'b1;` 写在状态开头，`if (sd_sec_read_end) sd_sec_read <= 1'b0;`

### 4.2 🔴 坑 2：`sd_sec_read_end` 后**要拉低**，否则会立刻重读

状态机是 `S_READ_END → S_WAIT_READ_WRITE`，而 `S_WAIT_READ_WRITE` 马上又看 `sd_sec_read`。

**如果你不拉低，它就在下一拍用（可能已经变了的）地址再读一次。**

- 想**只读一个扇区**：`if (sd_sec_read_end) sd_sec_read <= 1'b0;`
- 想**连续读多个扇区**：有两种都合法的写法
  - 写法 A（参考工程的）：`end` 那拍拉低 + 地址 +1 → 下一拍再举起（中间空 1 拍）
  - 写法 B（更省事）：**一直举着不放**，只在 `end` 那拍把地址 +1 → 状态机回到 `S_WAIT_READ_WRITE` 时看见电平还是高的，直接用新地址开始下一个扇区，**零间隙**

### 4.3 🔴 坑 3：`sd_sec_read_data_valid` 是"重复脉冲"，要**自己数到 512**

- 它是 `(state == S_READ) && block_read_valid`，**一次读扇区会出现 512 次**
- 用 `if (sd_sec_read_data_valid) cnt <= cnt + 1;` 累加
- 用 `else if (sd_sec_read_end) cnt <= 0;` 清零 —— **注意是 `else if`**，因为结束那拍不会再给 `data_valid`
- 一次读扇区 = **正好 512 个字节**，不要假设别的长度

### 4.4 附：性能数字（来自走读第5站）

| 项目 | 数值 |
|---|---|
| 一个扇区（512 B @ 25 MHz SPI） | ≈ **175 µs** |
| 一张 640×480 的图（约 1.84 个扇区/行 × 480 行 ≈ 900 KB） | **0.3 ~ 0.5 秒** |
| 用途 | **所以双缓冲是必须的**（你们方案已有 ✅） |

## 五、🔧 建议封装 A：`sd_sec_reader`（把电平协议包成事件）

> **只在你们不用 `bmp_read`、要自己写扫描/解析时使用。**

### 5.1 接口（建议）

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---|---|
| `clk` / `rst` | in | 1 | 同 `sd_card_top`（100 MHz，异步高复位） |
| `init_done` | out | 1 | 电平：初始化流程已走完（**可以只当"卡在不在"的指示，不要用它触发读**） |
| `req` | in | 1 | **1 拍脉冲**：启动一次读。`busy` 期间忽略 |
| `sec_addr` | in | 32 | 起始扇区号，`req` 当拍有效（内部会锁存） |
| `sec_count` | in | 16 | 读几个扇区（1 = 单扇区；读整张图就填整张图的扇区数） |
| `busy` | out | 1 | 电平：正在读 |
| `done` | out | 1 | **1 拍脉冲**：`sec_count` 个扇区全部输出完 |
| `byte_data` | out | 8 | 字节流 |
| `byte_valid` | out | 1 | 脉冲，每字节一拍（一次读共 `sec_count × 512` 个） |
| `cur_sec` | out | 32 | 当前正在读的扇区号（调试 / 上层判断用） |
| `byte_in_sec` | out | 10 | 当前扇区内偏移 0~511（省得上层自己数） |
| `SD_nCS`/`SD_DCLK`/`SD_MOSI` | out | 1 | 直接接板卡引脚 |
| `SD_MISO` | in | 1 | ← 板卡 |

### 5.2 内部要做的事（约 60~80 行）

1. 例化 `sd_card_top`（原样），把它的 4 个 SD 引脚原样引出。
2. 用寄存器把 `req` 锁存成**电平**，接到 `sd_sec_read` —— 这样就自动绕开了坑 1 和坑 2。
3. `sd_sec_read_addr` 由内部寄存器驱动；`sd_sec_read_end` 时 +1 并继续（用 4.2 的写法 B，零间隙）。
4. `byte_valid` 接 `sd_sec_read_data_valid`；`byte_in_sec` 是 0~511 计数器。
5. 扇区读完 `sec_count` 个后，产生 `done` 脉冲、清 `busy`。

### 5.3 在你们方案里的用途

- **W1 判据**：`sec_count = 1`、`sec_addr = 0`，把前几个字节打到数码管 / LED 上 —— 通了就说明整条链好了
- W2 如果决定自己解析 BMP（不用 `bmp_read`），就用它做底层

## 六、🔧 建议封装 B：`img_loader`（对标 `sd_card_bmp`，但要自己写）

> **这是推荐路线**：把"载入第 N 张图"做成一个黑盒，你们的模式状态机只跟它打交道。

### 6.1 接口（建议）

| 分组 | 端口 | 方向 | 位宽 | 含义 |
|---|---|---|---|---|
| 引脚 | `SD_nCS`/`SD_DCLK`/`SD_MOSI` | out | 1 | → 板卡 |
| | `SD_MISO` | in | 1 | ← 板卡 |
| 状态 | `init_done` | out | 1 | 电平：卡初始化完成 |
| | `bmp_width` / `bmp_height` | out | 16 | 从 BMP 头解析出的宽高（给显示/校验用） |
| 扫描 | `scan_req` | in | 1 | 脉冲：开始扫描找图 |
| | `scan_start` / `scan_max` | in | 32 | 扫描起止扇区 |
| | `scan_target` | in | 3 | 要找几张图 |
| | `scan_busy` / `scan_done` | out | 1 | 电平 / 一次性脉冲 |
| | `scan_found_valid` | out | 1 | 一次性脉冲（每找到一张来一次） |
| | `scan_found_sector` | out | 32 | 找到的扇区号（在 `scan_found_valid` 那拍有效） |
| 载入 | `load_req` | in | 1 | 脉冲：载入一张图 |
| | `load_sector` | in | 32 | 该图的 BMP 头所在扇区 |
| | `load_buf_idx` | in | 2 | 载入到哪个缓冲区（0/1） |
| | `load_busy` / `load_done` | out | 1 | 电平 / 一次性脉冲 |
| 写缓冲 | `wr_buf_idx` | out | 2 | 实际写入的缓冲区号（回读确认） |
| | `wr_req` / `wr_req_ack` | out/in | 1 | 接 `frame_read_write` 的写侧握手 |
| | `wr_en` | out | 1 | 写使能 |
| | `wr_data` | out | 32 | 32 位像素（已做 `[31:8]` 打包） |

### 6.2 内部要做的事

| 组件 | 来源 |
|---|---|
| `bmp_read` | 第4站，**原样搬**（⚠️ `header_match` 要求宽高精确匹配、宽度必须 4 的倍数） |
| `sd_card_top` | 第5站四层，**原样搬** |
| 扫描参数寄存器 | 把 `scan_start` / `scan_max` / `scan_target` 从上层锁存进 `bmp_read` |
| 举请求的胶水 | 同封装 A 的第 2 点 |
| 双缓冲指针 | **抄 `sd_card_bmp` 的零件**：`write_buf_idx` / `disp_buf_idx` 两个 2 位索引 + `write_finish_toggle` 三级同步 |

**剥掉的（交给上层）**：按键去抖、模式切换、数码管状态码 —— 这些是 `sd_card_bmp` 里应用相关的部分，你们自己写。

### 6.3 用起来是什么样（文字描述）

你们的三模式状态机大概长这样：

| 模式 | 做什么 | 用到的接口 |
|---|---|---|
| **① 教学浏览** | 按键翻页：`load_req` 载入下一张到空闲缓冲区，等 `load_done`，然后切 `disp_buf_idx` | `load_req` / `load_done` |
| **② 自动展播** | 定时器到点就 `load_req`，配合转场 | `load_req` / `load_done` |
| **③ 按压训练** | 显示反馈页 + 实时参数（ADC 按压速率）叠加 | 同①，叠加部分用图层的方案 |

**上层完全不需要知道 SD 卡、扇区、SPI、双缓冲的存在** —— 这正是封装的价值。
