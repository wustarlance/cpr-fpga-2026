## 建议

## 本次实际验证

统一用当前机器的 TD 6.2.1 SP1 / 6.2.178840，PR 在独立快照运行，保留原始输入。PR 文档记录的是另一台机器上的 TD 6.2.168116，因此资源数字可能略有区别。

- `python tests/sim/run.py --all --self-test-runner`：11 项产品测试通过，5 项运行器控制达到预期。
- PR `top`：综合通过；5681 LUT（28.98%）、4198 寄存器、20 BRAM、3 PLL。
- PR `top_adc`：综合通过；5755 LUT（29.36%）、4282 寄存器、20 BRAM、3 PLL、1 ADC。
- 本地完整实现报告：4050 LUT（20.66%）、3866 寄存器、20 BRAM、3 PLL。它功能更少，不能把较低资源直接解释为架构更优。
- 给原 PR 的构建脚本仅追加 place/route/报告命令，默认 `top` routed setup WNS **−6.072 ns**，TNS −305.733 ns，hold WNS +0.003 ns。最差仍在 SDRAM DQ 回读；此外存在内存同域、内存到 SD，以及音频复位入口检查。没有对原 PR 做功能修复。
- 本地现有 routed 报告：setup WNS **+1.246 ns**，hold WNS +0.003 ns，TNS 均为 0。

本地和 PR 的 WNS **不是完全同口径的优劣评分**：本地有更宽泛的时钟例外，PR 没有互斥像素/串行时钟。正裕量只说明当前 SDC 实际分析的路径通过，不说明所有跨域和板级 I/O 已签核。

### 临时组合验证

另外创建一份临时 PR 副本，仅移植本地 40 MHz SDRAM、刷新计数和 BMP 扫描流水，保留 PR 的 PLL lock 端口、复位、应用层和约束。

默认 `top` 重跑物理实现后：

| 路径 | Setup WNS |
|---|---:|
| SDRAM 回读 | +2.428 ns |
| SDRAM 写方向 | +4.983 ns |

剩余两端点位于 `por_ready`（50 MHz 域）到音频域 `reset_release` 的异步复位入口。需要按异步置位/同步释放协议核对 recovery/removal 与局部时序例外，不能给所有音频路径统一 false-path。组合版只是路线验证，不是可下载或已合并的交付版本；未对组合版 `top_adc` 完成物理验证。

## 仍需处理的问题

1. **媒体链端到端验证不足。** PR 的 11 项测试没有覆盖 SD 图像调度、帧缓存所有权和 OSD 整体渲染；两个顶层通过综合不能代替这些测试。
2. **旧缓冲释放过早。** PR 的 `rtl/SD/sd_card_bmp.v:245` 在源完成和写完成后改变 `disp_buf_idx`、清 `load_busy`；读地址在参考 `frame_fifo_read` 的下一次帧握手中才更新。快速连续切图仍有机会覆写正在读取的旧缓冲。需增加帧边界切换确认。
3. **频率测量的产品语义。** PR 的 `training_core` 以两次完整释放事件测间隔，有测试且文档明确；释放时长变化会影响该测量。若目标是按压开始到开始，应额外输出 `press_start`，不能直接更改现有计数事件契约。
4. **ADC 模拟真实性。** 当前极性归一化、滤波、触发/释放和三档边界实现较完整，但 baseline 和阈值是未标定码值，不能直接标成 5/6 cm。实际 VREF、输入窗口、噪声和机械传力仍待实测。
5. **合并时频率与路径冲突。** 本地 `.al` 移到 `project/td_project/`，PR 使用 `project/project.al`；本地尚未跟踪多份源码。必须先保存两套输入快照，按模块整合，保留 PR 的 lock 输出，不能整文件覆盖 PLL。PR 自带 `vendor/include/global_def.v`，只合入例程的刷新修复不会更新这份。

## 整合顺序

1. 保存本地基线与当前位流，统一主工程入口和 vendor 依赖。
2. 引入 PR 的应用、ADC、reset 和 AXIS 模块，合并本地 PLL/刷新/BMP 修复。
3. 修显示切换确认，复核复位/ADC/音频/视频跨域约束。
4. 运行 PR 11 项测试加本地 BMP/刷新测试，补 SD 调度、OSD 和缓冲所有权测试。
5. 两个顶层按相同标准 run 做综合、布局布线和 setup/hold 检查，再生成对应位流。
6. 先按键模式验证显示和训练，再用电位器验证 ADC，最后接实际按压盒。

原 PR 不直接作为已签核主工程；本地媒体地基也不能代表训练功能已经实现。建议把“应用层更完整”和“媒体层已修时序”两项成果同时保留。
