# 常规选题清单（回到主流）

> 前面几轮（空间天气、类脑、深空探测）偏了，那些是"研究型"选题，不适合 7 周交付的竞赛作品。
> 本文收回主流：**7 个成熟产品形态的方向**，全部直接对应赛题要求的"多幅图像播放 / 透明叠加 / 按键交互 / 平移缩放 / 音频"。

---

## 一、七个常规方向

### ① 商用数字标牌 · 分屏多媒体终端 ★ 最贴合赛题

| | |
|---|---|
| **定位** | 商场、电梯、门店、政务大厅的信息发布屏 |
| **为什么正常** | 这就是"HDMI 多媒体播放系统"的**正统产品形态**。商显是成熟产业，评委不需要任何背景知识 |
| **FPGA 真活** | **多图层实时合成引擎**：底图 + 图文层 + 字幕层 + 角标层；**分屏**（单画面/左右/四画面）；透明叠加与透明色处理；字幕滚动；转场 |
| **怎么不平庸** | 不是拼接视频文件，而是**真正的多图层合成器**——每层独立控制位置、透明度、缩放。再配"内容与硬件解耦"（换一张 SD 卡即换整套内容） |
| **难度** | 中低 |

**和赛题的对应**：多幅播放 ✅ 透明叠加 ✅ 按键 ✅ 平移缩放 ✅ 音频 ✅ —— 五条要求一条不落，几乎是为这个方向写的。

---

### ② 工业 HMI · 设备操作面板 ★ 最有产业说服力

| | |
|---|---|
| **定位** | 数控机床、注塑机、电力柜、水处理设备的操作面板 |
| **为什么正常** | 工业 HMI 是嵌入式**最主流**的应用之一，国产替代需求真实，评委里做工业的人多 |
| **FPGA 真活** | **实时曲线**（滑动窗口 + FIFO 缓存，逐列推进）；**仪表盘**（指针、圆弧刻度在像素域实时绘制）；报警弹窗；多页面切换；参数联动 |
| **怎么不平庸** | 曲线和仪表都是**算出来的**，不是贴图；而且**无操作系统 → 上电即用、长期运行不死机**，这恰好是工业现场最看重的特性——赛题的"限制"在这里又变成了卖点 |
| **难点** | 需要数据源：用 SD 卡预置数据回放 + 按键模拟传感器输入即可 |

---

### ③ 车载智能座舱 · 仪表与多媒体终端

| | |
|---|---|
| **定位** | 液晶仪表 + 多媒体播放 + 倒车辅助显示 |
| **为什么正常** | 智能座舱是当前最热的产业方向之一，话题度高 |
| **FPGA 真活** | 指针仪表实时渲染；多图层（背景 + 指针 + 数字 + 报警图标）；**平滑插值动画**（指针不会跳变）；音频 |
| **怎么不平庸** | 指针角度、刻度、数字全部实时算，帧率恒定；多套主题（运动/经济/越野）实时切换 |
| **难点** | 同样需要模拟车速/转速数据源 |

---

### ④ 家庭智能相框 · 多媒体相框

| | |
|---|---|
| **定位** | 照片轮播 + 背景音乐 + 日历/信息叠加 |
| **为什么正常** | **最经典**的入门级 FPGA 多媒体项目，几乎每个评委都见过 |
| **FPGA 真活** | 图片解码、缩放、转场、多图层合成 |
| **怎么不平庸** | **实时 Ken Burns 效果**（照片缓慢平移+缩放，"活"起来，这是纯播放器做不到的）；**照片墙拼贴**（多张照片实时合成一屏）；日历/纪念日信息叠加 |
| **难度** | 低 |

> ⚠️ **风险**：门槛低意味着**撞车概率高**，而且容易被判为"太简单"。要靠 Ken Burns + 拼贴的实时性把它撑起来。

---

### ⑤ 音频可视化音乐播放器

| | |
|---|---|
| **定位** | 桌面音乐播放器，屏幕显示频谱、波形、歌词 |
| **为什么正常** | 音频可视化**正好是赛题的扩展功能点**，把"选做"做成主卖点是很聪明的打法 |
| **FPGA 真活** | I2S 音频输出；**8 段滤波器组实时能量检测**（不用 FFT，省资源，EG4S20 没有 DSP 硬核）；频谱条/波形/粒子随音乐实时渲染；歌词滚动 |
| **怎么不平庸** | 大多数队伍会跳过音频可视化（太麻烦）；把它做扎实就是差异点 |
| **难度** | 中低 |

---

### ⑥ 多媒体导览 · 语音讲解终端

| | |
|---|---|
| **定位** | 景区、展馆、校园的语音导览机 |
| **为什么正常** | 导览机是成熟的嵌入式产品形态 |
| **FPGA 真活** | 地图/平面图**平移与局部放大**；讲解点标注叠加；按键选点；语音播放与字幕同步 |
| **难度** | 中低 |

---

### ⑦ 便携式游戏机（纯硬件逻辑实现）

| | |
|---|---|
| **定位** | 俄罗斯方块、贪吃蛇、打砖块 |
| **为什么正常** | FPGA 做游戏机是**经典课题**，评委熟悉，展示效果好 |
| **FPGA 真活** | 图形引擎、精灵（Sprite）叠加、背景滚动、碰撞检测、音效 |
| **难度** | 中 |
| **⚠️ 红线** | **必须用状态机/专用硬件实现游戏逻辑，绝对不能实现通用 CPU 或软核**——赛题明确"不得带有额外处理器" |

## 三、建议

- **最稳、最不容易出错** → **① 商用数字标牌分屏终端**：赛题五条要求一条不落，开发风险最低
- **最有产业说服力、最容易讲出深度** → **② 工业 HMI**：撞车概率低，且"无操作系统→上电即用不死机"这一条在工业场景是真实卖点
- **最省力** → **④ 智能相框**（但要做好被质疑"太简单"的准备）
- **最讨巧** → **⑤ 音频可视化播放器**：把赛题的选做项做成核心，大多数队伍会跳过

如果要我选一个：**② 工业 HMI 显示终端**。理由是它同时满足"正常"（成熟产品、评委熟悉）、"低撞车"（没人愿意啃实时曲线和仪表渲染）、"技术纵深"（曲线和指针都是算出来的）、"演示直观"（曲线在动、指针在转）四条，是这批里综合分最高的。
