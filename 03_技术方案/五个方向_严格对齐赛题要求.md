# 五个方向：严格按赛题列举场景 + 逐条对齐要求

> 依据：赛题 1.2 列举的五个应用场景（**数字广告牌、商业展陈终端、应急信息发布、车载辅助显示、教育演示**）、1.3 赛题要求、1.5 评分标准（基础 4 条 + 扩展 5 条）。
> **每个场景给一个方向，逐条标注覆盖情况。** 文末给覆盖率对比与推荐。

---

## 〇、先明确评分规则（决定"做几个功能"）

- **基础要求 4 条**：核心功能完整性 / 显示稳定性与鲁棒性 / 基础音频输出 / 系统工程规范性
- **扩展要求 5 条**：①图层叠加与字幕 ②轮播与转场 ③图片自适应缩放 ④实时参数调节与 OSD ⑤音频可视化
- **计分**：完成 1 项得一定分值；2 项且效果良好得扩展部分一半以上；**3 项及以上且完成度高得较高分**；完成度高、创新突出可满分

**结论**：目标应当是**扎实做满基础 4 条 + 扩展至少 3~4 条**，而不是把一条做到极致。

## 一、数字广告牌方向

### 多源图层融合数字广告牌

| 项 | 内容 |
|---|---|
| **产品形态** | 商场、门店、电梯口的商用广告机：底图 + 商品图 + 滚动促销字幕 + 背景音乐频谱，多图层实时合成 |
| **用户** | 商家、商显集成商 |

**逐条覆盖**

| 要求 | 怎么做 |
|---|---|
| 基础1 核心功能完整性 | SD 卡扫描素材、BMP 解析、SDRAM 帧缓存、HDMI 输出、按键控制 |
| 基础2 稳定性与鲁棒性 | 无操作系统、硬件流水线、确定性刷新；循环播放长期运行 |
| 基础3 **音频输出** | 背景音乐经 I2S/HDMI 输出 |
| 基础4 工程规范性 | 模块化划分、时序约束、双缓冲 |
| 扩展① 图层叠加与字幕 | **4 层实时合成**：底图层 + 商品图层 + 滚动字幕层 + 频谱层；促销标语**平滑滚动** |
| 扩展② 轮播与转场 | 淡入淡出、滑动切换 |
| 扩展③ 自适应缩放 | 不同尺寸素材自适应 HDMI 输出分辨率 |
| 扩展④ 实时调节与 OSD | 按键调节**亮度/对比度**，屏幕角标显示当前档位 |
| 扩展⑤ 音频可视化 | 背景音乐**频谱条**实时叠加 |

**FPGA 优势体现**：**图层数量是 FPGA 的强项**——PC 方案要"先合成再送显"，缓存与带宽压力随图层数上升；FPGA 是每个像素在像素时钟内**并行取四层并一次合成**，图层越多优势越明显。这正是赛题所说的"多源信息融合"。

**难度**：中低（全是"地址级"操作 + 一个滤波器组）

## 二、商业展陈终端方向

### 展品细节多图层阅览终端

| 项 | 内容 |
|---|---|
| **产品形态** | 展馆展柜旁的阅览屏：高清展品图 + 线图/拓片标注层 + 释文滚动字幕 + 语音讲解 |
| **用户** | 参观者、场馆运营方 |

**逐条覆盖**

| 要求 | 怎么做 |
|---|---|
| 基础1 | 多幅展品图播放、HDMI 输出、按键控制 |
| 基础2 | 无操作系统，上电不到一秒出画面，长期无人值守 |
| 基础3 | 语音讲解音频输出 |
| 基础4 | 模块化 + 时序约束 + 双缓冲 |
| 扩展① | 标注层以**透明色键控**叠加；释文以片内点阵字库实时渲染并**平滑滚动** |
| 扩展② | 展品间淡入淡出切换 |
| 扩展③ | **高清图无级缩放**（相位累加），支持局部放大窗 |
| 扩展④ | 按键调节亮度/对比度，OSD 显示档位（展厅光照差异大，很自然） |
| 扩展⑤ | 音频可视化 ⚠️ **稍勉强**（可做成"讲解播放中"的声波指示） |

**FPGA 优势体现**：**逐像素实时缩放与透明合成**——通用播放器放大到一定倍数就发虚，FPGA 每帧重算，任意倍率任意位置都清晰。

**难度**：中（缩放要调质量，可用多级预缩放素材规避）

## 三、应急信息发布方向

### 多预案应急信息发布终端

| 项 | 内容 |
|---|---|
| **产品形态** | 公共场所/社区的应急信息屏：多套预案图 + 疏散指令滚动字幕 + 语音播报 + 高对比模式 |
| **用户** | 场馆管理方、社区 |

**逐条覆盖**

| 要求 | 怎么做 |
|---|---|
| 基础1 | 预案图多幅播放、HDMI 输出、大按键 |
| 基础2 | **无操作系统 → 上电即亮**，意外断电来电立刻恢复；这正是应急场景要的 |
| 基础3 | **语音播报指令**输出 |
| 基础4 | 模块化 + 时序约束 |
| 扩展① | 疏散指令**滚动字幕**（应急场景最自然的字幕应用） |
| 扩展② | 预案切换淡入淡出 / 滑动 |
| 扩展③ | 疏散图**平移与局部放大** |
| 扩展④ | **高对比 / 夜间模式**切换，OSD 显示当前模式 |
| 扩展⑤ | 音频可视化 ⚠️ 可做成"播报中"的声波指示条 |

**FPGA 优势体现**：**确定性与可靠性**——应急场景最怕屏黑，无操作系统意味着没有死机、病毒、文件系统损坏三类失效路径；上电即出画面。

**难度**：中低

> ⚠️ 注意：此方向与市面上"应急广播/应急屏"作品有一定重合度，需要在答辩时突出**离线、无OS、秒启**这三条差异。

## 四、车载辅助显示方向

### 车载多图层辅助显示终端

| 项 | 内容 |
|---|---|
| **产品形态** | 车载辅助显示：行车信息层 + 提示文字层 + 多媒体画面 + 音乐频谱，日夜模式自动切换 |
| **用户** | 驾驶员、乘客 |

**逐条覆盖**

| 要求 | 怎么做 |
|---|---|
| 基础1 | 多幅画面播放、HDMI 输出、按键/开关控制 |
| 基础2 | 无操作系统 → **上电立刻出画面**（车载场景对启动时间敏感）；确定性时序 |
| 基础3 | 音乐/提示音输出 |
| 基础4 | 模块化 + 时序约束 + 双缓冲 |
| 扩展① | 信息层以透明色键控**叠加**；提示文字（时间戳、状态语）实时渲染并**平滑滚动** |
| 扩展② | 多媒体画面淡入淡出切换 |
| 扩展③ | 不同分辨率画面自适应缩放 |
| 扩展④ | **日夜模式亮度/对比度调节**——车载刚需，OSD 显示当前档位 |
| 扩展⑤ | 音乐**频谱显示**——车载多媒体里非常常见 |

**FPGA 优势体现**：**低延迟 + 确定性**——赛题原话是"低延迟显示"；FPGA 从像素到输出没有软件栈延迟，按键响应下一帧即变。

**难度**：中低

> ⚠️ 注意：真正的车规认证我们做不了。建议表述为"车载辅助显示方案"，明确定位为原理验证与演示，不要声称符合车规。

## 五、教育演示方向

### 实训作业指导演示终端

| 项 | 内容 |
|---|---|
| **产品形态** | 实训台/教室的作业指导屏：步骤图 + 标注层 + 滚动提示 + 语音讲解 |
| **用户** | 实训教师、学生 |

**逐条覆盖**

| 要求 | 怎么做 |
|---|---|
| 基础1 | 多幅步骤图播放、HDMI 输出、按键翻步 |
| 基础2 | 无操作系统，上电即用，长期运行 |
| 基础3 | 语音讲解输出 |
| 基础4 | 模块化 + 时序约束 |
| 扩展① | 关键部位**标注层**叠加；提示文字实时渲染并**平滑滚动** |

## 六、覆盖率对比（这是选方向的关键）

| 方向 | 扩展① 图层字幕 | 扩展② 转场 | 扩展③ 缩放 | 扩展④ 调节+OSD | 扩展⑤ 音频可视 | **自然覆盖数** | 难度 |
|---|---|---|---|---|---|---|---|
| **① 数字广告牌** | ✅ | ✅ | ✅ | ✅ | ✅ **很自然** | **5** | 中低 |
| **④ 车载辅助显示** | ✅ | ✅ | ✅ | ✅ **刚需** | ✅ **很自然** | **5** | 中低 |
| ② 商业展陈 | ✅ | ✅ | ✅ **最强** | ✅ | ⚠️ 勉强 | 4 | 中 |
| ③ 应急信息发布 | ✅ | ✅ | ✅ | ✅ | ⚠️ 勉强 | 4 | 中低 |
| ⑤ 教育演示 | ✅ | ✅ | ✅ | ✅ | ⚠️ 勉强 | 4 | **低** |

**关键发现**：

- **数字广告牌**和**车载辅助显示**是唯二能**自然地**覆盖全部 5 项扩展要求的场景——因为这两个场景里"背景音乐/播放音乐"本来就是标配，音频可视化不用硬凑；而"环境光变化调亮度"也都是真实需求。
- **商业展陈**在扩展③（无级缩放、看细节）上技术最强，但音频可视化牵强。
- **教育演示**实现难度最低，适合保守策略。

## 七、推荐

| 策略 | 选它 | 理由 |
|---|---|---|
| **想扩展项做满、又不难** | **① 数字广告牌** | 5 项扩展全部自然覆盖；核心是"多图层并行合成"，正好命中赛题说的"多源信息融合"；技术全是地址级操作 + 一个滤波器组 |
| **想突出低延迟与确定性** | **④ 车载辅助显示** | "日夜模式"是真实刚需不是硬凑；5 项全自然覆盖；能讲"上电立刻出画面" |
| **想风险最低** | **⑤ 教育演示** | 最接近最小可行方案，扩展③④都简单 |
| **想技术最强** | **② 商业展陈** | 无级缩放质量最见功夫 |

**我的建议**：**① 数字广告牌**。
理由有三：一是**五项扩展全部自然覆盖**，按计分规则直接落在"3 项及以上且完成度高"；二是核心机制是**多图层并行合成**，这是 FPGA 相对通用处理器最本质的优势，答辩时最好讲；三是**技术难度低**——所有操作都是地址偏移、比较器和多路选择器，唯一的"新东西"是音频可视化的滤波器组，而它只影响扩展⑤。

## 九、共同的技术底座（五个方向完全一样）

不管选哪个方向，FPGA 内部要写的东西是同一套：

| 模块 | 来源 | 对应要求 |
|---|---|---|
| PLL 时钟 | IP | 基础 |
| HDMI 发送 + 视频时序 | 加密 IP + 官方例程 | 基础1 |
| SD 卡 SPI + FAT32 | 参考工程改写 | 基础1 |
| BMP 解析 | 自己写 | 基础1 |
| SDRAM 控制器 + 双缓冲 | IP + 参考工程 | 基础1/2 |
| **多图层合成器** | 自己写 | **扩展①** |
| **滚动字幕生成** | 自己写（地址偏移） | **扩展①** |
| 转场控制 | 自己写 | 扩展② |
| 缩放引擎（相位累加） | 自己写 | 扩展③ |
| 亮度/对比度 + OSD | 自己写 | 扩展④ |
| I2S 音频输出 | 参考工程 | 基础3 |
| 音频滤波器组 + 频谱绘制 | 自己写 | 扩展⑤ |
| 按键消抖 | 参考工程 | 基础1 |

> **换方向 = 换 SD 卡里的素材 + 换宣传口径，代码基本不动。** 这也意味着：**先选一个开工，中途想换方向成本很低。**
