### 判断

| 资源 | 可用 | 估用 | 余量 |
|---|---|---|---|
| LUT | 19,600 | 4,000–9,000 | **20–45%，充足** |
| DSP | 29 | 0–2 | 充足 |
| PLL | 4 | 3 | 刚好够 |
| **ERAM** | **136 KB** | **60–115 KB** | **⚠️ 44–85%，紧** |
| IO | 188 | ~35 | 极充裕 |

> **结论：LUT 不是问题，块 RAM 才是。**

### 块 RAM 的关键对策：字库只放"本作品用到的字"

原计划按"常用汉字 3000 字"做 16×16 点阵字库：

```
3000 字 × 32 字节 = 96 KB      ← 直接吃掉 70% 的块 RAM
```

**但本作品的文字是固定的**——滚动字幕、提示文案、要点清单都是预先写好的，**全篇用到的不同汉字大概只有几十到一两百个**。

```
150 字 × 32 字节 = 4.8 KB      ← 降到 5% 以内
```

**做法**：写个小脚本扫描所有文案，提取去重后的字表，只给这些字做点阵数据，并生成"字符 → 索引"的查找表。这能把块 RAM 的最大一块开销砍掉 95%。

**这是整个设计里最要紧的一条资源优化。**

### 第二条对策：图像一律放片内 SDRAM

8 MB 片内 SDRAM 足够放多帧 640×480×16bit（每帧 600 KB，可放 13 帧）。
**绝不把整帧图像放块 RAM**——那样必爆。

来自 `05_lab_ex/.../constraints_source/pin.adc` 与顶层模块端口：

| 外设 | 引脚 | 占用 |
|---|---|---|
| 系统时钟 | `clk` = **R7** | 1 |
| HDMI | CLK_P = **C3**，D0_P = **G5**，D1_P = **F1**，D2_P = **E1** | 4（差分实际 8） |
| HDMI DDC | SCL = **P2**，SDA = **R2** | 2 |
| **按键** | **`key1` = B2，`key2` = C1** | **2** |
| **复位** | **`rst_n` = A2** | 1 |
| SD 卡 | dclk = **A14**，miso = **B14**，mosi = **A13**，ncs = **A12** | 4 |
| I2S（引到排针 **J4**） | BCLK = **J13**(J4-7)，LRCK = **F13**(J4-3)，DOUT = **L14**(J4-9) | 3 |
| 数码管 | seg_data[7:0] = C15,C16,B6,A5,B5,A8,A7,A6；seg_sel[5:0] = E12,E10,C13,F10,E11,D11 | 14 |
| **VGA（约束里已全部注释）** | vga_data[11:0] + hs + vs | **14（可释放）** |

**合计已用约 35 个 IO，占 188 的 19%。**

### 三个重要观察

1. **板载按键只有 3 个**：`key1`、`key2`、`rst_n`。这是硬约束。
2. **VGA 的 14 个引脚被注释掉了**——说明这版工程不用 VGA，**这 14 个脚是空出来的**，可以外接按键。
3. **数码管的 14 个引脚**——本作品的信息全在 HDMI 屏上，**数码管用不到**，理论上也可释放（需从板上飞线或看是否引到排针）。

### 参考工程的按键语义（顶层注释）

```verilog
input key1,   // 手动下一张
input key2,   // 自动播放 开/关
```

> **参考工程本身就是"手动翻阅 + 自动轮播"两模式**——我们要做的三模式，前两个模式正是它的直接升级。

## 五、按键分配（核心问题）

### 功能需求 vs 可用按键

需要 7 个功能，只有 2 个可用按键（`rst_n` 保持复位语义不动）：

| # | 功能 | 属于 |
|---|---|---|
| 1 | 模式切换（①教学 / ②展播 / ③训练） | 全局 |
| 2 | 下一张 | 模式① |
| 3 | 上一张 | 模式① |
| 4 | 暂停 / 继续 | 模式② |
| 5 | 复位计数 | 模式③ |
| 6 | 亮度 / 对比度（扩展④，必须有） | 全局 |
| 7 | 放大 / 标注开关（扩展③①的体现） | 模式①③ |

### 方案 A：双键 + 短按/长按（零额外硬件）★ 保底

| 按键 | 短按 | 长按（>0.8s） |
|---|---|---|
| **key1 (B2)** | 主操作：往下走 | **切换模式 ①→②→③→①** |
| **key2 (C1)** | 次操作：往回走 / 开关 | **亮度 / 对比度循环（带 OSD）** |
| **rst_n (A2)** | 复位 | — |

各模式内的短按语义：

| 模式 | key1 短按 | key2 短按 |
|---|---|---|
| ① 教学浏览 | **下一张** | **上一张** |
| ② 自动展播 | **暂停 / 继续** | **标注层开关** |
| ③ 按压训练 | **复位计数** | **切换放大倍率** |

**记忆规则统一**：key1 = 往前走，key2 = 往回走/开关；长按 key1 换模式，长按 key2 调亮度。

**优点**：零额外硬件，板子一插就能演示
**缺点**：长按切换模式在现场演示时不够直观

### 方案 B：外接按键盒（推荐用于正式演示）

利用 **VGA 区空出的引脚**（或排针 J4 剩余脚），外接一个 **5 键小键盘**：

| 键 | 功能 |
|---|---|
| K1 | 切换模式 |
| K2 | 上一张 / 复位 |
| K3 | 下一张 / 暂停 |
| K4 | 亮度 / 对比度 |
| K5 | 放大 / 标注 |

**优点**：一键一功能，便于现场理解
**成本**：5 个按键 + 一块小亚克力 + 杜邦线，约 20 元
**风险**：需要确认 VGA 区的引脚是否方便接线（见第九节）

### 建议

> **两条都做**：板载 2 键保底（不依赖任何外接线），外接 5 键盒用于正式演示。
> 逻辑上只需一份"按键事件 → 功能"的映射表，切换输入源是几行代码的事。

**按键数量够不够？够。** 单靠板载 2 键 + 长短按就能覆盖全部 7 项功能；外接盒只是让演示更直观。

## 六、音频通路：核实结果（好消息）

参考工程里音频的完整链路（从顶层端口反查）：

```
hdmi_audio_tone_i2s_64fs        ← 内部产生 I2S 测试音
    ↓ BCLK / LRCK / DOUT
    ├──→ 输出到排针 J4（可外接 DAC 验证）
    └──→ I2S_receiver → audio_valid / left_data / right_data
                              ↓
           HDMI 核端口：I_audio_left_data / I_audio_right_data / I_audio_valid
                        （核内有 AUDIO_SAMPLE_RATE 参数）
```

**关键结论**：

1. **HDMI 发送核本身带音频输入端口** → **音频可以直接嵌进 HDMI 流，从显示器喇叭出声，不必外接 DAC** ✅
2. **基础要求 3「基础音频输出」因此可以稳稳满足**
3. 参考工程的音频源是**内部测试音**，我们要换成**从 SD 卡读音频数据**——这部分是新增工作量

### 由此引出的一个风险：SD 卡带宽竞争

| 数据流 | 速率 |
|---|---|
| SD 卡 SPI（约 25 MHz） | 理论约 3.1 MB/s |
| 一帧 640×480×16bit | 600 KB |
| 48 kHz × 16 bit × 2ch 音频 | 约 192 KB/s |

**判断**：如果图像是"读一帧、显示较久"的机制，带宽完全够；**但若要做逐帧动画或快速轮播，就有压力**。

**对策**：
- 图片切换只在**切换的瞬间**读卡，平时显示静止帧
- 音频单独做**小容量 FIFO 预读**，与图像读取错开
- 必要时降低音频采样率（如 22050 Hz，速率减半）

## 七、★ 片内 ADC：按压盒方案可以升级

### 发现

器件库里写的是 `Hard Cores: ADC*1`，官方原语模板里也确认存在：

```verilog
EG_PHY_ADC #(
  .CH0 ("DISABLE"), ... .CH7 ("DISABLE"),   // 8 个通道可分别使能
  .VREF ("DISABLE")                          // 内部参考
) u_EG_PHY_ADC(
  .clk (clk), .pd (pd),       // 掉电（高有效）
  .s   (s),                   // 3 位通道选择
  .soc (soc), .eoc (eoc),     // 启动转换 / 转换结束
  .dout(dout)                 // 12 位结果
);
```

**8 通道、12 位、带内部 VREF 的片内 ADC。**

### 对按压盒的影响

| | 原方案（开关阵列） | **新方案（FSR + 片内 ADC）** |
|---|---|---|
| 传感器 | 4 个微动开关 + 挡片 | **力敏电阻 FSR 分压** |
| 机械精度 | **要求高**（挡片长度要反复试） | **要求低**（弹簧一压即可） |
| 深度分辨率 | 三档 | **连续**（12 位） |
| 额外芯片 | 无 | **无**（用片内 ADC） |
| FPGA 侧 | IO 读电平 | **ADC 时序状态机 + 标定表** |
| 标定 | 无 | 需要一张"电压 → 深度"表 |

**电路极简**：
```
VCC ──[ R ]──┬── FSR ── GND
             │
        接 ADC 输入引脚
```

### ⚠️ 但有一个前提必须确认

**EG4S20BG256 的 ADC 输入引脚是哪几个、HX4S20C 板有没有把它们引出来** —— 这一点我在 TD 安装目录、器件数据库、参考工程约束里**都没有找到明确答案**。

已知旁证：
- 安路自家的 **YADAN 板（同为 EG4S20）** 有教程用**旋钮**演示片内 ADC 调灯亮度，说明片内 ADC 在外围确实可用
- 但 **HX4S20C 是否引出了 ADC 输入，必须实测或问 FAE**

### 所以按压盒走双轨

| 轨 | 方案 | 前提 | 定位 |
|---|---|---|---|
| **主** | FSR + 片内 ADC | ADC 引脚可用 | 深度连续，机械简单，技术亮点高 |
| **备** | 4 路微动开关阵列 | 不需要任何前提 | **一定能做**，深度三档 |

**两轨的 FPGA 上层逻辑完全一致**——都产出"深度值/档位"，频率测量、中断计时、轮换倒计时、图层合成都照用。切换只需换一个采集前端模块。

## 八、必须修正的三个判断（我之前的错误）

| # | 我之前的说法 | 实际 | 影响 |
|---|---|---|---|
| 1 | 「**EG4S20 没有 DSP 硬核，乘法是短板**」 | ❌ **错。有 29 个 `EG_PHY_MULT18`（18×18→36）** | 音频 FFT 可选；频率换算可用除法；**但滤波器组仍然更省，原方案不用改** |
| 2 | 「音频可视化不能用 FFT」 | ⚠️ **部分错**。有 DSP 可以做 FFT，只是占用大 | 结论不变（用滤波器组），但**理由要改**：不是因为没 DSP，而是因为滤波器组资源更省、且足够用 |
| 3 | 「用 RC 充放电法读力敏电阻，绕开 ADC」 | ⚠️ **不必要**。片内就有 12 位 ADC | **改用片内 ADC，方案更简单、精度更高** |

**第 1 条是最需要纠正的**——我曾多次基于"没有 DSP"论证设计选择。幸好最终结论（用滤波器组、不做除法）依然成立，只是**论据要换**。

## 十、选题要求对照（最终确认）

### 赛题简介（1.2）原话对照

> 「与依赖通用处理器的软件栈方案相比，FPGA 方案能够……实现**更确定的时序、更低的显示延迟和更高的系统可靠性**」

| 赛题表述 | 本方案如何体现 |
|---|---|
| 更确定的时序 | 节拍由单一计数器产生，每周期严格相等 |
| 更低的显示延迟 | 按压判定后**下一帧即上屏** |
| 更高的可靠性 | 无操作系统，上电即出画面，长期运行不死机 |

### 赛题要求（1.3）原话对照

> 「系统需体现 FPGA 在**并行处理、实时控制、低延迟显示、音画同步及多源信息融合**等方面的优势」

| 优势项 | 落在哪里 |
|---|---|
| 并行处理 | 8 层图层在像素时钟内并行取层合成 |
| **实时控制** | 节拍产生、按压采集、频率测量、中断计时、轮换倒计时 |
| 低延迟显示 | 判定结果下一帧上屏 |
| **音画同步** | **同一计数器驱动节拍音与屏幕脉动** |
| **多源信息融合** | SD 卡静态素材 + 按压传感器动态数据两路汇合 |

> 「采用的算法或技术方法例如……**本地图像资源扫描、BMP 图像解析、SDRAM 帧缓存管理、HDMI 视频显示、HDMI 音频输出、交互控制、音视频联动展示**等」

| 赛题列举的方法 | 本方案 |
|---|---|
| 本地图像资源扫描 | ✅ SD 卡 FAT32 |
| BMP 图像解析 | ✅ 自写解析模块 |
| SDRAM 帧缓存管理 | ✅ 双缓冲 |
| HDMI 视频显示 | ✅ 加密 IP + 时序 |

> 「所有算法、控制逻辑及数据处理流程应在 FPGA 中自主编程实现……**不得带有额外处理器**」

| 红线 | 本方案 | 结论 |
|---|---|---|
| 不带额外处理器 | 仅 EG4S20，无 MCU/ARM/软核 | ✅ |

## 十二、一句话总结

> **LUT 充裕、IO 充裕、DSP 够用、PLL 刚好；真正的瓶颈是块 RAM（用"只放用到的字"化解）。**
> **按键只有 2 个，但靠长短按组合够用，外接按键盒只是让演示更直观。**
> **两个意外收获：HDMI 核自带音频输入端口（基础要求 3 稳了），芯片自带 12 位 8 通道 ADC（按压盒可以从"开关阵列"升级为"力敏电阻直采"）。**
> **唯一的硬缺口是 ADC 引脚位置未知，必须尽快确认——确认不了就退回开关阵列，方案不受影响。**
