# 鲁棒性提升与一站式演示视频方案

> 面对对象：本项目（HX4S20C / 安路 EG4S20BG256 · 心肺复苏实时反馈训练终端）
> 依据：`project/rtl/`（43 个源文件、7256 行）、`tests/sim/`（60 个 TB、62 条用例）、`project/docs/`（46 份证据文档）
> 日期：2026-10-26 · 本文只做方案，不改动任何代码

---

## 0. 先给结论

**鲁棒性不是"多写几个 if"，而是四个可被检验的性质**：

| 性质 | 问法 | 本项目当前 |
|---|---|---|
| **不崩** | 最坏输入下还出画面吗 | 大部分能（有媒体故障码），但**没有"永远有画面"的兜底** |
| **可观测** | 出问题时屏幕/数码管/日志说得清吗 | 有 `state_code`（0xD 缺页 / 0xE 介质故障），但**没有统一的健康字** |
| **可自愈** | 用户能不能不动电源就恢复 | 能：按键触发重扫、WAV 100 ms 重解析、SD abort 兜底 |
| **可复现** | 下次改完还知道它没坏吗 | 62 条 RTL 用例 + 门禁脚本，但**一条命令跑全还是手工拼** |

最该补的 5 件事（按"演示收益 ÷ 改动量"排序）：

1. **兜底画面**——把"HDMI 全黑"这类最伤演示的失败模式从"可能发生"变成"不可能发生"；
2. **健康字 + OSD 角标**——让"设备在看什么、遇到什么"当场可见，这是视频里最有力的证据；
3. **4 条故障注入用例**（坏 RIFF / 截断 WAV / 换页中途拔卡 / 连续 200 次换页）进回归清单；
4. **`make verify` 一条命令**——RTL 自检 + TD 报告门禁 + 位流新鲜度，任一失败非零退出；
5. **资源余量**——81.99% slice 是 10-26 黑屏事件的间接嫌疑，降到 75% 以下再谈"稳定"。

# 第一部分 · 鲁棒性

## 1. 现状盘点：现在靠什么撑着

### 1.1 六个层次

```
        呈现层  兜底画面 / OSD / 数码管 / 滚动字幕
          ↑
        数据面  SD 事务仲裁 → 扇区重试 → WAV 头解析 → PCM FIFO → HDMI
          ↑
        控制面  复位释放 / 消抖 / 模式切换 / 页调度 / 三缓冲发布
          ↑
        跨域面  两级同步 / 格雷码 / 时间过滤 / SDC 例外
          ↑
        验证面  62 项 RTL 自检 / 门级后仿真 / TD 报告门禁
          ↑
        运维面  位流新鲜度守卫 / 构建参数分离 / 证据存档
```

### 1.2 逐层清单

| 层 | 机制 | 落在哪 | 证据 | **它不覆盖什么** |
|---|---|---|---|---|
| 复位 | 异步置位、同步释放；`ready` 过两级同步再放开 | `reset_release.v` | 各 TB 复位阶段无 X | 上电时序抖动（PLL 锁定失败）没有重试 |
| 复位 | 跨域复位"同时置位、各自同步释放" | `frame_buffer_publish.v` | 三缓冲 TB | — |
| 跨域 | 50+ 处 `_meta/_sync` 两级同步 | 全工程 | `grep -c "_meta\|_sync\[0\]"` = 56 | 多 bit 总线不能只靠两级同步 |
| 跨域 | 异步 FIFO 用格雷码指针 | `pcm_fifo.v`、`frame_read_write` | 26 处 gray | — |
| 跨域 | **非格雷码的多 bit 选曲码**用"连续 8 拍不变才认"做时间过滤 | `wav_track_select.v`（`S_sel_cnt`） | `tb_wav_track_select` | 8 拍 = 80 ns，只对"人按键"这种毫秒级变化成立 |
| 跨域 | 状态字用"邮箱 + busy 合并"而不是逐位同步 | `page_status_cdc.v` | `tb_page_status` | 不承诺事件计数，只承诺最终一致 |
| 约束 | **只剪第一级同步触发器**，保留 `set_max_delay` 飞行时间上界 | `constraints/project_cdc.sdc` | 0 viol endpoints，SWNS +0.128 | 约束写错时 TD 不会报错，只会在别处冒违例 |
| SD | 请求按 `I_ch1_read` **上升沿锁存**（整笔事务期间是高电平），换曲 abort 时丢挂起 | `sd_sec_arbiter.v` | `tb_sd_sec_arbiter_abort` | 卡被物理拔出（线路无响应）要靠超时 |
| SD | abort 后**等在跑的扇区交出 end** 再发新请求，`DRAIN_MAX` 1 ms 兜底放行 | `wav_audio_path.v` §5.5 前 | 上板"换页偶发卡死"已消失 | — |
| SD | 单扇区 1 s 无字节 → 超时；出错后 100 ms 重解析 | `wav_audio_path.v`（`WAIT_TIMEOUT_CYCLES` / `RETRY_CYCLES`） | 38 处 timeout / 38 处 retry | 卡已经坏到连 CMD 都不回时，只重试不报警 |
| SD | 失败**不改变已发布/正在显示的缓冲**，重试在后台进行 | `sd_card_bmp.v`（"Failure recovery never changes a published/displayed buffer"） | `tb_sd_image_recovery` 等 | — |
| SD | 介质故障 `media_fault`（0xE）/ 缺页 `page_missing`（0xD），**按键即重扫** | `sd_card_bmp.v` L163/L385 | `tb_sd_retry_limits` | 恢复过程用户看不见（只有数码管状态码） |
| 音频 | WAV 头 **8 类错误码**（非 RIFF / 无 fmt / 无 data / 格式不支持 / 长度不可信…） | `wav_reader.v` L93-100 | 4 条 WAV 用例 | 数据区不做 CRC（见 §2 P1） |
| 音频 | 双时钟 PCM FIFO + underrun 计数 | `pcm_fifo.v`、`wav_audio_path.v` | `O_underrun_cnt` 上板可读 | underrun 只计数，不抑制（会听到咔哒） |
| 音频 | 心跳 2:1 硬切 + `O_busy` 等包络收尾再切回 WAV | `wav_audio_path.v` §5.5 | `tb_heartbeat_synth` | 硬切交界仍有单帧阶跃（文档 §12 已说明） |
| 音频 | 频率常量 **48 bit** 乘法（32 bit 时 150 Hz 溢出成负数） | `heartbeat_synth.v` | 过零次数反推音调 | — |
| 输入 | 消抖 10 ms + **复位后第一拍只取基线不产边沿** | `input_filter.v` | `tb_input_filter` | — |
| 呈现 | 四缓冲 + **帧边界发布**（写完的 buffer 只在 reader 的帧起点生效） | `frame_buffer_publish.v`、`cpr_transition_publish.v` | `tb_slide_transition`、`tb_presentation_pipeline` | — |
| 验证 | 62 条 ModelSim 用例（另有 3～5 项独立故障注入做负控，见 `docs/verification-report.md`） | `tests/sim/run.py` | 2026-10-26 全量 62/62 PASS | 只覆盖 RTL 行为，不覆盖板级电器 |
| 验证 | 门级后仿真：`route.db` 导网表 + SDF 反标 | `tests/sim/postsim/` | 网表 10.1/10.9 MB，SDF 5.7 万 INTERCONNECT | 慢，不能进每次提交的循环 |
| 验证 | **正 slack 不算通过**：`td_report_checks.py` 审 `check_timing` 覆盖 | `project/td_report_checks.py` | `td-acceptance-*.md` | 需要人看报告 |
| 验证 | 接口延迟**只分类不豁免**：`audit_interfaces.py` | 同上 | `io-timing-budget.md` | — |
| 运维 | 位流新鲜度守卫：`0` 可跳过 / `1` 必须建 / `2` 判定失败也按必须建 | `scripts/bit_uptodate.ps1` | `build_bit_fast.bat` | 只比时间戳，不比参数 |
| 运维 | 构建参数分离：`build.tcl`(基线) / `build_fast.tcl`(实验) / `build_baseline.tcl`(对照) | `project/` | README 每次位流的参数+md5 | 参数与 RTL 的绑定关系靠人记 |

### 1.3 最有说服力的部分：真实故障 → 被哪条机制接住

鲁棒性讲"设计意图"没人信，讲"我们踩过并且不再踩"才有说服力。近一周实际发生的：

| 故障 | 现象 | 根因 | 现在的护栏 | 防止复发的手段 |
|---|---|---|---|---|
| 心跳音调偏低 | 峰值只剩 68.7% | `f * (1<<24)` 在 150 Hz 时 32 bit 溢出成负数，相位倒着走 | 48 bit 常量（上限 ~128 kHz） | `tb_heartbeat_synth` 用**过零次数反推音调**，不看波形只看频率 |
| 换页偶发卡死 | 连换几首后某页不换歌 | 旧扇区事务的 `end` 撞上新 header 解析 | abort 后等 end 收尾（`DRAIN_MAX` 兜底） | `tb_sd_sec_arbiter_abort` |
| `top_adc` 时序差 13 ps | 只有 ADC 顶层 FAIL | `page_pending` 跨层次长线 2.14 ns | 本地打拍再生（`_q`） | 两顶层都要过门禁，不许只报一个好的 |
| **黑屏无声音（数码管正常）** | 上板 HDMI 全黑 | 位流 P&R 参数（RTL 未变） | 实验参数撤出 `build.tcl`，只留 `build_fast.tcl` | 位流新鲜度守卫 + 参数分离 + README 记录 md5 |
| 上电自动进训练模式 | 按键"像坏了" | 上电瞬间已处于按下电平，被当成一次按键 | `input_filter` 复位后第一拍只取基线 | `tb_input_filter` |
| 白线（D123 竖线） | 画面右侧一条白线 | 行尾 padding 被当成像素 | 修正读地址收尾 | `check_white_line_mutations.py` |

> 这一节建议**原样进视频**，因为它是唯一能同时证明"完整性"和"鲁棒性"的素材。

### 1.4 诚实的边界：现在挡不住的 7 件事

1. **HDMI 可能全黑**（只发生在 P&R 参数异常时，但用户看到的是"设备坏了"）；
2. **SD 数据区没有 CRC/校验和**——SPI 层有 CRC，但"读到的 512 字节是不是文件里那 512 字节"没有端到端保护；
3. **没有看门狗**——视频域一旦丢帧同步，只能靠人按复位；
4. **没有上电自检**——SDRAM 坏了、FIFO 位错，表现是"偶尔花屏"，不报错；
5. **没有长时间测试数据**——最强的一句话"连续跑了 N 小时"目前没有 N；
6. **没有断电/热插拔的状态保护**——运行中拔卡有兜底（0xE），但"正在写卡时断电"不涉及（本工程不写卡）；
7. **资源 81.99%**——留给定局布线的碎片余量太小，这是"时序能过但板上不亮"这类玄学问题的温床。

## 2. 提升路线

> 原则三条：**① 失败要降级，不要黑掉；② 每个错误都必须可观测；③ 每次修复都要变成一条自动测试。**

### P0 · 一周内，改动小、演示收益最大

**P0-1 兜底画面（永远有画面）**

- 问题：`display_valid=0` 时输出 `24'h102030`（深蓝），黑屏与"设备死了"无法区分。
- 改法：在 `cpr_overlay` 之前加一层 `fallback_canvas`：用内置 ROM（640×480 1 bit 或 4 bit 小图 + 中文提示）在 `!display_valid` 时输出。ROM 用 8 KB 以内，能放一张"未检测到 TF 卡 / 正在准备素材"的提示卡。
- 验收：**不插卡上电 → 3 秒内出现提示画面**，不是黑屏；插卡后自动切到正常画面，无需复位。

**P0-2 健康字 + OSD 角标**

- 改法：把已有诊断信号打成一个 8 bit `health`：

  ```
  health[0] sd_init_done      health[4] wav_error != 0
  health[1] catalog_ready     health[5] underrun_cnt 增长中
  health[2] media_fault(0xE)  health[6] fifo 低水位告警
  health[3] page_missing(0xD) health[7] pll_locked
  ```

  一路进 `cpr_overlay`（右下角 8 个小方块，故障为红），一路进数码管第 4 位（现在固定全灭）。
- 验收：拔卡后 2 s 内 OSD 上 `media_fault` 块变红、数码管出 `E`；插回并按一次键，5 s 内全绿。
- 为什么值钱：**这是视频里"鲁棒性"唯一能用一秒钟讲清的道具**。

**P0-3 四条故障注入用例进回归**

| 用例 | 注入 | 期望 |
|---|---|---|
| `tb_wav_bad_header` | RIFF 魔数被改 | `ERR_NOT_RIFF`，**退回上一首继续播**，不出静音 |
| `tb_wav_truncated` | 声明长度 > 实际扇区 | `ERR_SIZE`，播到实际尾就停，不跳飞 |
| `tb_sd_yank_midpage` | 换页中途撤销 `sd_sec_end` | 状态回 `media_fault`，不锁死，恢复后能继续 |
| `tb_page_stress` | 连续 200 次换页 | 每次换页 ≤ 200 ms，最终页号正确，`err_cnt == 0` |

- 验收：4 条进 `run.py` 清单，总数 62 → 66，全绿。

**P0-4 `make verify` 一条命令**

```
tests/sim/run_msim.py --all      # 62 项 RTL
python project/td_report_checks.py …   # 正 slack 不算通过
python project/audit_interfaces.py …   # 接口延迟分类
powershell scripts/bit_uptodate.ps1 top top_adc   # 位流新鲜度
```

任一非零 → 整体非零。写进 `README.md` 第一屏，也写进视频的证据墙。

### P1 · 两周内，把"能演示"升级成"敢连续跑"

**P1-1 WAV 端到端一致性**：解析出的 `data_bytes` 与实际送进 FIFO 的帧数比一次，差值 > 1 帧即置 `wav_error`。比 CRC 便宜，能抓住 90% 的"卡坏/文件截断"。

**P1-2 上电自检（BIST）**：SDRAM 写读 4 个花样（0x00/0xFF/0x55/0xAA）+ 一片地址线走 1 → 结果进 `health[?]`；失败则**降级为单缓冲**（牺牲转场，保住画面）。板上有 46 块 RAM 已用满 82%，BIST 只在复位后跑 20 ms，代价可接受。

**P1-3 长时间测试**：4 h 循环（自动展播 + 每 3 分钟强制换页 + 每 10 分钟拔插一次卡），记录 `underrun_cnt / retry_count / error_code` 与板温（红外枪或手摸分档）。产出 `docs/longrun-YYYYMMDD.json`，视频里做成"延时摄影 + 计数面板"。

**P1-4 资源余量**：`cpr_font16_rom`（142 行查表）与两张教程图 ROM 是 slice 大户；把只读查表迁到 BRAM、把 24 bit 图像降到 RGB565 后再补，目标 slice ≤ 75%。**这不是洁癖**：82% 占用下 TD 的布线自由度不足，正是"时序数字漂亮、板上却黑屏"的经典土壤。

### P2 · 有余力再说

- **P2-1 视频域看门狗**：`vs` 边沿超 100 ms 不到 → 只复位显示通路（不动 SD/音频），避免"黑屏必须断电"。
- **P2-2 双备份位流 + 启动回滚**：若板上 SPI Flash 余量允许，存 A/B 两份，上电读版本号选新的、失败自动回 A。
- **P2-3 运行参数持久化**：亮度/对比度/音量写 Flash 时用双副本 + 序号，断电不丢也不乱。

# 第二部分 · 一站式演示视频

## 4. 定位与结构

### 4.1 一句话定位

> **一块 FPGA、一张 TF 卡、一个按压盒——把一段急救教育内容做成"上电即用、无人值守也不出错"的信息屏，同时又是一台能当场纠正你按压质量的训练器。**

这句话同时压住四性：一块板 = 完整性（音频/视频/传感器/存储全在片内），上电即用 = 实用性，无人值守 = 鲁棒性，"当场纠正" = 创新性。

### 4.2 时长与节奏

| 段 | 时间 | 内容 | 作用 |
|---|---|---|---|
| 钩子 | 0:00–0:40 | 上电即出图（秒级）+ 三模式三联画面 | 先给结论，别让人等 |
| 场景 | 0:40–3:25 | 模式①②③ 各走一遍 | 完整性 + 实用性 |
| 鲁棒性 | 3:25–4:55 | 拔卡/坏文件/狂按/长跑 | 独有的说服力 |
| 证据墙 | 4:55–5:45 | 62/62、0 viol、SDF 后仿真、位流守卫 | 把"稳"变成数字 |
| 创新 | 5:45–6:10 | 三条快剪 | 差异化 |
| 收尾 | 6:10–6:30 | 板子特写 + 一句话 | 记忆点 |

**三条节奏规则**：① 每 8–10 秒必须有一个新信息点；② 任何"我说很好"都要马上接"你看这里"；③ 故障段落全部用"倒计时 + 结果卡片"，像实验而不是像展示。

### 4.3 三种镜头语言

| 镜头 | 用途 | 器材 |
|---|---|---|
| **实拍** | 板子、按键、按压盒、数码管 | 手机 4K + 三脚架 + 微距（俯拍按压） |
| **屏录** | HDMI 画面与声音（**一次录到音画，免对轨**） | HDMI 采集卡（1080p60，UVC） |
| **素材** | TD 报告、仿真波形、代码、文档 | OBS 录屏 / 截图翻页动画 |

> 强烈建议**全程用采集卡录 HDMI**：拍屏会有摩尔纹和反光，而且音频必须单独录再对轨，后期成本翻倍。

## 8. 拍摄执行单

### 8.1 器材

| 项 | 规格 | 备注 |
|---|---|---|
| HDMI 采集卡 | 1080p60 UVC，带音频 | 主板 HDMI → 采集卡 → 笔记本；OBS 同时录 |
| 相机/手机 | 4K@30，手动曝光锁定 | 拍板子/按压盒，别自动对焦（会抽） |
| 三脚架 + 俯拍臂 | — | 按压盒必须正俯拍，否则看不清行程 |
| 补光 | 两盏 5600K 柔光 | 亚克力面板反光，用侧光 |
| 麦克 | 领夹或后期配音 | 现场只用环境音（按键"嗒"、心跳"咚"） |

### 8.2 TF 卡预置（拍摄前必须做完）

| 内容 | LBA | 说明 |
|---|---|---|
| BMP 镜像（4 页 + 缩放测试图） | 0 起 | `sd_card_bmp` 扫描 0..131071 |
| 第 1 段音频 | 12000 | 教学页 1 |
| 第 2 段 | 123000 | 教学页 2 |
| 第 3 段 | 250000 | 教学页 3 |
| 第 4 段 | 370000 | 教学页 4 |

烧卡：`python tools/burn_wav.py --list` → `--device N --track 5 --sector`（管理员权限，脚本会先做只读预检）。

### 8.3 拍摄顺序（先拍稳定段，后拍破坏段）

1. **屏录优先**：模式①②③ 各录 3 分钟原始素材（多录，后期挑）。
2. 拍板子特写、按键手感、按压盒行程（静音 B-roll）。
3. **破坏段最后**（拔卡会把卡上状态弄乱）：先做坏文件测试，再做拔插测试，最后恢复卡。
4. 4 h 长跑**前一晚开始**，延时摄影 + 计数面板截图，第二天作为素材进片。

### 8.4 后期规范

- 分辨率 1920×1080@60，H.264，12 Mbps；另出 60 s 竖版（9:16）发短视频平台。
- 字幕：底部居中，28–32 px，关键词加粗；**所有数字加角标**（右上角小卡，2 s 后淡出）。
- 故障段落统一模板：左上"实验 3/4"、中间现场画面、右上倒计时；结束时来一张"结果卡"（绿勾 + 关键数字）。
- 音乐：无版权 BGM，音量压到 −20 dB，故障段落**去掉 BGM 只留现场音**（紧张感）。
- 三种画面用不同边框色区分：实拍（无框）、屏录（细白框）、素材（细灰框 + 圆角）。

### 8.5 风险预案

| 风险 | 概率 | 预案 |
|---|---|---|
| 现场黑屏（P&R 参数问题复发） | 中 | ① 只用 `build.tcl` 基线参数出的位流；② 现场带**两块板/两份位流**；③ P0-1 兜底图上线后此风险归零 |
| 按压盒没准备好 | 中 | 用电位器或板载按键模拟力度档位，片中明确说"按压盒在最终版接入"，**别假装** |
| HDMI 音频不出声 | 低 | 检查显示器音频源切换；备选蜂鸣器节拍（H11） |
| 屏幕反光/摩尔纹 | 高 | 一律走采集卡；实在要拍屏，用偏振片 + 手动白平衡 |
| 拔卡后恢复慢 | 低 | 拍摄时预留 5 s；后期可加速并标注"×2 加速"（诚实标注即合规） |
