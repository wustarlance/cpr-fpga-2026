> 对象：`lab_ex5_i2s`（康芯 TF卡轮播 + HDMI 音视频）
> 方法：从顶层模块 `top_tf_hdmi_audio.v` 逐层分析

## 一、顶层接口

```verilog
module top(
    input  clk,              // 50MHz 板载晶振
    input  rst_n,            // 复位（低有效）

    input  key1,             // 手动下一张
    input  key2,             // 自动播放 开/关

    output [5:0] seg_sel,    // 数码管位选
    output [7:0] seg_data,   // 数码管段选

    output HDMI_CLK_P,       // HDMI TMDS 时钟
    output HDMI_D2_P,        // HDMI TMDS 数据2
    output HDMI_D1_P,        // HDMI TMDS 数据1
    output HDMI_D0_P,        // HDMI TMDS 数据0

    output HDMI_DDC_SCL,     // HDMI DDC（读显示器 EDID）
    inout  HDMI_DDC_SDA,

    output sd_ncs,           // TF 卡 SPI
    output sd_dclk,
    output sd_mosi,
    input  sd_miso
);
```

**接口很干净**：1 个时钟 + 1 个复位 + 2 个按键 + 数码管 + HDMI + TF 卡。

## 二、时钟结构（3 个 PLL，5 路时钟）

```verilog
// ① 系统 PLL
sys_pll sys_pll_m0(
    .refclk(clk),                 // 50 MHz
    .clk0_out(sd_card_clk),       // → TF 卡读取域
    .clk1_out(ext_mem_clk),       // → SDRAM 域
    .clk2_out(ext_mem_clk_sft),   // → SDRAM 相位调整
    .reset(1'b0)
);

// ② 视频 PLL
video_pll video_pll_m0(
    .refclk(clk),                 // 50 MHz
    .clk0_out(video_clk),         // → 25 MHz 像素时钟
    .clk1_out(hdmi_5x_clk),       // → 125 MHz TMDS 5×
    .reset(1'b0)
);

// ③ 音频 PLL
PLL_HDMI_AUDIO u_audio_pll(
    .refclk(clk),
    .extlock(audio_pll_lock),     // 锁定信号
    .clk2_out(audio_mclk)         // → 12.288 MHz 音频主时钟
);
```

| PLL | 输出端口 | 接到 | 频率 | 用途 |
|---|---|---|---|---|
| `sys_pll` | `clk0_out` | `sd_card_clk` | **100 MHz** | **TF 卡读取** |
| | `clk1_out` | `ext_mem_clk` | **125 MHz** | **SDRAM** |
| | `clk2_out` | `ext_mem_clk_sft` | 125 MHz **180°** | SDRAM 相位调整 |
| `video_pll` | `clk0_out` | `video_clk` | **25 MHz** | **像素时钟** |
| | `clk1_out` | `hdmi_5x_clk` | **125 MHz** | **TMDS 5×** |
| `PLL_HDMI_AUDIO` | `clk0_out` | *(未连接)* | 75 MHz | — |
| | `clk1_out` | *(未连接)* | 375 MHz | — |
| | `clk2_out` | `audio_mclk` | **12.288 MHz** | **I2S 音频** |

**三个 PLL 全部是 🏭 IP，并行工作，形成三个独立时钟域。**

### 频率是怎么查出来的（三步法）

| 步骤 | 查什么 | 得到什么 |
|---|---|---|
| **①** | PLL 的 `.v` 文件头注释 / `.ipc` 配置 | PLL **能**输出哪些频率 |
| **②** | 顶层怎么连的（`.clk0_out(...)`） | 哪个输出**接到**哪个信号 |
| **③** | 接收方模块的参数 | **交叉验证** |

**本表的依据**：
- `video_pll` / `PLL_HDMI_AUDIO` → 各自的 `.v` 头注释与 `.ipc`
- `sys_pll` → `sys_pll.ipc`，并用 `sd_card_bmp` 的例化参数 `CLK_FREQ_HZ(100_000_000)` **交叉验证**

> ⚠️ **只做第 ① 步会出错**：`.ipc` 里列出的频率 ≠ 实际用途。
> 本表初版就写错过（把 100 MHz 当成了 SDRAM 时钟），原因是漏了第 ② 步。

> 📌 **一个冗余设计**：`PLL_HDMI_AUDIO` 配了 3 个输出，顶层只连了 1 个。
> 75/375 MHz 是从原 I2S 工程复制过来没清理的。**你们生成 PLL 时只配需要的输出即可。**

## 三、复位结构

```verilog
wire rst_all;
assign rst_all = ~rst_n | ~audio_pll_lock;
```

**关键设计**：所有模块共用 `rst_all`。

```
rst_all = 0  仅当：  rst_n 有效（低）  且  audio_pll_lock 已锁（高）
```

**即：等音频 PLL 锁定后，才释放全局复位。**

这是**分级复位释放**的一个简化版——保证 PLL 稳定后再启动数据通路，**避免上电花屏**。

```
┌────────────────────────────────────────┐
│ hdmi_audio_tone_i2s_64fs                │
│   用 DDS 方式合成正弦测试音               │
│   PHASE_INC = 39370534 → 约 1kHz        │

│   输出左右声道 24bit                     │
└────┬───────────────────────────────────┘
     │ audio_left_data / audio_right_data
     ├──────────────────────────────────┐
     ▼                                  ▼
┌──────────────────────┐   ┌────────────────────────┐
│ audio_arc_calculate  │   │                        │
│  算 ACR 参数          │   │                        │

│ u_hdmi_1_4b_transmitter_core_wrapper            │◄┘

```

**ACR（Audio Clock Regeneration）是什么**：HDMI 里音频采样率不直接传，而是传一组 `CTS/N` 参数，让显示器**反推出音频时钟**。这是 HDMI 协议的机制。

## 七、双缓冲机制详解

**两个缓冲区**：

```verilog
parameter FRAME_PIXELS = 24'd307200;   // 640 × 480
parameter BUF0_ADDR    = 24'd0;
parameter BUF1_ADDR    = FRAME_PIXELS; // 307200
```

**两个索引**：

```verilog
wire [1:0] write_buf_idx;   // 当前往哪个 buffer 写
wire [1:0] disp_buf_idx;    // 当前显示哪个 buffer
```

**工作方式**：

```
时刻 T1:  显示 BUF0   ← 用户正在看 A 图
          写入 BUF1   ← 后台正在解码 B 图

时刻 T2:  B 图解码完成 → frame_write_finish
          交换索引！ disp_buf_idx ← 1

时刻 T3:  显示 BUF1   ← 切换到 B 图（瞬时完成，无撕裂）
          写入 BUF0   ← 后台开始解码下一张
```

**关键：切换显示时只改一个索引，不搬数据。** 所以切换是瞬时的、无撕裂的。

**跨时钟域的"写完成"信号**：

```verilog
// mem_clk 域把 write_finish 单拍转成 toggle
always @(posedge ext_mem_clk or posedge rst_all) begin
    if (rst_all)
        frame_write_toggle_mem <= 1'b0;
    else if (frame_write_finish)
        frame_write_toggle_mem <= ~frame_write_toggle_mem;
end
```

**为什么用 toggle 而不是直接传单拍信号？**

- 单拍脉冲跨时钟域，**可能被漏采**（目标时钟慢于源时钟时）
- **toggle 方式**：信号只在"完成"时翻转一次，目标域用**边沿检测**捕捉，**永远不会漏**
- 这是**跨时钟域传事件信号的标准手法**

**你们一定要掌握这个技巧。**

## 八、三个值得学的设计点

### ① 分级复位释放

```verilog
assign rst_all = ~rst_n | ~audio_pll_lock;
```

等 PLL 锁定才释放复位。**避免上电时时钟不稳导致的随机行为。**

### ② 首图黑屏保护

```verilog
assign vout_data = display_valid ? vout_data_raw : 24'd0;
```

**第一张图还没解码完时，输出纯黑**，而不是随机数据（那就是花屏）。

### ③ 双缓冲 + 索引切换

见上文。**这是"无撕裂切换"的核心机制。**

## 九、对你们项目的启示

### 直接可复用的思路

| 参考工程的做法 | 你们可以怎么用 |
|---|---|
| 三 PLL 分域 | 同样需要（像素/存储/音频） |
| 双缓冲 + 索引切换 | **直接照搬思路**，改成你们的调度策略 |
| toggle 跨时钟域 | **照搬**，这是标准手法 |
| 分级复位 | 照搬，改成你们的分级 |
| 首图黑屏保护 | 照搬 |
| RGB → AXIS → HDMI | 接口照抄 |
| ACR 参数计算 | 照抄（HDMI 音频必需） |

### 你们要在它基础上"加"的

```
参考工程：  TF卡 → BMP → 帧缓存 → HDMI
                    ↑
你们的：      字模渲染 → 图层叠加 → 色彩查表
                    ↑
              这一层是全新的，参考工程没有
```

**具体来说，你们要做的改动：**

1. **在帧缓存**读**通路**后、HDMI 前，插入**像素处理流水线**
   - 现在的路径是 `video_delay → vout_data → axis`
   - 你们要变成 `video_delay → [字模叠加] → [色彩查表] → vout_data → axis`

2. **字模数据从哪来** —— 参考工程只读 BMP；你们还要读**字库文件**
   - 需要扩展 `sd_card_bmp` 或新增一个字库读取模块

3. **页面调度** —— 参考工程是"按键切图"；你们要"页面 + 语音 + 模式"
   - 控制状态机要重新设计

### 你们不用碰的

- PLL 配置（照抄参数，重新生成）
- SDRAM 控制器（用 IP）
- HDMI 发射核（加密，只能调用）
- I2S → HDMI 音频链路（照抄）

## 十、一句话总结

> **参考工程 = TF卡读图 + 双缓冲 + HDMI音视频输出**
> **你们 = 在它的"帧缓存 → HDMI"之间，插进一层自己的渲染引擎**

**主线认清了吗**：

```
TF卡 → BMP解码 → SDRAM双缓冲 → (你们的渲染引擎) → HDMI
                     ↑                  ↑
                照抄思路           全新自研
```
