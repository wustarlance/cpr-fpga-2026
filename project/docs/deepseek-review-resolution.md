## 报告中需纠正的接口表述

- `rotate_due` 是保持到复位、停用或清场的到期电平，表示人员轮换，不是一拍脉冲；`tb_training_events` 已检查到期后继续保持。
- 稀疏采样的 PD 脉宽为一个 ADC 时钟，PD 输出上升沿比 SOC 输出上升沿提前五个 ADC 时钟。「SOC 前一拍脉冲」容易混淆脉宽和提前量，现有 [ADC 契约](adc-contract.md) 已准确规定。
- 事件模式仅接收 `press_event && !press_fault`。故障同拍的完成事件不会加计数或更新等级；正常完成可清训练级故障显示，但不能解除采样链的硬件粘滞故障。
- 按压计数在完成事件的处理时钟更新，不只在 `tick_ms` 时更新。使能首拍与清场优先于同拍事件/毫秒使能，输入不会排队保留。
- 事件接口要求发送方提供一拍事件；持续高电平会被逐拍处理。清场持续高也会连续置位 `beat_event`，不能无条件保证所有调用方式下输出仅一拍。
- 原报告多处源码行号偏移，本次依据信号、条件和实际接线复核，没有把整份接口表直接作为已核准工程契约。

## 八项待确认事项

| 事项 | 当前结论及依据 |
|---|---|
| ADC 超时计数 | [tb_adc_ctrl](../../tests/sim/tb/tb_adc_ctrl.v) 已检查 SOC 后前 63 拍不超时、第 64 拍超时，以及五拍后的恢复 SOC；对应测试记录通过。 |
| 直通寄存延迟 | 接受沿 N 后更新输出，下游沿 N+1 读取；已明确写入压力契约。 |
| 未使用输入 | 独立实例应接确定的零值；当前默认顶层的事件输入固定为零，ADC 模式的接触输入仍有确定驱动但不参与训练事件处理。 |
| 毫秒来源 | [timebase](../rtl/timebase.v) 的独立默认值是 50 MHz，`cpr_control` 配置为 25 MHz，计数 25000 拍；不补偿整数除法余数，实测精度仍依赖时钟。 |
| 速率边界 | 500–600 ms 两端包含，499/500/600/601 ms 及同拍毫秒修正均由 [训练事件测试](../../tests/sim/tb/tb_training_events.v) 检查。 |
| `in_press` | 采样链有意不导出该内部状态。未来若 UI 需要持压指示，应另行规定接口，目前没有功能缺陷证据。 |
| 用户共同复位 | 板级顶层将 KEY1 对应的 `rst_n` 与全部 PLL 锁定状态组成共同复位原因，各域同步释放；清场不替代该复位。 |
| CDC 物理约束 | [ADC 邮箱 SDC](../constraints/adc_mailbox.sdc) 约束完整字路径为 40 ns；TD 日志确认源/目标各 12 位绑定。尚未布局布线，不能据此宣布跨域物理时序已收敛。 |

## 验收清单与现有证据

报告清单 1–4、5–6、10–11 的数字场景由现有邮箱、归一化、峰值、ADC 和采样链测试覆盖，证据见 [基础架构验证报告](verification-report.md)。第 6 项按「PD 脉宽一拍、提前五拍」理解。第 9 项按各域的有效协议解释，连续有效采样不应被误判为脉宽错误。

第 7 项的非法 ADC 配置策略由源码确认，测试实测了 `SAMPLE_HZ=0`，并未遍历每类非法参数组合。第 8 项超时边界的 armed EOC 优先由源码分支顺序确认；当前 `tb_adc_ctrl` 没有独立的第 64 拍同时注入 EOC 的场景，不能登记为该场景仿真通过。第 12 项的 CH1 路径与名义时钟已对照官方资料，实际模拟输入、参考电压和时钟测量仍待实板完成。
