# 重启后横线改变：本轮定位记录

基线：GitHub main `c8f2ab93601ccbea23d1418084333b3680622100`。用户确认实际烧写 main 最新版，横线肉眼可见，同次运行中基本固定，重新启动后位置变化。训练页反馈面板与页眉保持正常，白线主要落在教程底图。

main 已包含 PR #5 的频率显示与刷新互锁，也包含 `c6199e2` 的缩放除法准备流水线修正。不能再以旧 main 为基线，也不能把前一轮仿真结果解释为板上横线已消除。

本轮不修改产品 RTL、PLL、IP、引脚、时序约束或 SD 素材。新增独立 [D107 板上诊断](../../tests/board/sdram/README.md)，使下一次观察能区分直接显示输出与实际 SDRAM 数据完整性。它是定位工具，**尚未证明横线已经修复**。

同时新增 `tb_frame_roundtrip`，使用当前实际生成的 FIFO RTL，校验四槽数据的写入和读回。旧 `tb_sd_scaled_pipeline` 校验了写入像素，却没有校验读回像素，而且读 FIFO 模型复用了写 FIFO 的 show-ahead 行为。本轮保留原测试，增加独立往返校验，避免将其覆盖范围夸大。

往返测试已通过 5120 像素的逐字核对。测试模型必须遵守实际 FIFO 的 511 字可用容量，而不能假设能放满 512 字后再读；最终测试直接编译原厂 FIFO，消除了这一模型差异。

验证证据按本次交付清单记录：新增两项仿真，频率与刷新互锁回归，以及禁用读回错误检查、误改读 FIFO 模式的负向控制。没有执行烧板、TF 写入或硬件验收。

本地旧 TD 6.2.168116 可以综合诊断工程；完整构建的时钟布线严重告警尚未通过门槛。团队需使用已验证的 TD 6.2.178840/SP1 重建，只有完整结果 `passed` 后才做板上诊断。记录表与结果判读见 D107 说明。

协议事实依据为所提供的安路 `APUG011_基于ERAM接口实现的高性能SDRAM读写v1.2.pdf`：物理 PDF 第 6–10 页，涉及刷新开始条件、进行中的读写、十拍响应、四字分组与接口信号。没有按其他 FPGA 厂商的原语或时序假设修改本工程，也没有修改 SDRAM 频率/相位来尝试掩盖故障。
