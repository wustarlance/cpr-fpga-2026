## 1. PLL 反馈：连接已核对，告警未关闭

三个 PLL 均采用 `NORMAL / CLKC0_EXT`，经 `EG_LOGIC_BUFG` 返回 `fbclk`。资料包 APUG011 官方参考 ZIP 的 `prj/al_ip/clk_pll.v` 也使用相同反馈结构；它的输入频率、输出频率和板卡引脚与本项目不同，不可直接替换。

对完成布线的两个检查点执行只读查询，三个反馈网的 `Route Type` 都是 `global`，驱动器是 `EG_PHY_GCLK`；系统与音频反馈端点报告的 NetDelay 都是 2099 ps。该查询限制打印前 8 个负载，视频 PLL 的反馈端点未列在这 8 个负载内，不能给它补写未观测的延迟值。完整构建仍对三个 PLL 各报 `USR-6135`，称反馈路径位于本地网络、补偿延迟不可预测。

“网被归为 global”不证明每段反馈路径都使用专用资源，也不能据此认定检查器误报。之前最小工程和有效网名的专用路由要求仍复现告警，故未继续改反馈模式。PLL 指南 PDF 第 3 页指出 No Compensation 不补偿网络延迟；改成该模式会改变时钟相位假设，不能作为消警措施。

**关闭条件：** 安路针对 EG4S20BG256 / 6.2.168116 给出支持的反馈结构或约束，并以同输入复现证明实际反馈路径符合补偿要求；若属于工具诊断问题，需要明确适用条件的厂家说明。

## 2. SDRAM 转发时钟与宏位置：已定位，告警未关闭

两个顶层中，相移 180° 的 40 MHz 时钟都直接由系统 PLL `clkc[2]` 驱动内置 SDRAM 时钟 PAD，端点为 `U3/sdram_syn_45.do[0]`（ADC 顶层多 `u_board/` 前缀），布线延迟报告为 2581 ps。CTS 摘要明确列出该网 `Clock/Fanout=0/1`、`LocalWireNum=1`，并保留 `PHY-5079`。

路由 PNL 中 SDRAM 宏均位于 `x20y36_0`。构建日志仍有 `PHY-7002`：top 一条，top_adc 两条。PNL 的网格位置与日志中的物理坐标不能混写为同一单位，也不能仅凭最终有位置就豁免重定位。

只读 DRC 没有多驱动和异常时序路径，以上两类告警仍有效。先前 ODDR 最小实验虽消除 `PHY-5079`，却出现时钟根检查及负 setup，未进入产品。当前保留 D123 已实板验证的实现。

APUG011 PDF 第 6 页对连续写入给出至少 64 MHz 的要求。当前是 40 MHz 有限突发和实验得到的 64 拍间隔；这份文档没有明确给出该配置的豁免。仍需厂家确认此 IP 的工作条件。

**关闭条件：** 厂家确认该封装内 SDRAM 的合法宏位置、可正确建模的时钟输出路径，以及 40 MHz 有限突发是否属于支持条件；再实施有依据的修改并重新实现。任何物理改动后的白线/启动行为还需另行实板验证。

## 3. I/O 时序：端口清单已补全，外设预算未齐

每个顶层仍有 19 个输入、29 个输出缺少接口延迟；双向 DDC SDA 在两方向都计数，去重后为 **47 个端口位**。

| 类别 | top 输入 | top_adc 输入 | 输出（两顶层相同） | 当前结论 |
|---|---:|---:|---:|---|
| 默认未启用的外接按键/档位输入 | 9 | 9 | 0 | 仅适用于 USE_EXTERNAL_IO=0 |
| ADC 模式未用的演示拨码 | 0 | 1 | 0 | 配置相关，不能推广到默认 top |
| 异步按键/拨码 | 7 | 6 | 0 | 保留控制 CDC 审查，本轮不改按键 |
| 异步复位 | 1 | 1 | 0 | 需按复位释放结构解释 |
| LED / 数码管 | 0 | 0 | 20 | 无外部采样时钟的状态输出 |
| SD SPI | 1 | 1 | 3 | 需卡、板级和 FPGA I/O 预算 |
| HDMI DDC | 1 | 1 | 2 | 需 IP 与上拉/负载条件 |
| HDMI TMDS | 0 | 0 | 4 | 需串行输出/转发时钟裕量依据 |

SD 控制器采用 100 MHz 逻辑时钟，初始化 SPI 约 200 kHz，传输 SPI 为 25 MHz，MISO 在 SCK 上升沿对应的逻辑时钟拍采集。资料包 `SDSDv17.pdf` 是 **2003 年 SanDisk 特定产品手册**：PDF 第 34 页将 SPI 条件关联到总线条件，第 36–37 页给出单卡、负载不超过 25 pF 下 setup/hold 各 5 ns，数据传输输出延迟 0–14 ns、初始化输出延迟 0–50 ns。该文件不是当前实际卡型号或板级传播/负载的证明，因此仅作为预算参考，没有直接写入产品 SDC。初始化和传输还需分别建模。

当前 HDMI 是 25 MHz 像素、125 MHz 串行 DDR，名义串行 UI 为 4 ns。官方 APUG092 示例的时钟分组不能原样套用：本项目像素/串行时钟同时工作且传输数据，不能设成互斥来消除分析。

另有 32 项封装内 SDRAM 输入延迟异常提示，需要结合内置宏和 IP 的时序模型解释。dangling 摘要中的 3/4 是本版本报告的**模型组数**，明细为 top 458 个原语引脚、top_adc 537 个。明细包含未用原语输入、恒定/未启用 I/O 等，不能直接将数量称为功能故障，也没有做全量豁免。逐端口、逐模型明细见配套 JSON。

**关闭条件：** 补齐实际 SD 卡及板级负载/延迟预算、HDMI/DDC IP 的接口验收依据，使用正确的边沿和 min/max 延迟重新分析；对结构提示保留配置范围内的解释。不能用零延迟、宽泛 false_path 或物理 DQ 多周期例外制造通过结果。
