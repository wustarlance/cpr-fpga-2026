# 训练页面管理

2026-10-15。HX4S20C / EG4S20BG256；在本地 SD 超时恢复版本上接入。本次通过分支 `codex/cpr-sd-pages-20261015` 提交 PR；不能用之前版本的构建记录代替本次验证。验证 JSON 的 `github_published=false` 记录验证执行时的状态。

## 操作

- 进入训练时保存当时真正显示的浏览页，并请求第二张“胸外按压”。
- 训练中上一张、下一张循环浏览已扫描到的教程，不清空训练计数；两个键同时按下不翻页。
- 退出训练请求恢复保存的浏览页。进入时还没有成功显示过图片，则退出后请求第一张。
- 连续操作保留最新目标。已开始的加载和帧发布先安全结束，再处理最新目标；退出恢复覆盖尚未开始的训练翻页。
- 训练期间停止自动展播。教学和自动模式继续使用原有操作。

默认 `top` 的板载 KEY2 用来模拟按压，因此训练中不翻页。`top_adc` 使用 ADC 采集按压，训练中板载 KEY2 下一张、KEY3 上一张。外接按键时，在 `top` 或 `top_adc` 选择 `USE_EXTERNAL_IO=1`；`ext_keys_n[0..4]` 分别为模式、上一张、下一张、亮度、清场，低有效。接线及电气条件继续按 `pin.adc` 和板卡资料核对。默认配置没有启用外接输入。

默认训练页通过两种顶层的 `TRAINING_PAGE_INDEX=2'd1` 设置，取值为零起始的 0～3。翻页输入来自 `cpr_control.keys_level` 的已去抖电平，进入训练前一直跟踪按键；进入时已经按住的键不会额外翻一页。扫描尚未结束时保存模式请求，暂不接受前后翻页。

## 素材与状态提示

页号按原始扇区扫描发现的有效 BMP 顺序分配，硬件不识别图片内容，也不读取文件名。请让四张有效图片依次为判断呼救、胸外按压、开放气道与人工呼吸、AED；640×480、24 位无压缩、正高度的格式和受控扇区布局要求不变。若第二张在卡中实际是别的内容，仍会显示第二张。

页眉 x176～255、y0～15 加入五字符状态，不占用教程区域。例如 `T2-4L` 表示训练中请求第 2 页、共 4 页、正在加载；`P4-4 ` 表示浏览时已显示第 4 页。

| 标记 | 含义 |
|---|---|
| `T` / `P` | SD 页面管理器已接收的训练 / 浏览状态 |
| 第二字符 | 空闲时为已显示页号；加载或缺页时为目标页号；尚无图片时为 `-` |
| 第四字符 | 目前扫描到的有效页数，0～4；扫描中可能尚未最终确定 |
| `L` | 等待扫描、排队、加载、恢复或等待帧发布确认 |
| `M` | 扫描已结束，指定页号不存在；数码管状态显示 D |
| `E` | SD 有限重试耗尽；数码管状态显示 E；优先于 M/L |

加载或出错时保留已有完整画面。只有一张图时，进入训练会明确显示 `T2-1M`，不会把第一张偷偷当成胸外按压；按前后键可显式选择现有第一张。没有有效图时显示缺页状态，不发无效加载。

SD 错误仍按 [SD 恢复契约](sd-recovery.md) 做有限重试。被加载器接收的请求不会因失败自动重新排队；新的模式/翻页操作可发起恢复。失败扫描需新的操作触发重扫。已明确排队的较新页面请求会在当前恢复结束后执行。

## RTL 与跨时钟接口

`cpr_page_manager` 在 100 MHz SD 域处理绝对页号。`request_valid` 保持到 `request_accept`，同拍接受的含义为调度器接管请求；成功显示仍需 BMP 源完成、写帧完成和读端帧边界确认。新模式/按键请求优先于同拍旧请求的 ACK。

`sd_card_bmp` 新增 `training_active`、`training_next`、`training_prev` 三个正逻辑电平输入，各经两级同步。调用方必须提供去抖电平，不能直接接机械触点或窄脉冲；旧测试显式连接为零。三路电平与原有自动模式来自相关的 25 MHz 视频时钟，保留原有时钟关系。

`page_status[11:0]` 仅在 SD 域使用，布局如下：

| 位 | 内容 |
|---|---|
| 11 | 已有成功显示的图片 |
| 10:9 | 当前真正显示的图片索引 |
| 8:6 | 已扫描有效图片数 |
| 5:4 | 排队目标，否则为在途加载目标，否则为当前页 |
| 3 | 正在加载/恢复/等待可用目标 |
| 2 | 指定目标缺页 |
| 1 | 重试耗尽的媒体错误 |
| 0 | 已同步到 SD 域的训练模式 |

`page_status_cdc` 通过现有 12 位 `sample_mailbox` 将完整状态字传到视频域，忙时合并中间状态，最终交付最新稳定状态。源字保持到目的端采样并返回 ACK，不承诺传递每个瞬时状态。双方共同异步置复位、各域同步释放；不支持单边独立复位。

新增 `page_status.sdc` 限制保持字到目的寄存器的数据路径为 40 ns，只对请求/ACK 的首级同步寄存器设置例外。`build.tcl` 在 RTL 优化后要求两端各匹配 12 位；TD 可能将源 `src_hold` 合并为等价的 `last_sent` 寄存器，仍须核对实际匹配集合。没有扩大时钟组例外，也没有更改 PLL、引脚、FIFO 或 SDRAM IP。

OSD 在 VS 下降沿捕获完整状态，同一帧中页码保持不变。显示可能晚于实际换图一帧或数帧，不能把页眉当作内存缓冲区归属握手。

## 验证与验收

```sh
python tests/sim/run.py tb_page_manager tb_page_status tb_training_pages
python tests/sim/run.py --all --self-test-runner
python project/verify_td.py --td "E:/bin/td_commands_prompt.exe" --stage full
```

新增三项自检：策略测试覆盖保存/恢复、按住进入、忙时更新、同时按键、同拍 ACK/模式变化、缺页/空目录和复位；双时钟状态测试覆盖忙时合并、完整字、最终值和页眉帧快照；整链测试使用真实 BMP、调度器、发布和写帧状态机，检查四种不同像素图、地址、双缓冲归属，以及加载中退出、自动模式竞争、SD 错误、缺页与重扫。

整链测试采用 4×2 图、SD 扇区模型和行为 FIFO/内存；不是实卡、加密 FIFO 或 SDRAM 的电气模型。完整清单共 30 项 RTL 自检及 5 项运行器检查。本次另用四个独立错误副本验证检查器：训练跳错页、退出恢复错页、忙时丢掉目标、跨时钟直接采样未保持的总线。产品源码中不保留这些错误。

当前构建、资源、时序和工具限制见 `page-validation-20261015.json` 与本地交付说明。实板需验证四图顺序、三模式切换、训练中连续翻页、加载中退出、长按进入、断卡保留旧图及恢复、复位重进；同时观察训练计数和按压采集正常。本次没有烧板、擦 Flash 或写 TF 卡。
