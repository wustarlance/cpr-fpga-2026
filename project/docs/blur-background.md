# 非 4:3 图片的模糊补边背景：实现说明

> 适用：`top` / `top_adc` 两个顶层，默认 `BLUR_BACKGROUND = 1`。
> 代码：`project/vendor/SD/bmp_blur_background.v`（460 行）、`project/vendor/SD/bmp_read_scaled.v`（两遍读取与合成）。
> 前置阅读：[四槽全缓存与加载时缩放](image-cache-scaling.md)。

---

## 1. 为什么需要它

教程图按 contain（等比缩小到能装下）上屏。源图不是 4:3 时，画面四周必然留出补边区：

- **正方形 640×640** → 缩到 480×480，左右各 80 列；
- **竖图** → 上下补边；
- **4:3 的图**（640×480、1280×960、320×240）→ 正好铺满，**不需要补边**。

补边区填纯色 `#102030` 时，一块亮色照片会被两条突兀的深色竖条夹住，像是"没做适配"。所以这里不是填纯色，而是**把这张图自己裁成 4:3、缩成缩略图、模糊放大、压暗到 75%，当作底铺满整屏**，再把清晰的前景盖在中间。

设计原则有两条：

1. **等比不变形**——医学示意图一旦拉长压扁就是错误示范；
2. **前景不插值**——前景仍是最近邻（`src_x = x·src_w/fit_w`），保原始像素锐度、不占乘加资源；**插值只花在看不见的底上**。

## 2. 总体流程：一次加载，两遍读源图

```
                    ┌──────────────── pass 1（背景预处理）────────────────┐
SD 卡 ── 扇区 ──► bmp_read_scaled ──(逐像素)──► bmp_blur_background
                    每行取 R/G/B 三通道             │
                                                     ├─ ① cover 裁切成 4:3
                                                     ├─ ② 32×24 面积平均缩略图
                                                     ├─ ③ 3 遍 3×3 盒式模糊
                                                     └─ ④ 双线性采样器待命（32×24 → 640×480）

                    ┌──────────────── pass 2（正常出图）──────────────────┐
SD 卡 ── 扇区 ──► bmp_read_scaled ──► 最近邻缩放 ──► bmp_data ──► SDRAM 帧缓存
                     │                                     ▲
                     └── 落在 contain 矩形外？ ──► BG_SAMPLE_REQ ──► ④ 取模糊采样
```

`bmp_read_scaled` 里的合成逻辑就一行（[`project/vendor/SD/bmp_read_scaled.v`](../../project/vendor/SD/bmp_read_scaled.v)）：

```verilog
assign bmp_data = (in_content_x && in_content_y) ? row_q :        // 矩形内：清晰前景
                  ((bg_enabled && bg_done) ? bg_pixel_q : 24'h102030); // 矩形外：模糊底，失败回退纯色
```

**为什么要读两遍**：缩略图必须看完整幅源图才能算面积平均，而 SD 卡是流式读取、没有整帧缓冲可用（整帧 640×480×3 = 900 KB，放不下也不该放）。所以先把整幅图过一遍做背景，再从头读第二遍出画面。

代价与代价控制：

| 项 | 4:3 图 | 非 4:3 图 |
|---|---|---|
| 源图读取遍数 | 1 | 2 |
| `LOAD_TIMEOUT_CYCLES` | 3×10⁸（100 MHz 下 3 s） | 1.2×10⁹（12 s） |
| SDRAM 写入 | 一遍 | 一遍（补边像素直接写模糊底） |

## 3. 背景模块的内部：四个阶段

`bmp_blur_background.v` 是一个单状态机，四个阶段串行，共用一套乘法器与除法器。

### ① cover 裁切成 4:3

```
aspect_w = src_w × 480
aspect_h = src_h × 640

aspect_w ≥ aspect_h  → 源图偏宽：裁左右
    crop_h = src_h
    crop_w = aspect_h / 480        // 一次 32 拍恢复除法
    crop_left = (src_w - crop_w)/2,  crop_bottom = 0
否则                 → 源图偏高：裁上下
    crop_w = src_w
    crop_h = aspect_w / 640
    crop_bottom = (src_h - crop_h + 1)/2,  crop_left = 0
```

即 CSS 的 `object-fit: cover`：先等比铺满 4:3 再居中裁掉多余部分，保证缩略图里不会有黑边混进来。

### ② 32×24 面积平均（精确分数边界）

缩放网格是 `bw × bh`，其中 `bw = min(32, crop_w)`、`bh = min(24, crop_h)`——源图比 32×24 还小时网格自动变小，1×1 也安全。

每个桶覆盖 `crop_w/bw × crop_h/bh` 个源像素（640×480 → 正好 20×20）。**不是顺手取一个点**，而是把桶覆盖范围内的源像素逐点累加：

- 累加器是**一行 32 个 120 位寄存器**（R/G/B 各 32 位 + 24 位计数），不是整帧缓冲；
- 桶边界落在源像素中间时，用 `x_rem`/`y_rem` 记余数做**分数边界重叠加权**，桶跨边界时按真实覆盖长度累计，桶内权重和恒等于计数；
- 一个桶的 R/G/B 用同一个共享 32 位恢复除法器依次除以计数，得 8 位值写入 `thumb_a`。

为什么较真分数边界：整数盒会退化。1024×768→640×480 用 `[floor(x·r), floor((x+1)·r))` 做盒平均只有 30.48 dB，**比最近邻还差**；带分数重叠加权才能到 45.22 dB（Python 金标准 `project/tools/scaler_golden_model.py` 的实测值）。

### ③ 3 遍 3×3 盒式模糊

对 32×24 缩略图做 `BLUR_PASSES = 3` 遍 3×3 盒式模糊：

- **乒乓缓冲**：`thumb_a` ↔ `thumb_b` 交替读写，`final_source` 记住最后结果在哪一片；
- 每遍每像素累加 9 个抽头后 `/9`，除法仍复用同一套恢复除法器（`div_den = 9`）；
- **边缘钳位**而不是补零：`nxm/nxp/nym/nyp` 全部 clamp 到 `0..last`，否则模糊后画面四周会一圈发暗的边框。

3 遍 3×3 盒式的等效高斯 σ ≈ 1.4 个缩略图像素 ≈ 28 个输出像素——足够把文字化成色块，又不会糊成一整片单色。

### ④ 双线性采样器（32×24 → 640×480）

补边区的每个输出像素都向这个采样器要颜色：

```
x_fp = clamp( ((x·2+1)·bw·128) / 640 − 128 , 0, last_x·256 )   // 8.8 定点
y_fp = clamp( ((y·2+1)·bh·128) / 480 − 128 , 0, last_y·256 )
```

取 4 个邻点 → 两次水平线性 + 一次垂直线性（`h0/h1` → `interpolation_r`），加法带 `+32768` 做四舍五入，最后

```
out = clamp( (v · BRIGHTNESS_NUM) >> BRIGHTNESS_SHIFT , 0, 255 )
    = clamp( (v · 3) >> 2 , 0, 255 )        // 压到 75%
```

压暗是为了让前景（通常更亮）压得住背景，也让 OSD 白字落在补边区上仍然可读。

乘法器只有一组（`mul_a × mul_b`，一拍一乘，三通道串行），除法器只有一套，所以一个像素要几十拍——但**只有补边区的像素才会请求采样**，矩形内的像素走前台直通，不付这个时间。

## 4. 触发条件与回退

| 情形 | 行为 |
|---|---|
| contain 结果正好 640×480（4:3 源图） | `bg_enabled = 0`，走原来单遍直通路径，**逐字节不变** |
| 需要补边 且 `BLUR_BACKGROUND = 1` | 双遍 + 模糊底 |
| 需要补边 但 `BLUR_BACKGROUND = 0` | 单遍，补边区是纯色 `#102030`，整个模块被 `generate` 掉 |
| 模糊任务未完成 / 被取消 / SD 初始化丢失 | `bg_done = 0` → 补边区自动回退纯色，**不会出现半幅模糊** |
| 源图小于 32×24（极端小图） | 网格自动缩到 `min(32,w)×min(24,h)`，桶计数为 0 时除数被钳到 1 |

参数在顶层（[`project/rtl/top/top_tf_hdmi_audio.v`](../rtl/top/top_tf_hdmi_audio.v) / [`project/rtl/top_adc.v`](../rtl/top_adc.v)）：

```verilog
parameter BLUR_BACKGROUND     = 1;   // 0 关闭整个功能
parameter BG_BRIGHTNESS_NUM   = 3;   // 亮度 = NUM/SHIFT = 75%
parameter BG_BRIGHTNESS_SHIFT = 2;
```

## 5. 资源占用

| 存储 | 规模 | 实现 |
|---|---|---|
| `thumb_a` / `thumb_b` | 768 × 24 bit × 2 = 36,864 bit | 强制 BRAM（`ram_style="bram"`），约 4 个 BRAM9K |
| `accum[0:31]` | 32 × 120 bit = 3,840 bit | 一行桶累加器 |
| 乘法器 | 1 组 18×9 → 27 bit | 与输入/输出共用一套 |
| 除法器 | 1 套 32 拍恢复除法 | crop 商、桶平均、盒式 /9、采样坐标共用 |

**没有任何整帧缓冲**：这是本模块能在 64 块 BRAM 的 EG4S20 上和四槽帧缓存共存的前提。

## 6. 时序上踩过的坑（可写进答辩）

这些注释都留在 RTL 里，是真实调过的：

1. **桶地址锥直连 BRAM 地址口**：clamp + shift + add 共 6 个加法器、12 级逻辑，10 ns 违例 → 加一拍寄存 `read_addr_q`，代价是每次取点多等一拍。
2. **归约比较串进状态锥**：`payload_left == 0` 的 32 位归约直接喂 `finish → state`，是 `sd_card_clk` 域最差路径（9.75 ns / 10 级）→ 改成与 `payload_left` 同拍维护的 `payload_zero_q`。
3. **双线性求和直连输出**：乘加结果到 `sample_rgb` 之间 6 级逻辑，同时违例 setup 和 hold → 求和单独寄存进 `interpolation_r`，`V_SAVE` 只做字节缩放。
4. **`INIT_COMPARE` 拆两拍**：仿真全绿，但布线结果从 +0.188 ns 掉到 −0.111 ns，**净损失，已回退**。这条说明"拆拍"不总等于更好时序。

## 7. 怎么验证

**仿真**（`tests/sim`）：

```bash
python3 tests/sim/run.py tb_bmp_blur_fill tb_bmp_blur_fill_frame
```

- `tb_bmp_blur_fill`：只测背景引擎——crop 边界、桶平均、模糊 9 抽头、采样坐标钳位；
- `tb_bmp_blur_fill_frame`：整帧比对，验证"矩形内是源图、矩形外是模糊底、两者边界不串"。

**板上**：烧 `暂存/教程图_20261027_merged/bmp_scaling_test`（第 2 页是 640×640 正方形），翻到第 2 页看两侧——应当是山水景/CV 卡的模糊压暗版本，不是纯色竖条。

**几何自检**：改 crop/采样公式后，先跑 `project/tools/scaler_golden_model.py` 算 PSNR，
和 RTL 的最近邻结果对比；再看 `tests/sim` 的两个 blur 用例。板级只需在最后确认一次——
非 4:3 图每改一次都上板，成本比仿真高一个数量级。

## 8. 与"高质量缩放"的关系（避免误写）

| 部位 | 现状 | 说明 |
|---|---|---|
| 前景缩放 | **最近邻** | `src_x = x·src_w/fit_w`，零插值 |
| 补边背景 | 面积平均 + 3×3 盒式 ×3 + 双线性 | 本文件描述的对象 |
| 面积平均/双线性**前景** | **未落地** | Python 金标准已验证（缩小 45.22 dB、放大 38.12 dB），RTL 仍是最近邻；原因是需要重构摄取状态机的纵向级（行缓存 + 滤波状态），不在提交前冒这个险 |

写文档或答辩时说"前景最近邻 + 背景质量优先"是准确的；说"整幅图都做了双线性"会被现场放大画面拆穿。
