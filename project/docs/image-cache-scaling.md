# 四槽全缓存与加载时缩放（2026-10-15）

## 当前实现

主工程 `project/project.al` 已启用四张图片全缓存和加载时缩放。独立例程 5 的 RTL 不随本次改动更新。

支持宽1..2048、高1..1536、正高度（bottom-up）、24位、无压缩 BMP。使用最近邻采样，等比适配并居中到640×480，空白颜色为 RGB(16,32,48)。DIB头40..124字节、`bfOffBits` 指定的像素起点、跨扇区BGR三字节和行尾0..3字节填充均处理。压缩、其他位深、负高度、超限尺寸或长度不足的BMP被拒绝，不会作为有效帧发布。

本次**未实现面积加权平均或双线性插值**。最近邻适配功能已接入真实SDRAM写路径；后续画质升级需要增加滤波行缓存和对应定点金标准，不能直接使用草案中的伪代码。

不同尺寸的预期输出：

| 源图 | 缓存中的内容 | 补边 |
|---|---|---|
| 640×480 | 640×480，逐像素直通 | 无 |
| 320×240 | 放大为640×480 | 无 |
| 1536×1024 | 缩小为640×427 | 上26、下27行 |
| 1280×720 | 缩小为640×360 | 上下各60行 |
| 480×640 | 缩小为360×480 | 左右各140列 |

先按宽高交叉乘积确定受限方向，再用32拍恢复除法计算另一方向的尺寸（四舍五入，最小1像素）。内容像素使用 `floor(x*src_w/fit_w)` / `floor(y*src_h/fit_h)`，由整数余数累加与分拍减法实现，不在像素路径放组合除法器。

## 数据流与缓存契约

```text
SD完整512字节扇区 → 扇区BRAM → BMP字节/行解析 → 源行BRAM
    → 最近邻缩放、重复行、补边 → 可暂停的写FIFO → SDRAM固定帧槽
    → 帧边界发布索引 → 既有HDMI/亮度/对比度/字幕/训练OSD
```

`bmp_read_scaled.v` 消费完当前扇区才申请下一扇区；缩放输出只在 `pixel_ready` 时前进。该信号来自异步写FIFO写侧的full标志。写请求的ACK经过SD域两级同步，等待ACK撤销、FIFO清除结束后才开始生成像素。源行与扇区使用同步读BRAM，不清除整块RAM。

`sd_card_bmp.v` 扫描最多四张图片，然后按编号逐张预载入对应物理槽；`load_seq` 为3位，可以表示终值4。槽位在本次上电期间不再覆写。

| 槽 | SDRAM起始字地址 | 长度（32位字） |
|---|---:|---:|
| 0 | 0 | 307200 |
| 1 | 307200 | 307200 |
| 2 | 614400 | 307200 |
| 3 | 921600 | 307200 |

总计1,228,800个32位字，即4.6875 MiB。缓存的是缩放后输出帧，不是原始大图。

必须同时观察缩放器返回ready和SDRAM的write_finish，才置cache_valid。第一张有效槽完成后立即请求显示，其余槽后台填充；后台加载可以与显示索引的发布并行。用户请求尚未就绪的下一张/上一张时，保留一个请求，目标完成后在帧边界切换。不会累计无限次翻页。

`disp_buf_idx` 在publish至done期间保持不变。`img_idx` 只在读端确认新帧地址已被采用后改变。四张都缓存好后，手动/自动切换不再发起SD读卡或SDRAM写帧。

读FIFO低于一个预取阈值时，`frame_fifo_read.read_urgent` 阻止写端开启下一突发；已开始的突发仍正常完成。这避免小图放大、连续补边时的后台写入饿死显示读取。原有40MHz SDRAM、25MHz像素时钟和HDMI输出分辨率保持不变。

## 使用与板测

先用原来的四张640×480素材验证兼容性，再测试320×240、1536×1024、426×240和480×640的混合素材。用 `project/tools/pack_bmp_images.py` 可以生成按512字节对齐的原始镜像文件；它只新建普通文件，不写SD卡。旧的例程烧卡脚本默认仍要求640×480，不能用其固定尺寸校验判断新播放器是否支持某张图片。

当前仍是原始连续扇区扫描，**不支持FAT32目录或碎片文件**。普通文件复制不会建立受控的原始扇区布局。建议始终放四张符合要求的图片；不足四张时扫描会继续到范围上限，首次显示可能明显延后。

首次读卡和缩放仍然需要时间；全缓存减少的是后续切换等待。实际开机时间还取决于SD初始化、扫描和图片尺寸，不承诺草案中的0.5秒首图/1.2秒全部就绪。四张就绪后，切换只保留按键消抖和帧边界等待。

默认按键演示位流为 `project/build/top/top.bit`；ADC版本为 `project/build/top_adc/top_adc.bit`。本次通过命令行 `build.tcl` 生成，TD GUI旧的best_result目录不代表本次新位流。尚未下载硬件或擦写Flash/SD卡。
