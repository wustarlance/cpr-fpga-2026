## 一、D107：独立 SDRAM 全空间诊断

### 1.1 它是什么

与产品完全解耦的独立测试工程（`top_sdram_diag`），只做两件事：

1. **视频侧**：用 `color_bar` 在视频时钟域直接生成 8 条彩条，经现有 RGB→AXIS、HDMI 核、PHY 输出。**不经过 SD、缩放器、帧 FIFO、SDRAM。**
2. **存储侧**：用真实的 40 MHz / 180° SDRAM 时钟和真实 `sdram` 控制器，对全部 **2,097,152 个 32 位字（8 MiB）** 逐字验证。

它**没有**帧 FIFO、没有 SD 访问、没有读写交织，是刻意构造的最简单访问形式：突发四字对齐、先纯写后纯读、开始后保持连续。

### 1.2 图案序列

每轮先把全空间写一遍，等 100 ms，再**完整读两遍**（中间不重写）。

```
pattern(0, a) = 0x00000000                      全零
pattern(1, a) = 0xFFFFFFFF                      全一
pattern(2, a) = {a, ~a[10:0]} ^ 32'h5A3C96E1    地址相关
pattern(3, a) = ~pattern(2, a)                  地址相关反码
a 为 21 位字地址
```

`pattern(2,·)` 是**单射**的：任意两个不同地址的值必然不同。所以"读回值等于某个 pattern(2,b)"等价于"硬件实际访问了地址 b"。

### 1.3 构建

```
python3 tests/board/sdram/build_diag.py --td .tools/td --stage full
```

- TD **6.2.178840**（SP1）
- **status=passed**，SWNS **+2.696 ns**
- 位流 `project/build/md_112910043419/top_sdram_diag.bit`，629,635 字节，sha256 `788d471b9a73ada0fa1975fa0c3552344c5710832fe53f080084c2d6797f7144`
- 该工程的 `build_diag.py` 会校验 CDC 首级触发器数量（`flags=2 dips=4`）、所有 `check_timing` 项目为 0、并核对 5 个时钟周期

### 1.4 第一次读数（SW1=0，突发 256 字）

数码管布局：`[d107] [S状态] [P图案] [F错误类型] 0`

| 拨码 | 页面 | 读数 |
|---|---|---|
| SW4/SW3 = 00 | 状态字 | **`d107E210`** |
| SW4/SW3 = 01 | 首个错误字地址 | **`00000000`** |
| SW4/SW3 = 10 | 该地址的期望数据 | **`5A3C911E`** |
| SW4/SW3 = 11 | 该地址的实际数据 | **`5A3C991F`** |

状态字解码：`S=E` 数据错误，`P=2` 地址相关图案，`F=1` 数据不符（不是超时）。
图案 0 与 1 **通过**，图案 3 未执行（在图案 2 就失败）。

> 注：第一次抄录期望值时把第三位 `3` 看成了 `E`（记成 `5AEC911E`）。`0x5AEC911E` 在 2²¹ 个地址里**穷举不存在**对应的 `pattern(2,·)`，因此必然是读数错误；复核后确认为 `5A3C911E`。

### 1.5 数据解码

```
pattern(2, 0) = 0x5A3C911E     地址 0 应该有的值
pattern(2, 1) = 0x5A3C991F     地址 1 应该有的值
实际读到       = 0x5A3C991F     ← 等于 pattern(2,1)
```

**结论：RTL 要求访问地址 0，SDRAM 返回的是地址 1 的内容。**

### 1.6 第二次读数（增强版 BIST：逐字计数 + 末错地址）

为区分"整体偏移一个字"与"地址位混叠"（二者首个错误三元组完全相同），BIST 改为**记录首个错误后不再停机**，继续扫完整个图案，并新增四个量。SW2=1 切换显示页。

SW1=0（突发 256）：

| 拨码 | 内容 | 读数 | 换算 |
|---|---|---|---|
| SW4/SW3 = 00 | `head_map`（前 32 字对错位图） | **`00000000`** | 前 32 字全错 |
| SW4/SW3 = 01 | 图案 2 第一遍不符字数 | **`001FE000`** | 2,088,960 |
| SW4/SW3 = 10 | 图案 2 第二遍不符字数 | **`001FE000`** | 2,088,960（与第一遍**逐位相同**） |
| SW4/SW3 = 11 | 最后一个不符字地址 | **`001FFFFE`** | 字 `0x1FFFFF` 是对的 |

SW1=1（突发 128，按 KEY1 复位重跑）：

| 页面 | 读数 | 换算 |
|---|---|---|
| SW4/SW3 = 01 | **`001FC000`** | 2,080,768 |

### 1.7 规律推导

```
总字数                    2,097,152 = 2^21
突发 256 → 正确字数       8,192  = 2^21 / 256   → 不符 0x1FE000   ✓ 实测
突发 128 → 正确字数      16,384  = 2^21 / 128   → 不符 0x1FC000   ✓ 实测
```

两个不同的突发长度、两次独立测量、两个精确整数关系，同一个公式无须调参：

> **在一个 N 字的突发里，第 k 个字（k = 1…N−1）带回的是第 k+1 个地址的数据；只有第 N 个（末字）带回自己的数据。**
> 即每个突发错 N−1 个、对 1 个，且对的那个永远在突发末尾。

三条独立佐证：

1. `head_map` 全 0 是这条规律的**必然结果**——0~31 里没有一个是突发末字。
2. 末错地址 `0x1FFFFE`：`0x1FFFFF mod 256 = 255`（突发末字，对），`0x1FFFFE mod 256 = 254`（不是，错）。
3. 第一遍与第二遍的不符字数**逐位相同** ⇒ 确定性缺陷，不是随机位错误。

### 1.8 排除的假设

| 假设 | 排除依据 |
|---|---|
| 刷新不足 / 保持力不足 | 两遍读回完全相同；若是保持力问题第二遍必然更差 |
| 时序裕量 / 采样相位临界 | 同上，且 SWNS +2.696 ns |
| 随机位错误 | 同上，且错误位置服从突发边界规律 |
| 数据线/位宽/字节掩码 | 图案 0 与图案 1 全空间通过；`App_wr_dm` 恒 0 |
| 与产品仲裁、帧 FIFO、读写交织有关 | 该工程里**没有**这些东西，故障照样出现 |

### 1.9 同一工程给出的第二个结论：视频链路干净

彩条由视频时钟直接生成，失败时叠加红色调 `{r|8'h80, g>>2, b>>2}`。8 条彩条按 `WHITE/YELLOW/CYAN/GREEN/MAGENTA/RED/BLUE/BLACK` 顺序，套色后的预期颜色为

```
粉红 / 橙 / 灰藕 / 橄榄暗黄 / 亮粉 / 红 / 暗紫 / 暗红
```

板上实测**八条、顺序、颜色、色调全部吻合**，且彩条上**没有横线**。

⇒ 视频时序、TMDS 编码、PHY、HDMI 链路正常；`fail_sync` 从 40 MHz SDRAM 域正确跨到 25 MHz 视频域；**横线不出在 HDMI 输出级**。

### 1.10 D107 小结

1. **存储阵列在最简单的访问形式下就读错**：每突发只有一个字对，其余带回邻居地址的数据。
2. 这与队员早先"第 512 个像素重复第 511 个"的症状属**同一类缺陷**（突发边界上的数据与有效标志错开）。
3. 产品里 **1 个 32 位字 = 1 个像素**（`video_read_data[31:8]` 即 RGB，四槽间距 307,200 = 640×480），因此该偏移表现为**整幅图平移 1 像素**，视觉上几乎不可见；它**不是**白线横线的成因。
4. 白线横线另需定位，见下一节。

## 二、紧接着 D107 的产品侧写通路测试

### 2.1 目的

D107 已证明存储侧底层读回存在系统性偏移，但它不覆盖产品的写通路。紧接着做的这一轮只回答一个问题：**写进帧缓冲的像素里，有没有被测状态机伪造出来的？**

### 2.2 新增的两个只读仪表

`project/vendor/SD/frame_read_write.v`：

```verilog
wire write_fifo_empty;   // 接出 write_buf 的 empty_flag（原来悬空）
wire read_fifo_empty;    // 接出 read_buf 的 empty_flag（原来悬空）

always @(posedge mem_clk or posedge rst)
    if (rst) write_empty_reads <= 0;
    else if (App_wr_en && write_fifo_empty && write_empty_reads != 32'hffffffff)
        write_empty_reads <= write_empty_reads + 1;      // 从空 FIFO 取出的字数
```

`project/rtl/top_tf_hdmi_audio.v`：

```verilog
always @(posedge sd_card_clk or posedge rst_sd)
    white_hit_sd <= sd_card_write_en && (sd_card_write_data[31:8] == 24'hffffff);

// 每 65536 个 sd_card_clk（约 0.66 ms）发布一次，toggle 握手跨到 clk 域
```

数码管左起第 4~7 位显示该计数值（4 位十六进制）。

### 2.3 仿真先行验证

`tests/sim/tb/tb_frame_write_underrun.v`（已注册，全量回归通过）：

- 用**真实 RTL**（`frame_read_write` + 两个真实异步 FIFO）
- 生产者故意难缠：**30% 随机断流** + 每 200 像素**停 400 拍**
- 在 `mem_clk` 域逐字断言：写进 SDRAM 的每个字必须**正好等于生产者刚提供的那个像素**，顺序不能乱、不能重复、不能跳
- 同时监视 `write_buf.empty_flag`：`App_wr_en` 拉高时 FIFO 为空即计数

结果：`640/640` 像素精确，**0 次空读**。

### 2.4 板上读数一：空读计数

位流 `project/build/top/top.bit`（20:19 构建，仪表为 `write_empty_reads`）：

| 页面 | 数码管 4~7 位 | 含义 |
|---|---|---|
| 任意 | **`0000`** | 写状态机从未从空 FIFO 取过数 |

⇒ **写状态机（FIFO → SDRAM）没有伪造任何像素。** 这条由仿真与板上共同确认。

补充的代码事实：两个异步 FIFO **内部自我保护**，空读不会推进指针也不会破坏 RAM 输出：

```verilog
assign rd_en_s = ((!empty_flag) & re);   // afifo_32_16_256.v:110
.ceb((SHOW_AHEAD_EN | rd_en_s))          // :240
```

所以"`empty_flag` 悬空"只是代码异味，不是缺陷——这一点在排查中曾被误判，此处更正。

### 2.5 板上读数二：上游纯白像素数

位流（21:24 构建，仪表改为统计 `sd_card_write_data[31:8] == 24'hffffff`）。

### 2.7 与本轮仪表相关的代码事实

排查中确认的三条（与仪表读数互相独立）：

1. **亮度 3 / 对比 2 在代码里是精确恒等变换**
   - `brightness_rgb.v`：`level=3` → `default: scale_channel = value`（100% 直通）
   - `contrast_rgb.v`：`level=2` → 增益 4 → `t = ((x−128)·4) >>> 2 + 128 = x`
   ⇒ 底图原样上屏，屏上白色 = 帧缓冲里的白色。

2. **中文文字层不画正文**
   `cpr_text_zh.v` 在教学浏览模式下只有两段绘制：
   ```verilog
   else if(x_next>=16 && x_next<624 && y<16) ...                 // 页眉
   else if(x_next>=16 && x_next<... && y>=448 && y<464) ...      // 字幕滚动
   ```
   正文（y = 16…447）完全不参与；字形 ROM 的 `default: bitmap = 256'd0`（无效字符全零，不会发白）。

3. **合成器在正文区没有其他白色来源**
   `cpr_overlay.v` 里全部 `24'hffffff` 仅出现在：训练模式节拍条（x∈[624,632) 的 8 像素竖条）、以及 `CHINESE_UI=0` 才生效的 ASCII 字幕/文字（默认 `UI_LANGUAGE_ZH=1`，这两路是死代码）。

### 2.8 本轮结论

1. 写通路不伪造像素（板 `0000` + 仿真 640/640 逐字精确）。
2. 底图在白线与亮度/对比之间没有任何变换（两者恒等）。
3. 合成器与文字层在正文区无法产生白。
4. ⇒ 当时据此判断「白只能来自 `rgb`（底图侧），即帧缓冲内容」。**这个判断依赖 `049F` 这唯一一个读数，而该仪表存在下述已知缺陷，因此尚未被可靠确立。**

## 三、已知局限（读本文时必须知道的两点）

### 3.1 `049F` 那个仪表会少算

21:24 那版跨时钟域发布用的是"计数一变就翻 toggle"：

```verilog
else if (empty_reads_now != empty_reads_pub) begin
    empty_reads_pub <= empty_reads_now;
    empty_tog       <= ~empty_tog;      // 装载期间接近 100 MHz
end
```

装载期间白像素计数几乎每拍都变，toggle 以接近 100 MHz 翻转，而消费端 `clk` 只有 50 MHz，**绝大多数边沿会被漏掉，快照最终冻结在装载中途的某个值**——四页读数据完全相同正符合这个症状。

⇒ **`049F` 可能是中途值而非总数**，第 2.8 节第 4 点不能当作已确立的结论。

**已修的版本**（RTL 中已存在，可直接复用）：改为固定节拍发布，每 65,536 个 `sd_card_clk`（约 0.66 ms）发布一次，边沿间隔远大于 `clk` 域采样能力，快照会持续跟随最新值。

### 3.2 D107 的读数不受 3.1 影响

D107 的全部结论来自**单次烧写后的静态寄存器值**（`status/phase/fault/地址/期望/实际/计数/末错地址`），这些量在测试结束后保持不变，没有任何跨时钟域持续计数的环节；`0000` 那个写侧空读计数在正常装载中恒为 0，属慢变量，也不受该缺陷影响。

因此：**D107 的一字偏移结论与"写状态机不伪造像素"这两条是稳的；"帧缓冲里没有白线"这一条不稳。**

## 四、给接手者的建议（基于本文范围）

1. **不要重复 D107 的结论推导**：逐突发的数据偏移已经定量确认（两种突发长度、四个独立读数互为佐证），可以直接作为既成事实使用。
2. **先修 `049F` 那类仪表再谈白线位置**：跨时钟域发布多位计数必须用固定节拍或请求/应答握手，不能用"变化即翻 toggle"。正确的实现已在 `top_tf_hdmi_audio.v` 中。
3. **`write_empty_reads` 恒 0 与 FIFO 内部 `rd_en_s = !empty_flag & re` 这两条一起说明**：FIFO 层不是白线的来源，往上找（SD 字节流、行缓冲、缩放器）。
4. **动手前先看时序余量**：本设计 `top` 的建立余量只有约 0.1 ns 量级。任何新增逻辑都可能把网表推到临界（曾有某次新增诊断后 SWNS 只剩 +0.008 ns，板上表现为动态花屏）。加仪表前先确认 `report_timing_status` 的 SWNS/HWNS 仍明显为正。
5. **仿真覆盖要包含扫描阶段**：`bmp_read_scaled` 除了图像加载还有 `scan` 阶段（按 `BM` 签名扫扇区），任何对 `SECTOR` 状态机的改动都必须同时覆盖扫描路径，否则仿真会漏。
