## 0. 一句话实现           

`heartbeat_synth.v` 用一个输出是 24 bit 左对齐单声道（左右同值），
只占 **161 LUT + 75 寄存器 + 1 个 DSP + 0 BRAM**（单独综合探针实测，同口径改造前是
144 LUT / 75 寄存器 —— 这次加"退出收尾"只花了 17 个 LUT，0 个 DSP、0 个寄存器）。

| 文件 | 作用 |
|---|---|

| `project/rtl/audio/wav_audio_path.v` §5.5 | 音频口的 2:1 多路选择器（训练 → 心跳，否则 → 该页 WAV）；选择端两级同步；`sel = 训练 \| O_busy` |
| `project/rtl/audio/wav_audio_sd_top.v` | 透传 `I_heart_en`（就是那条 mux 的 `sel`） |

## 1. 规格 → 参数映射

你给的原始规格，和 RTL 参数的对应关系（**算式都在综合期折成常量，运行时不做乘除**）：

| 规格项 | 你给的值 | RTL 参数 | 参数值 | 折算后实测 |
|---|---|---|---|---|
| 第 1 声音高 | 150 Hz | `FREQ_FIRST` | 150 | 149.9981 Hz（−0.0013%） |
| 第 2 声音高 | 190 Hz | `FREQ_SECOND` | 190 | 189.9979 Hz（−0.0011%） |
| 第 1 声时长 | 25 ms | `DUR_FIRST_MS` | 25 | 1200 帧 = 25.000 ms |
| 第 2 声时长 | 35 ms | `DUR_SECOND_MS` | 35 | 1680 帧 = 35.000 ms |
| 两声起始间隔 | 70 ms | `GAP_MS` | 70 | 3360 帧 = 70.000 ms |
| 第 1 声相对幅度 | 100% | `AMP_FIRST` | 32767 | 8355584/8388608 = 99.6% FS |
| 第 2 声相对幅度 | 65% | `AMP_SECOND` | 21300 | 5431296/8355584 = 65.0% |
| 拍周期 | 110 BPM | `BPM` | 110 | 26182 帧 = 545.458 ms（标称 545.455） |
| 波形 | 衰减敲击音 | `DECAY_SHIFT_1/2` | 8 / 8 | τ = 5.33 ms，段落末残值 1.25% / 0.18% |

采样率侧：`MCLK_HZ = 12 288 000` → `FS = (MCLK+128)/256 = 48 000`。
工程实际 PLL 输出是 12.295082 MHz（`fs ≈ 48 027`），这里按参数取 48 000 计算，
两者相差 0.06%，听感上完全不可辨（`pcm_player` 用同一套公式，所以帧节拍是**同一个**）。

## 2. 信号链：它挂在哪一级、为什么挂在那

```
 SD 卡 ──► wav_reader ──► pcm_fifo ──► pcm_player ──┐
           (SD 域)       (跨到 MCLK)   (MCLK 域)    │  WAV 24 bit L/R
                                                     ▼
                                    ┌───────────────────────────────┐
   heartbeat_synth ──── 心跳 L/R ──►│  2:1 mux                       │──► toggle 跨域 ──► HDMI
   (MCLK 域, 吃同一帧节拍)    │     │  sel = 训练 | O_busy           │      (像素域, 48 kHz 帧节拍)
            └── O_busy ───────┘     │  0 → WAV, 1 → 心跳             │
                                    └───────────────────────────────┘
```

训练期间 `I_play` 被顶层压 0：`pcm_player` 不消耗 FIFO、SD 侧把 FIFO 填满就停住，
所以整个训练过程**一个扇区读都不发**（退出后断点续播）。

三条设计约束，决定了它必须放在这里：

1. **必须吃 `pcm_frame_tick` 的帧节拍，不能自己分频。**
   两路各跑各的分频器，标称都是 48 kHz，实际一个 48 000.0、一个 48 000.5，切换音源那一帧就会
   多/少一个样本 —— 波形上是一个台阶，听感是"咔"。放在 `pcm_player` 之后共用 `W_frame_stb`，
   两路天然同拍，切换只是"换数据源"。
2. **必须在 ACR 计数之后、跨域之前。**
   ACR（N/CTS）是数 `O_audio_valid` 的。`pcm_player` 无论播/停每帧都发一个 valid，
   所以训练模式即使完全不读卡，HDMI 音频流也不会断（播放器/电视不会去重新握手）。
3. **不能放在 SD 域。** 心跳和卡、和扇区、和 FAT 都没有关系；放进 SD 域只会让它跟着
   卡初始化、仲裁、掉卡一起受影响，而它的唯一时钟需求就是音频采样节拍。

## 3. 常数推导（全部在综合期算完）

```verilog
localparam integer FS        = (MCLK_HZ + 128) / 256;              // 48000
localparam integer PERIOD_I  = (FS * 60 + BPM / 2) / BPM;          // 26182   一拍多少帧
localparam integer DUR1_I    = (FS * DUR_FIRST_MS  + 500) / 1000;  // 1200
localparam integer DUR2_I    = (FS * DUR_SECOND_MS + 500) / 1000;  // 1680
localparam integer GAP_I     = (FS * GAP_MS        + 500) / 1000;  // 3360
localparam [23:0] INC1 = (FREQ_FIRST  * 48'd16_777_216) / FS;      // 52428 相位增量
localparam [23:0] INC2 = (FREQ_SECOND * 48'd16_777_216) / FS;      // 66409
localparam [15:0] HOLD1 = (48'd4_194_304 / INC1);                  // 80    满幅保持到首峰
localparam [15:0] HOLD2 = (48'd4_194_304 / INC2);                   // 63
```

| 量 | 算式 | 值 | 说明 |
|---|---|---|---|
| `INC1` | 150 × 2²⁴ / 48000 | 52428 | 相位是 24 bit 归一化到 2π；`2²⁴/48000` 是"每帧的相位步长基数" |
| `INC2` | 190 × 2²⁴ / 48000 | 66409 | 同上 |
| 实际频率 | `INC × FS / 2²⁴` | 149.9981 / 189.9979 Hz | 量化误差 = 1 LSB 相位 ≈ 0.003 Hz，可忽略 |
| `HOLD1` | 2²² / INC1 = FS/(4×150) | 80 帧 | 正弦第一个波峰在 t = 1/(4f) = 1.667 ms |
| `HOLD2` | 2²² / INC2 = FS/(4×190) | 63 帧 | 1.312 ms |
| `PERIOD` | (48000×60 + 55)/110 | 26182 帧 | 545.458 ms；真值 545.4545 ms，差 1 帧/拍（110 拍累计 0.4 ms） |

> **位宽陷阱（2026-10-26 修）**：`INC = f × 2²⁴ / FS` 里的乘法原来是
> `f * (1 << 24)`，两个操作数都是 32 bit 有符号，结果也就在 32 bit 里算。上限
> 2³¹−1 对应 **127.99 Hz** —— 75/95 Hz 时代一直安全，频率提到 150/190 Hz 就溢出：
> 150×2²⁴ = 2.52e9 变负，除完 FS 得 −37028，相位累加器等于每帧**倒着**走，
> 表指针从 63 往下数，听感是音高跑偏并随包络下滑（仿真里第一次见到的是峰值只有
> 68.7%，因为正弦根本没走到 ±90°）。改成 `f * 48'd16_777_216` 后乘法在 48 bit
> 里做，上限 ≈128 kHz，怎么调频都不会再溢出。`HOLD` 的 `2²² / INC` 同理写成
> `48'd4_194_304 / INC`。

`MCLK/256` 这个关系来自 `pcm_player`：MCLK 是 `fs × 256`（12.288 MHz / 256 = 48 kHz），
所以"帧"就是"每 256 个 MCLK 一个样本"。`pcm_frame_tick` 里那个 `+128` 是四舍五入，
保证 `MCLK/256` 落在整数上时不会因为截断少 1 Hz。

## 4. 拍内时间线：一个 16 bit 计数器决定一切

只有一个状态量 `S_idx`（拍内序号 0 … PERIOD−1），每帧 +1，到 PERIOD 归零。
所有"什么时候开始哪一声"都是对 `S_idx` 的等值比较：

```
S_idx:  0          1200        3360            5040                 26181 0
        │            │           │               │                      │ │
第1声   ██████████████                                                  ████
        └ 25 ms (1200 帧) ┘
第2声                 ████████████████████                             ████
                      └ 70 ms 处起, 35 ms (1680 帧) ┘
静音                                          └────── 21142 帧 = 440 ms ─────┘
        └──────────────── 一拍 26182 帧 = 545.5 ms = 110 BPM ────────────────┘
```

| `S_idx` 条件 | 动作 | 说明 |
|---|---|---|
| `== 0` | `env←AMP1, phase←0, inc←INC1, shift←8, hold←HOLD1, dur←DUR1, active←1` | 每拍从"咚"重新开始 |
| `== GAP`(3360) | `env←AMP2, phase←0, inc←INC2, shift←8, hold←HOLD2, dur←DUR2, active←1` | 第 1 声 25 ms 早已结束，两者不重叠 |
| `active` | `phase += inc`；`hold≠0 ? hold−− : env −= env>>shift`；`dur−−`，到 1 时 `active←0` | 一个 always 块，无分支嵌套 |
| 其它 | 什么都不做（`active=0` 输出恒 0） | 静音段不消耗任何运算 |

用"等值比较 + 一个计数器"，而不是三个状态机拼起来，好处是：改 `GAP_MS` 不用动任何逻辑；
`S_idx == 0` 和 `S_idx == GAP` 是同一条时间轴上的两个刻度，不会出现"第 1 声还没结束第 2 声就起"
（25 ms ≪ 70 ms，结构上不可能重叠）。

## 5. 包络：为什么先"满幅保持"再衰减

这是整个设计里最容易被做错、也最影响"幅度是否真的等于标注值"的一步。

朴素做法是从第 0 个样本就开始 `env -= env>>8`。问题是正弦从 0 起振，要走到波峰需要 1/(4f)：

| | 到波峰要多久 | 若从 0 就开始衰减，波峰时包络只剩 |
|---|---|---|
| 150 Hz | 80 帧 = 1.667 ms | `(255/256)^80 = 73%` |
| 190 Hz | 63 帧 = 1.312 ms | `(255/256)^63 = 78%` |

于是"幅度 100%"实际听起来只有一半，而且**两段的跌落比例还不一样**，65% 的比例会被吃掉
（0.61/0.53 = 1.15 倍偏差）。所以实现里加了 `S_hold`：先保持 `AMP` 到波峰，之后才开始衰减：

```verilog
if (S_hold != 16'd0) S_hold <= S_hold - 16'd1;
else                 S_env  <= S_env - (S_env >> S_shift);   // 一阶 IIR，极点 255/256
```

衰减参数 `SHIFT=8` 的含义：每帧乘 `255/256`，即 τ = 256 帧 = 5.33 ms，5τ ≈ 26.7 ms。
段落末的残值（只算保持之后的样本数）：

| 段落 | 保持 | 实际衰减帧数 | 末帧包络 | 听感 |
|---|---|---|---|---|
| 第 1 声 25 ms | 80 | 1120 | 1.25% | 硬切在 −38 dB，听不出咔哒 |
| 第 2 声 35 ms | 63 | 1617 | 0.18% | 硬切在 −55 dB，更干净 |

> 为什么不加"attack 斜坡"？相位每次从 0 起，`sin(0)=0`，音头本身就从零开始，不需要额外包络。
> 这一条省掉了一整套起振状态机。

## 6. 正弦表：24 bit 相位 + 64 点查表

```verilog
case (S_phase[23:18])    // 取相位高 6 bit → 0..63
  6'd0 : S_sin = 16'sd     0;      // 正负全表，Q15 有符号
  ...
  6'd16: S_sin = 16'sd 32767;      // 90°
  ...
  6'd48: S_sin = -16'sd 32767;     // 270°
```

- 全表（不靠对称折叠）：避免"象限换算"那几级加减，综合成 64×16 分布式 ROM，**不占 BRAM**。
- 相位累加器 24 bit：`INC = f×2²⁴/FS`，频率分辨率 `FS/2²⁴ = 0.0029 Hz`。
- 表值 = `round(32767·sin(2πk/64))`，`k=16` 处正好 32767（满量程）。

**这里有一个必须知道的量化特性**：64 点表 + 零阶保持，等效"每 5 帧才换一次表值"（150 Hz 时
`INC/2¹⁸ = 0.2`），也就是输出是一条 64 级阶梯正弦：

| 项 | 150 Hz | 190 Hz |
|---|---|---|
| 每周期帧数 | 320 | 252.6 |
| 表步进 | 5.625°（最大跳变 3212 LSB） | 同 |
| 阶梯更新率 | 64×150 = 9.6 kHz | 64×190 = 12.16 kHz |
| 最大量化台阶 | 3212/32767 = 10%（≈ −20 dB） | 同 |

听感上是一层很轻的"沙沙/颗粒"，在短促的衰减音上不明显，但**严格说不是纯净正弦**。
如果哪天要求"录音级"，最省资源的改法是**线性插值**（`s0 + (s1−s0)×phase[17:0]>>18`）：
多 1 个 DSP、约 50 个 LUT，失真从 −20 dB 掉到 −58 dB 量级；其次是换成 256 点表（约 +300 LUT，
在 82% slice 的现状下不建议）。当前不做，是"资源/收益"的取舍，不是遗漏。

## 7. 定标与位宽：一个 DSP 怎么算完

```
S_sin : signed 16 bit  Q15（±32767）
S_env : unsigned 16 bit Q15（0..32767，按有符号看也安全）
prod  = S_sin × S_env        → signed 32 bit，Q30
W_smp = prod[30:15]          → signed 16 bit，回到 Q15
O_l   = {W_smp, 8'd0}        → signed 24 bit，左对齐
```

- 取 `[30:15]` 而不是 `[31:16]`：Q15×Q15 的结果是 Q30，右移 15 位回到 Q15（若按 Q31 理解再移 16 会
  整体小 3 dB）。
- 左对齐 8 bit：和 `wav_reader` 把 16/24 bit 统一成 24 bit 左对齐的做法一致，混音时不需要再对齐。
- `W_env_s` 声明成 signed：包络最大 32767 < 2¹⁵，当成有符号数不会被解释成负数，少一级位扩展。
- 综合结果：**1 个 DSP**（16×16 乘法），ROM 走 LUT。

## 8. 寄存器 / 状态一览

| 名字 | 宽度 | 含义 | 复位值 |
|---|---|---|---|
| `S_idx` | 16 | 拍内序号 0…26181 | 0 |
| `S_phase` | 24 | 相位累加器 | 0 |
| `S_env` | 16 | 包络 Q15 | 0 |
| `S_dur` | 16 | 当前这一声剩余帧数 | 0 |
| `S_hold` | 16 | 距开始衰减还剩多少帧 | 0 |
| `S_inc` | 24 | 当前这一声的相位增量（INC1/INC2） | INC1 |
| `S_shift` | 4 | 当前这一声的衰减移位 | 8 |
| `S_active` | 1 | 正在发声（含退出收尾） | 0 |
| `O_busy` | 1 | = `S_active`，告诉下游选择器"别切源" | 0 |
| `O_left/O_right` | 24 | 输出（`S_active=0` 时恒 0） | 0 |

`I_enable` 拉低时：
- 若此刻**在发声**（`S_active=1`）→ 先收尾（包络每帧剩 75%，约 32 帧），期间 `O_busy` 保持 1、
  输出还在正常出样本；收完才清零并把 `S_idx` 压回 0。
- 若已经静音 → 直接全部清零回拍首（每拍都跑，`S_idx` 一直被压在 0）。

所以"下次进训练第一帧就是咚"这条不变：收尾结束那帧顺手把 `S_idx` 清 0，哪怕下一拍立刻
重新使能也是从拍首开始。

## 9. 与 WAV 的关系：音频口一条 2:1 多路选择器

`wav_audio_path.v` §5.5 整段就是下面这几行（2026-10-25 删掉混音和淡化，2026-10-26 补了同步与收尾）：

```verilog
// 选择端跨域：video_clk → MCLK，各两级同步（电平量，切模式后保持在毫秒级）
S_heart_sync <= {S_heart_sync[0], I_heart_en};   →  W_heart_m
S_mute_sync  <= {S_mute_sync[0],  I_mute};       →  W_mute_m

heartbeat_synth u_heartbeat (.I_enable (W_heart_m), .O_busy (W_hb_busy), ...);

W_wav = W_mute_m ? 24'sd0 : W_pcm;               // SW4 暂停闸（与选择器无关）

W_sel = W_heart_m | W_hb_busy;                   // 训练中，或心跳还在收尾 → 选心跳
W_out = W_sel ? W_hb : W_wav;                    // ← 就是它：2:1 mux
```

| `W_sel` | 音频口出什么 | 场景 |
|---|---|---|
| 0 | 该页 WAV（`pcm_player` 输出，逐位相等） | 教学 / 展播 |
| 1 | `heartbeat_synth` 的"咚—哒" | 训练模式（该页音频被**根本不选**） |

**为什么"屏蔽该页音频"用 mux 就够了**：需求是"训练时只播 HEART_BEAT"，二选一的语义正好
等于"另一路完全不参与"，不需要先把那一路压成 0 再相加 —— 相加才是多此一举，还带来削顶、
音量配平、混音开关这些额外问题。

**为什么必须在 `pcm_player` 之后**：心跳和 WAV 共用 `W_frame_stb`（48 kHz 帧节拍）。两路各自
分频的话标称同频、实际差一点点，切换那一帧就会多/少一个样本，波形上是一个台阶，听感是"咔"。

**为什么必须在跨域（toggle 握手）之前**：跨域之后就是 `audio_arc_calculate` 数
`O_audio_valid` 的地方。`pcm_player` 无论播/停每帧都发一个 valid，所以训练模式即使完全不读卡，
ACR 计数也不断，HDMI 音频流对播放器/电视完全透明 —— 不会因为"换了个音源"重新握手。

### 9.1 选择端为什么必须同步（2026-10-26）

`I_heart_en` / `I_mute` 都是从 `video_clk`（25.175 MHz）过来的电平，选择器跑在 MCLK（12.288 MHz）
上。原来直接拿它们当 `sel`：单 bit 被判成不同值的机会很小，但一旦发生，选择器的左右两路就会
**各选各的**（一帧 L 是心跳、R 是音乐，听感是一次爆响）；而且 `I_mute` 同时喂 ~120 个 FF 的
状态和数据闸，破坏的是 `project_cdc.sdc` 里"跨域只有 FIFO + 两级同步"这条举证。

现在两级同步（`S_heart_sync` / `S_mute_sync`，2 个 FF × 2 位），同步后的 `W_heart_m` 同时驱动
选择器和心跳模块，`W_mute_m` 驱动 WAV 闸。代价 4 个 FF。它们是**电平**不是单拍脉冲，
所以不需要 toggle 握手（`I_stop` 那种单拍才需要）。

### 9.2 退出训练为什么不能立刻切（2026-10-26）

原来的写法是 `I_enable` 一落，`heartbeat_synth` 就地归零、选择器下一帧切回 WAV。问题在于：
退出瞬间心跳可能正响在"咚"的峰上（±0x7F7F00），这一刀就是一次**满量程阶跃**，必然是明显的
"啪"。按 25 ms + 35 ms 脉冲 / 545 ms 周期算，落在脉冲内的概率约 **11%**，属于"偶尔按到
就吓一跳"的偶发故障，很难复现、更该在源头掐掉。

改法（模块内 + 模块间各一半）：

1. `heartbeat_synth` 在 `I_enable` 落下时不再立刻归零，而是继续出正弦、把包络按
   `env -= env>>2` 压下去（每帧剩 75%，32767 → <4 约 32 帧 = **0.67 ms**），期间 `O_busy`
   保持 1；
2. 选择器 `sel = W_heart_m | O_busy`，等 `O_busy` 落下才切回 WAV。切点上心跳侧已经**恒为 0**，
   最后一个非零样本 ≤ 3 LSB（−80 dBFS）。

**还剩什么**：切回 WAV 那一帧，WAV 是"接着播"的，此刻幅度是任意值 B，所以仍有一个
0 → B 的阶跃。它和 SW4 暂停/继续的硬闸同一量级（那个也是直接压 0），不是这次新引入的。
要彻底消掉就得在选择器输出上加**增益斜坡**（1 ms 内 0→1），代价是 2 个 24 bit 乘法器
（+1~2 DSP、+50 LUT 量级）；按"先只考虑功能"的口径，这次没加，`attic/audio-fade/` 里那套
交叉淡化是现成的加强版（+4 DSP）。

## 12. 调参手册

| 想改什么 | 改哪里 | 注意 |
|---|---|---|
| 更慢/更快的拍 | `BPM` | `S_idx` 是 16 bit，`PERIOD ≤ 65535` → BPM 不能低于 44（48 kHz 下） |
| 声音高低 | `FREQ_FIRST/SECOND` | 改了会自动重算 `INC` 和 `HOLD`（`HOLD` 依赖 `INC`，两者必须同源） |
| 两声长短 | `DUR_FIRST_MS/DUR_SECOND_MS` | 必须 `DUR < GAP`（第 1 声）否则"咚"会被"哒"截断 |
| 第 2 声轻一点 | `AMP_SECOND` | 32767×0.65 = 21300 |
| 更"闷"/更"脆" | `DECAY_SHIFT_*` | 值小=衰减慢（更闷），4→τ=0.83 ms 很脆；≤3 时末帧还有 5% 以上，硬切可能听出咔哒 |
| 退出收尾更快/更慢 | `heartbeat_synth` 收尾分支里的 `S_env >> 2` | 现在每帧剩 75%（约 0.67 ms）；改 `>>1` 约 0.3 ms，改 `>>3` 约 1.1 ms。太长会让人觉得"退出训练后还有半声余音" |
| 想消掉切换时的咔哒 | 在选择器输出上加 1 ms 增益斜坡（2 个 24 bit 乘法器，+1~2 DSP） | 这是唯一能同时管住"切回 WAV 那一帧"的办法；现成的加强版是 `attic/audio-fade/audio_crossfade.v`（+4 DSP），接法见那个目录的 README |
| 训练时想听背景乐 | 把 mux 改成相加（`sat_add(W_wav, W_hb)`） | 这就是已删除的混音方案，`attic/audio-fade/heart_mix_stage.v` 是现成实现 |

## 13. 与被删掉的"卡上第 5 段"对比

> 2026-10-26 补：LBA 500000 这个位置后来又用上了，但用途完全不同 —— 它是
> `wav_track_select.v` 里的第 5 段 `FREE_SONG`，只在**自动展播**（`app_mode==1`）
> 时被选中，四页轮播共用这一首。它不是心跳，也不会在训练模式里被播放（训练时
> 音频口被 §5.5 的 mux 独占，`I_play` 也被压 0）。下表比较的"卡上第 5 段"指的是
> 当年那套"用录音当心跳"的方案，和现在的 FREE_SONG 无关。

| 维度 | 卡上第 5 段（`HEART_BEAT=500000`，已删除） | 片内合成（现方案） |
|---|---|---|
| 依赖 | 卡必须插、必须是烧好的那份镜像、扇区不能被动过 | 无（卡没插也能响） |
| 占 SPI 总线 | 是（每 5.3 ms 一个扇区，和 BMP 抢仲裁） | 否（一点不占） |
| 改音色 | 重新导出 WAV + 烧卡 + 换扇区常量 | 改一个参数，重新出 bit |
| 循环 | 靠 `wav_reader` 的 loop（要等文件尾） | 计数器到 PERIOD 自动重来，无缝 |
| 扇区表 | 多一项（5 选 1，选择口 3 bit） | 回到 4 项、2 bit，和"一页一段"完全对齐 |
| 首帧延迟 | 换曲/换源要等 abort→start 读完头部（10~20 ms 静音） | 0（当拍就有样本） |
| 代码量 | 0（复用 WAV 通路） | 161 LUT + 1 DSP（单独综合实测） |

结论：心跳这种"要一直循环、内容固定"的音，用合成比用录音省总线、省素材流程、还更稳
（现场卡接触不良时训练模式仍然有心跳）。所以这次把两条路收成一条。
