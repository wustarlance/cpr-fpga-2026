# SDRAM 转发时钟修正（2026-10-28）

本轮继续使用 HX4S20C V1.0 / EG4S20BG256 和本机官方资料包中的 TD 6.2.168116。基线为 main `9ef00bd345b0c2a957b6e27939ffe00edcd08cc8` 加 ROM/调度优化与内部 PLL 反馈两个提交。这里记录实际的时钟结构、约束和验证范围，不以生成位流代替严格验收。

## 电路和约束

原实现将 PLL C2 直接接到 SDRAM 时钟输出 PAD，TD 报 PHY-5079 本地时钟布线。本轮使用该器件实际支持的 `EG_LOGIC_ODDR`：上升沿输出1、下降沿输出0，由 I/O 双沿寄存器转发连续时钟。`FORWARD_CLOCK_ODDR` 默认0，保留参考包装的默认行为；主工程显式设为1。ODDR 的复位固定为0，应用复位不会截断 SDRAM 初始化所需的时钟。

仅加入 ODDR 还不够：它增加了输出延迟。系统 PLL 的 C2 保持40 MHz，实际相位从180°提前到135°（3.125 ns）；其他输出频率和相位不变。Verilog、IPC和禁用VHDL的 C2 参数同步为 `DIV=25 / CPHASE=8 / FPHASE=3`，反馈仍为 `NOCOMP / VCO_PHASE_0`。这是一项真实电路相位修改，没有用多周期或假路径放宽 SDRAM DQ。

新增 `constraints/sdram_forward.sdc`，在实际映射的 `U3/sdram_syn_45.opad` 上创建 `sdram_forward_clk`，源为系统 PLL C2，继承25 ns周期及其相位。构建脚本在打包、合法化以后、布局之前持久加载该文件，且检查PAD唯一匹配。GUI工程也登记此文件，仅用于布局布线。先前交互调用 `create_generated_clock` 的实验未在最终时序模型中保留，因此不能作为签核证据。

最小复现中，正确计入 ODDR 后180°配置暴露约−2.12 ns建立违例；135°配置的建立/保持恢复为约+0.80/+0.59 ns。完整产品重新执行 Slow/Fast 检查，不能以最小复现替代产品结果。

## 补充的控制路径修改

首次完整演示构建已消除 PHY-5079，但 ADC 顶层出现−0.331 ns建立违例：背景图平均与边界选择组合成九级逻辑。现将背景图尺寸减一的边界值在原有 CLEAR 阶段寄存，后续平均、滤波、插值共享该边界；没有增加处理阶段或改变像素顺序。

另将仅用于背景图暂存工作单元的 SD 初始化状态寄存一拍，切开 SD 初始化状态到其宽控制锥的长路径。主读取器仍在原始初始化状态失效时立即返回IDLE、撤销请求，背景结果不能发布，重新加载重新初始化任务。功能测试覆盖中断时没有帧发布、随后用不同图像重新加载且逐像素匹配独立参考模型。

## 剩余边界

PHY-7002 是 SDRAM 宏重定位诊断，与 PHY-5079 不同。前移位置约束的读取时点后，最小复现仍出现该诊断，不能靠屏蔽日志或重复换位置宣称解决。严格验收仍为failed：还须处理宏重定位、只读ROM初始化诊断、悬空节点复核（演示3项、ADC 4项）和真实外部接口覆盖（两顶层均26项无输入延迟、29项无输出延迟）。上述物理初始化已核对，但这不会自动豁免其他诊断。建立与保持余量均为正，也不代表所有电压、温度和板级条件已经实测。

本轮临时上板限 JTAG SRAM，不写 Flash 或 TF 卡。已保留操作者确认过的内部PLL反馈位流作为恢复路径。新时钟结构的功能反馈必须关联本次位流，不沿用先前配置的“全部正常”。
