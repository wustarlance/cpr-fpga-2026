基线：`ad41f17721c11d0fdb459a06a418c7c1cd06ea8e`。保留该版本已整合的四槽缓存、缩放、音频、8 位数码管和 LED 功能。

## 频率数字偶尔变成横杠

旧 `rate_display_lut` 只接受 500～600 ms，因而只显示目标速率区间的数字；真实按压偏慢或偏快时，界面显示 `---`。照片中的 1096 ms 属于这一情况，不能据此判断为 HDMI 丢字。

现改为有界的逐拍除法，按 `round(60000 / interval_ms)` 显示最近两次完整按压的频率；1096 ms 显示 055 次/分，750 ms 显示 080，400 ms 显示 150。它与训练核心的慢/合适/快评级分别计算，评级边界不变。

- 保留 8 位 BPM 接口，可显示 1～255 次/分，对应 235～65535 ms。235 ms 经舍入为 255。
- 尚无第二次完整按压、0 间隔、短于 235 ms 的不可表示输入、清场或复位时无有效数字，不伪造测量值。
- 新结果在接收输入后 17 个计算时钟完成；25 MHz 下从采样到结果不超过 18 拍，约 0.72 微秒。计算期间保留上一有效结果，避免周期性清空数字。
- 输入改变时重新计算；输入失效或复位取消进行中的计算。模块新增 `clk/rst_n`，由 `cpr_control` 接到现有同一时钟域。

## 四张教程均有固定横线

原始教程和扇区镜像中不含照片中的横线。实际帧缓存读、写状态机在进入突发时均漏检 `Sdr_init_ref_vld`。官方 APUG011 第 3 节前的用户操作说明要求先等待该刷新信号变低，再启动读写。

已在读、写突发起点及实际请求输出端加入刷新空闲门控，低水位读优先的预告也遵守该条件。仅检查状态入口仍会漏掉“准备请求后、首个寄存请求发出前开始刷新”的临界拍，输出端门控用于阻止这一情况。刷新期间等待，不消耗 FIFO、不推进地址、不假装完成；已接受的命令不撤销，尚未发出的后续命令等待刷新结束。修改不依赖把刷新忙误当成数据有效，也不通过覆盖白色像素来掩盖问题。

新增测试可在旧状态机上复现刷新期间发请求的失败；修复后分别检查读、写互锁、首请求临界拍、互斥、翻转地址和 3840 次请求完整性。该测试证明接口缺陷被修复，不能代替实际 SDRAM/HDMI 电气与时序验收。
