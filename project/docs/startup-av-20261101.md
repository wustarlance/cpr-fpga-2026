# 开机音画顺序与外接 K6 K7 修正

本轮基于 GitHub main `4c35d3777be469da11e3e4987b633259ced4a992`，使用 HX4S20C / EG4S20BG256 与本机 TD 6.2.168116。操作者报告旧版约上电4秒开始音频、5秒出现LOGO、6秒出现教程，图片尺寸为680×480；这些是旧版现场观察，不是本轮仪器测量结果。

## 原因与修改

旧版的 WAV 播放使能上电默认为1，未等待真正显示教程；SDRAM 已有有效页时，LOGO 仍可能因四页预载和最短展示时间遮住该页。仅以“缓存有效”判断音频可播会让声音先于画面。现在等待 LOGO 退出、有效教程帧的 SOF 被 HDMI 核接受，再等该帧结束的场消隐，才允许播报。启动时保留音频样本及 ACR 节奏，但 HDMI 与波形监测共用的最终 PCM 为0；WAV 播放位置不提前消耗，训练心跳也不能穿透 LOGO 静音。

LOGO 仍由 BRAM 位图输出。视频时序、合成流水线与 HDMI 使用独立的 `u_video_release`，在视频 PLL 锁定后同步释放；应用、SD、SDRAM 与音频仍保留原有全部 PLL 锁定及20毫秒资格等待。整条视频流水线持续使用同一套光栅，不在 LOGO 与教程之间切换时序。该独立复位的 ready 为常量1，不属于 `por_ready` 跨域例外的四个 `u_*reset`；没有增加整时钟域假路径。

`splash_boot` 的交棒从组合切换改为场消隐内的 VS 边沿切换，避免同一帧出现半幅LOGO、半幅教程。原3秒最短展示时间和四页预载策略保留：最短展示时间约束的是LOGO何时退出，不会阻止LOGO首次输出。FPGA配置与接收显示器锁定仍影响肉眼可见时间，不能据此宣称冷启动提前了几秒。

按键错误位于顶层重映射。原 `~key_panel_n[5:0]` 把物理 K6 同时接到了应用字幕位；K7 没有进入该链路。现改为 `{~key_panel_n[6], ~key_panel_n[4:0]}`，K1～K5 保持原功能，K6 只送对比度，K7 只送字幕。管脚约束未变：K6 为 K15 / J1-23，K7 为 H15 / J1-25。

## 验证结果

67项产品 RTL 自检与5项运行器检查通过。新增顶层集成测试保留真实顶层、复位、640×480视频时序、LOGO ROM、应用去抖、字幕与对比度逻辑；SDRAM、SD、HDMI PHY 与PCM生成使用明确的边界激励。它验证视频独立启动、LOGO静音、完整教程帧后开声、无图静音，以及三个模式下 K6/K7 的单按、长按和同时按下。该测试不模拟显示器锁定、真实TF延迟或模拟ADC精度。

三个独立错误变体均编译成功并触发具体断言：恢复 K6 字幕接线、去掉最终 PCM 静音保护、允许 LOGO 在有效行中交棒。错误文件均位于独立测试目录，未进入产品源码。

构建前后产品输入和工具哈希一致。时钟缺失、非法约束、无路径及被覆盖的 FIFO 例外为0；保留原有宏重定位、ROM初始化诊断和接口覆盖审查。两顶层均有26项输入延迟与29项输出延迟待审，悬空节点为3/4项。正时序及位流生成不替代严格验收。本轮未修改 PLL、SDRAM 时钟相位或物理 DQ 时序约束。

## 实板观察与边界

2026年11月1日13:01，通过JTAG将上述ADC修正版下载到SRAM，芯片ID匹配EG4S20BG256。操作者按KEY1复位后确认“LOGO静音，教程后有声”，并确认K6只调对比度、K7只切字幕。本轮没有写Flash或TF卡；这两项实板结论只对应上述位流。

真正断电冷启动到LOGO的时间尚未测量。SRAM位流断电消失，不能用断电后旧Flash程序的表现评价本轮改动。后续冷启动计时须先确认固化与恢复方案，再记录供电、LOGO、首张教程与首个音频的时间；复位测试与下载后启动不能冒充该结果。680×480来自用户报告，未通过读卡器核对当前卡中所有图片的尺寸。

复现：在仓库根运行 `python tests/sim/run.py --all --self-test-runner`；两个顶层完整构建使用 `python project/verify_td.py --td <本机TD命令行路径> --tops top top_adc --stage full --timeout 900`。原严格诊断存在时，验证脚本按设计返回失败，不应隐藏退出码。
