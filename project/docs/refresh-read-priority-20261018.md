# 刷新事务与读优先级修正（2026-10-18）

基线为 GitHub main `c8f2ab93601ccbea23d1418084333b3680622100`，保留四槽缓存、加载缩放、中文 UI、音频、LED、数码管和频率显示。另保留 D107 独立诊断工具。

本轮找到并修复两处可在数字仿真中独立复现的问题。**尚未确认它们能消除实板全部横线。** 用户反馈的“重启后横线位置变化、同次运行基本固定”仍需用对应位流上板确认；不要将仿真通过解释为硬件验收。

## 1. 刷新指示会中断已经开始的事务

原代码在每个请求上使用 `App_*_en_d0 && !Sdr_init_ref_vld`。这会在进行中的读写段中插入空拍。安路 APUG011 第 2.3 节要求在开始读写前等待刷新，进行中的正常读写由控制器管理；第 2.3.4 节说明数据按四字分组。

新增 `tb_frame_refresh_contiguous` 在一段读请求已开始后改变刷新指示。原逻辑在第 6 个字后中断，测试直接报错；写端单独测试也可复现。修正后，读写状态机各记录 `burst_started`：

- 首个实际请求发出前仍检查刷新，包括状态机已准入但首拍尚未到来的窗口。
- 首拍被接受后保持该段请求连续，不按刷新指示撤回中间拍。
- 在下一段准入前清除标志，再次等待刷新空闲。

原有 `tb_frame_refresh_interlock` 的初始刷新、首拍临界窗口、地址计数和读写互斥检查仍保留。

## 2. 读段结束交接时，写端可能抢走低水位优先级

原 `read_urgent` 仅在 `S_CHECK_FIFO` 有效。读段刚完成时，状态机经过 `S_READ_BURST_END`，此时 `O_rd_busy` 已下降，`read_urgent` 尚未接上。写端的组合准入逻辑可在这个空档抢先开始完整的 256 字写入。

新增 `tb_frame_mixed_roundtrip` 用实际生成的读写 FIFO RTL，在显示已完成的槽 0 时，持续向另外三个槽写入。三种时钟分别为 25/40/100 MHz，带刷新等待和写端背压。为缩短回归，每槽使用 640×2 像素并检查行切换和翻转；它没有在数字仿真中遍历实际四槽全部 640×480 数据。

修改前可重复观察到：

1. 显示 FIFO 只剩约 114 字时，后台开始 256 字写入。
2. 写入持续约 6.4 μs；25 MHz 连续显示在这段时间需要约 160 个像素。
3. 第 512 个像素读不到新数据，读 FIFO 保持前一个值：实际 `31546eff`（第 511 个像素），期望 `32569200`。

此失败同时出现在 main 的原状态机及仅完成刷新事务修正的候选中，说明它不是本次刷新修正引入的。

修正将低水位读优先级覆盖到 `S_READ_BURST_END`，保持交接连续；该组合信号仍独立于 `App_wr_busy`，不形成组合环。FIFO 低水位时先继续补读，达到安全水位后再放行写入。修正后混合测试完整检查 10240 个像素，通过。

显示 FIFO 饿空后保持最后一个像素，可能形成连续同色横段。这与照片现象有关联，但没有板上读回证据，不能把它认定为所有静态横线的唯一原因。

## 验证与复验

最终代码的 45 项 RTL 仿真及 5 项运行器控制全部通过。5 项故障注入分别恢复读/写端每拍刷新门控、删除读/写端首拍门控、删除交接优先级，均被对应测试拒绝。原 main 的两项失败也保留独立复现记录。工具构建结果以交付的验证 JSON 为准，保留源码、约束、工具版本和哈希。

先在可用的 TD 环境完整构建 `top` 与 `top_adc`，要求现有严格检查通过；不放宽时序，也不隐藏严重告警。优先使用团队的 TD 6.2.178840/SP1 是为了减少工具版本差异，并非芯片硬性要求。其他版本也需记录实际版本并通过相同检查。随后由板卡操作者保存旧位流，核对目标板后烧写新版本，观察冷启动加载期间、四页全部缓存后、训练/浏览切换及多次断电重启。

若横线仍存在，使用 `tests/board/sdram/README.md` 的 D107 诊断区分实际 SDRAM 数据完整性和直接视频输出。独立诊断通过不能替代产品混合读写的板上验收。

另有一项需要保留的接口条件：安路 `APUG011_基于ERAM接口实现的高性能SDRAM读写v1.2.pdf` 的 PDF 第 6 页（正文第 3 页）第 2.3.1 节，对连续写入提出 64 MHz 以上的时钟要求。当前参考设计使用 40 MHz、有限长度突发；数字测试不能证明这一组合的物理适用性。应结合官方确认及 D107 的 128/256 字突发实测判断，本轮没有据此擅改 PLL 或放宽 SDRAM 时序。该资料 SHA-256 为 `e20d565e0776bf91eddfd0062df6cb03ec6f6b4dc4a255b7fe57bad05d4e2294`。
