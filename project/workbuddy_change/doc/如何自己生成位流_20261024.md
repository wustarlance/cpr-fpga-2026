## 二、`.al` 到底是什么

`project.al` 是 TD 的工程清单（XML），里面只有三类信息：

1. **器件**：`EG4S20BG256`
2. **源文件列表**：71 条 `<File Path="...">`，每条带 `CompileOrder`（编译顺序）
3. **顶层模块**：`<TOP_MODULE><MODULE>top</MODULE>`
4. **约束文件**：`pin.adc` + 4 个 `.sdc`

它**不存任何综合结果**。每次构建都是读它 → 重新从源码跑一遍。

## 三、`.al` 什么时候更新（重点）

### 不会自动更新

| 操作 | `.al` 会变吗 |
|---|---|
| 用编辑器改 `rtl/*.v` 的内容 | 不会（也不需要，清单只记路径） |
| **新建**一个 `.v` 文件 | **不会**！必须手动加 |
| 命令行 `td_commands_prompt` + `open_project` | **不会**（只读，不回写） |
| 跑综合 / 布局 / 布线 | 不会 |
| **TD 图形界面里 Add Files + 保存工程** | **会** |
| 手工编辑 XML | 会 |

**所以：每次新增一个 `.v`，都要么在 TD 界面里 Add Files，要么手动改 `project.al`。**
漏掉的后果不是报错，而是更隐蔽的 **black box 警告**——TD 把找不到定义的模块当空盒，综合能过，上板功能全无。

## 四、新增文件后怎么登记

### 推荐：TD 图形界面

1. 打开 `project.al`
2. Project 树里对 `Verilog` 右键 → **Add Files**
3. 选中新 `.v` → 确定
4. **Ctrl+S 保存工程**（不保存不写回 `.al`）

顺便验证：`Tools → Show Black Box` 或综合日志里搜 `black`，应为空。

### 手工改 XML

在 `project.al` 的 `<Verilog>` 段末尾（`</Verilog>` 之前）插入：

```xml
            <File Path="rtl/audio/新文件.v">
                <FileInfo>
                    <Attr Name="UsedInSyn" Val="true"/>
                    <Attr Name="UsedInP&R" Val="true"/>
                    <Attr Name="AutoExcluded" Val="false"/>
                    <Attr Name="BelongTo" Val="source_1"/>
                    <Attr Name="CompileOrder" Val="200"/>
                </FileInfo>
            </File>
```

- `CompileOrder` 取比现有最大值更大的数（当前最大约 190），**对于纯模块文件顺序其实不重要**，TD 会自动排序；只有包含 `` `include `` 的头文件才需要靠前。
- `AutoExcluded="true"` 只是"标记为自动排除"的备注，**不影响编译**，不要手动删（这是本工程的既定约定）。

## 五、为什么不能双击 `.tcl`

`workbuddy_change/scripts/build_project.tcl` 双击跑不起来，三个原因叠加：

1. **文件关联不对**：Windows 上 `.tcl` 默认往往关联到文本编辑器，双击只是打开源码
2. **即使关联到 TD 也不行**——脚本第 21 行 `set proj [pwd]` 取当前目录，双击时当前目录是**脚本自己所在的 `scripts/`**，于是 `open_project "project.al"` 找不到文件、`constraints/pin.adc` 也读不到
3. **必须作为参数传给 TD 的命令行解释器**：`td_commands_prompt.exe <脚本>`

这个坑我实际踩过：CWD 不对时 TD 报的是 `HIER-1013 找不到顶层`，看起来像代码问题，其实是路径问题。

---

## 六、正确做法：双击 `build_project.bat`

我已放在 **project 根目录**（`D:/ANLU/code/cpr-fpga-2026/project/build_project.bat`）。

```bat
build_project.bat          :: 全流程 → top.bit
build_project.bat gate     :: 只综合，1-2 分钟看资源
build_project.bat route    :: 到布线，看最终时序
```

它内部做了三件事：
1. `cd /d "%~dp0"` —— 强制切到 project 根，解决 CWD 问题
2. 设 `BP_STAGE` 传入脚本
3. 结束后打印 `top.bit` 的路径、大小、时间戳

### 等价的命令行（自己敲）

```bash
cd D:/ANLU/code/cpr-fpga-2026/project
export BP_STAGE=bit
/D/ANLU/TD_6.2.1/bin/td_commands_prompt.exe workbuddy_change/scripts/build_project.tcl
```

## 七、构建完必看两件事

| 检查 | 文件 | 期望 |
|---|---|---|
| 时序 | `workbuddy_change/build_project/route_timing_status.rpt` | SWNS / HWNS 都是正数、0 违例 |
| 引脚落地 | `workbuddy_change/build_project/route_area.rpt` 的 IO 段 | `clk=R7`、`key1=B2`、`dip_sw[3]=C5` 等 |

引脚没落地（全在自动位置）的唯一原因是 `read_adc constraints/pin.adc` 没执行——命令行构建时脚本已含这行；用 GUI 构建则天然会读。
