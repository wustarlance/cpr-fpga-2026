# 上板与音频引脚说明（2026-10-24）

本文回答三件事：`wave_painter.v` 的归属、现在要做什么才能出位流、音频到底要接哪些引脚。
引脚全部取自 `9_康芯开发板使用手册及实验平台/HX4S20开发板手册-HDL版2410.pdf`（页码随文标注）。

---

## 1. `wave_painter.v` 是什么文件

| 项 | 说明 |
|---|---|
| 来源 | 上一轮按你"两个 bank 缓存 + 200×200 内画采样点"的要求**新写**的模块 |
| 现在的位置 | `wb_audio_code/rtl_wave/wave_painter.v`（原始）→ 复制到 `workbuddy_change/rtl/wave_painter.v`（构建用） |
| 不是什么 | **不在** `wb_audio_code/rtl/`（原音频工程），也**不在** `project/rtl/audio/`（你合并后的位置） |
| 依赖 | 只有 `I_clk/I_rst`、像素扫描口（`I_pix_de/x/y`）、音频样本口、输出 `O_pix_hit/O_pix_rgb/O_pix_de_d`；不依赖加密 IP |
| 现状 | 按你"暂时不考虑波形"的要求，**已从 `audio_tmg.al` 移除**（14 → 13 个文件），当前所有构建都不含它 |

它当初的价值是自检过的（16 帧逐列核对 PASS），但它是"显示件"，和"能不能出声"无关，所以先摆着不参与综合。

## 2. 现在卡在哪：HDMI 核是本机 TD 解不开的加密代码

这是本轮最重要的发现，**先说结论**：当前装的 TD 生成不出带 HDMI 的位流。

证据（三条独立复现）：

1. 本工程 `project/build.tcl`（`CPR_STAGE=synth`）→
   `HDL-8007 ERROR: unexpected non-printable character ... hdmi_1_4b_transmitter_core_wrapper.enc.v(30)`
2. **厂商自带的参考工程** `05_lab_ex/lab_ex5_i2s/src/td_project/HDMI1.4b_Transmitter_v1.0.al` → 同一条报错
3. 我自己新建的 `audio_board.al`（原样引用同一个核）→ 同一条报错

看文件内容就清楚了：它是 IEEE-1735 保护代码，不是普通 Verilog。

```
`pragma protect begin_protected
`pragma protect encrypt_agent = "Anlogic"
`pragma protect key_keyowner = "Anlogic", key_keyname = "anlogic-rsa-001"
`pragma protect key_method = "rsa"
`pragma protect data_method = "AES128-CBC"
`pragma protect data_block
xEMGgtGIXwk0uhv47C5Xei6+oMfm2ONT1t6zT1CKQM5qm+4a56gf5KT7sieLLIz2 ...
```

本机 TD 版本是 `Tang Dynasty, V6.2.168116`（`Jun 12 2025` 构建）。
工程 `README.md` 里记录的可用版本是 **TD 6.2.1 SP1 / 6.2.178840** —— 差的就是 SP1 的 1735 解密支持。
（`.al` 里写的 `TD_Version 6.2.168116` 只是生成该文件时的版本号，不代表解密能力。）

**处理办法**：装 TD 6.2.1 **SP1**（或更高），其余一行代码都不用改，`AB_PROJ=board` 直接能出 HDMI 位流。

## 3. 本机能出的位流：bring-up 版（不碰加密 IP）

为了不干等 SP1，本轮加了一个"只用板载器件验收音频链路"的顶层：

```
音频板级 bring-up 数据流

  TF 卡 ──SPI──► sd_card_top ──扇区──► wav_audio_sd_top ──► PCM FIFO
                     (100 MHz)            (WAV 解析)          │
                                                            ▼
                                             pcm_player (12.295 MHz, 48 kHz)
                                                            │
                                       ┌────────────────────┴───────────┐
                                       ▼                                ▼
                              一阶 Σ-Δ → 蜂鸣器 H11            数码管/LED 状态
                              (video_clk 25 MHz 打 1 bit)
```

| 顶层 | 文件 | 依赖加密 IP | 用途 |
|---|---|---|---|
| `audio_board_bringup_top` | `rtl/audio_board_bringup_top.v` | 否 | **今天就能上板**：听得到声、看得到状态 |
| `audio_board_top` | `rtl/audio_board_top.v` | 是（HDMI 核） | 等 SP1：640×480 彩条 + 音频进 TMDS 数据岛 |

### 3.1 build_bringup 实测（TD 6.2.1，已出位流）

| 项 | 数值 |
|---|---|
| 位流 | `build_bringup/audio_board_bringup_top.bit`（629 644 B） |
| 固化镜像 | `build_bringup/audio_board_bringup_top.bin`（626 777 B，`bit_to_bin` 生成，两次 md5 一致） |
| LUT | 2 729 / 19 600（13.92%） |
| REG | 1 591 / 19 600（8.12%） |
| BRAM9K | 3 / 64（pcm_fifo 2 + 1 块零碎） |
| PLL | 3 / 4 |
| PAD | 34 / 188（18.09%） |
| sd_clk 100 MHz | SWNS **+0.353 ns**（fmax 103.66 MHz），HWNS +0.032 |
| mclk 12.295 MHz | SWNS +0.542 ns |
| video_clk 25 MHz | SWNS +17.129 ns |

> 注意 `clk0` 的 fmax 只有 103.66 MHz：`wav_reader` 那条组合链仍是全设计最紧的地方。
> 与之前 audio_tmg 工程的结论一致——它够用，但不宽裕，别再加逻辑到这个域。

复现：

```bat
cd D:\ANLU\code\cpr-fpga-2026\project\workbuddy_change
set AB_PROJ=bringup
D:\ANLU\TD_6.2.1\bin\td_commands_prompt.exe scripts\build_board.tcl
```

## 4. 音频对应的引脚（重点）

### 4.1 先纠正一个前提：**这块板没有音频编解码器**

手册把开发板每个外设都列了（LED/数码管/蜂鸣器/按键/TF/以太网/HDMI/VGA/扩展口/Flash），
**没有任何 I2S DAC、没有 3.5 mm 音频口、没有功放**。所以：

- "音频引脚"不等于 I2S 四线（BCLK/LRCK/DIN/MCLK）—— 板上一根都没有；
- 板子能出声的通道只有两个：**HDMI（数字，嵌在 TMDS）** 和 **蜂鸣器 H11（1 bit）**；
- 你工程里的 `pcm_frame_tick/pcm_player` 已经是"PCM 直连 HDMI"方案，本来就**不需要** I2S 引脚。

### 4.2 HDMI_B（声音唯一的正经出口）—— 手册 P11/P12

| 信号 | FPGA 引脚 | 说明 |
|---|---|---|
| `HDMI_CLK_P` | **C3** | TMDS 时钟 P（N = C2，差分对自动配对，无需单独约束） |
| `HDMI_D0_P` | **G5** | TMDS 数据 0 P（N = G6） |
| `HDMI_D1_P` | **F1** | TMDS 数据 1 P（N = F2） |
| `HDMI_D2_P` | **E1** | TMDS 数据 2 P（N = D1） |
| `HDMI_DDC_SCL` | **P2** | EDID 读时钟（接到 5 V 上拉的 DDC） |
| `HDMI_DDC_SDA` | **R2** | EDID 数据（双向） |
| （不用）HPD | J6 | 热插拔检测，本设计未接 |
| （不用）CEC | K5 | 消费电子控制，本设计未接 |

电平：4 对 TMDS 用 `LVDS33`；DDC 两线用 `LVCMOS33` + 上拉（`PULLUP`）。
**音频数据就在这 3 条数据通道的数据岛里发出去**，所以"分配音频引脚"这件事到 HDMI 这 4 对就结束了。

### 4.3 蜂鸣器（唯一不靠 HDMI 的出声方式）—— 手册 P18

| 信号 | FPGA 引脚 | 说明 |
|---|---|---|
| `O_buzzer` | **H11** | **低电平导通**（0 = 响，1 = 不响）；板上 SW5 乒乓开关必须拨到"接通" |

bring-up 版就是把左声道 24 bit 用一阶 Σ-Δ 变成 1 bit 打在 H11 上（25 MHz 对 48 kHz，过采样 520）。
它只能算"能听出旋律"的验收手段，音质别指望；正式演示仍然走 HDMI。

### 4.4 如果要外接 I2S DAC 模块（可选，本工程未实现）

板上两个 40 芯扩展口可借 4 根 IO：

| 扩展口 | 可用引脚（手册 P7/P8、P13） |
|---|---|
| J1（GPIOA_n） | D14 / G11 / G12 / F13 / H13 / H14 / J14 / J13 / K12 / L14 … |
| J2（GPIOB_n） | P4 / N4 / N3 / M5 / M3 / M4 / L3 / J3 / J4 / H4 … |

要接 DAC 还得补一个"并行进、三线出"的 I2S 发送器（`pcm_i2s_tx` 系列在 2026-10-22 已被删除），
本工程暂不提供；除非你要拿板子接功放，否则不建议走这条路。

### 4.5 配套必须一起分配的引脚（bring-up 版，共 34 个 PAD）

| 功能 | 信号 | 引脚 | 备注 |
|---|---|---|---|
| 时钟 | `clk` | **R7** | 50 MHz 有源晶振（P22 也印证 CLK = R7） |
| 复位 | `rst_n` | **A2** | 就是 KEY1，按下接地 = 复位 |
| 播放/暂停 | `key_play` | **B2** | KEY2 |
| 停止 | `key_stop` | **B1** | KEY3 |
| 静音 | `key_mute` | **C1** | KEY4 |
| 循环开关 | `dip_sw[0]` | **C8** | SW1，拨上 = 循环 |
| 备用拨码 | `dip_sw[1..3]` | C7 / C6 / C5 | SW2..SW4 |
| LED | `led[0..3]` | A4 / A3 / C10 / B12 | 高电平点亮 |
| 蜂鸣器 | `O_buzzer` | **H11** | 低电平响 |
| TF 卡 | `sd_ncs` | **A12** | SD_DAT3/CS |
| | `sd_dclk` | **A14** | SD_CLK |
| | `sd_mosi` | **A13** | SD_CMD/DI |
| | `sd_miso` | **B14** | SD_DAT0/DO |
| 数码管位选 | `seg_sel[0..7]` | F16 / E16 / E12 / E10 / C13 / F10 / E11 / D11 | 高电平使能 |
| 数码管段码 | `seg_data[0..7]` | C15 / C16 / B6 / A5 / B5 / A8 / A7 / A6 | 共阳，低电平点亮，bit7 = 小数点 |

约束文件：
`constraints/audio_bringup.adc`（bring-up，含数码管，不含 HDMI）
`constraints/audio_board.adc`（HDMI 版，含 TMDS + DDC，不含数码管）

## 5. 上板步骤

### 5.1 先把 WAV 写到卡的固定扇区

`wav_audio_sd_top` 是"给起始扇区就顺序读"，不解析 FAT，所以 WAV 必须**物理落在** `LBA 12000`
（`START_SECTOR = 32'd12000`）。拖拽复制到卡上是不行的（文件系统会把它放到别的扇区）。

```bat
cd D:\ANLU\HX4S20_Contest_202606\学习\wb_audio_code\tools
python burn_wav.py --list                       :: 看读卡器是几号盘
python burn_wav.py --disk 2 --file song.wav      :: 预检（不写盘）
python burn_wav.py --disk 2 --file song.wav --yes --verify
```

写完卡插回电脑会提示"需要格式化"——**不要格式化**。
WAV 要求：PCM、16/24 bit、单/双声道，48 kHz 最省事（44.1 kHz 也行，`pcm_player` 会做重采样式的跳帧）。

### 5.2 下载位流（TDSRAM / 固化 Flash）

板上是 SRAM 型 FPGA（EG4S20），两种下载方式：

| 方式 | 文件 | 掉电 | 操作 |
|---|---|---|---|
| JTAG → FPGA 内部 SRAM | `.bit` | **丢失** | TD → `Tools → Download`，选 `build_bringup/audio_board_bringup_top.bit`，模式 SRAM/JTAG |
| JTAG → 板载配置 Flash | `.bin` | 保留，上电自启动 | 同一对话框里选 SPI Flash / 或 BitWizard（SWUG110），文件选 `.bin` |

配置 Flash 用的是专用 MSPI 引脚（R11/P10/T3/T10），**不需要在 .adc 里约束**。

### 5.3 验收清单（bring-up 版）

| 现象 | 说明 |
|---|---|
| 上电后 LED4 亮 | `O_wav_ready = 1`，WAV 头解析成功 |
| 数码管左 2 位 = `1 0` 之类 | 左起第 1 位 = `O_wav_state`，第 2 位 = 错误码（`0` 正常） |
| 数码管右 6 位在**跳** | 48 kHz 帧计数在累加 → SD→FIFO→PCM 全程通了 |
| 蜂鸣器有旋律 | SW5 拨下；按键 KEY2 暂停后无声 |
| LED3 亮 | `O_wav_error = 1`，看数码管第 2 位的错误码定位（1=超时/2=格式/…） |

### 5.4 拿到 SP1 之后

```bat
set AB_PROJ=board
D:\ANLU\TD_6.2.1\bin\td_commands_prompt.exe scripts\build_board.tcl
```

出 `build_board/audio_board_top.bit`，接 HDMI 显示器就能同时看到彩条和听到声音。
`audio_board_top` 已经写好并通过 SGM 语法检查，只剩加密核这一道门。
