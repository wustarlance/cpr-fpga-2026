## 2. 踩过的两个坑

### 坑一：`pin.adc` 不读 = 位流被拒（BIT-8123）

`project.al` 里虽然登记了 `constraints/pin.adc`，但 `open_project` 不带 `-single_run`
时只建层次、**不会自动套用约束**。第一轮构建因此把所有 IO 自动摆放
（`key1` 落到 C16、`dip_sw[0]` 落到 J16），最后 bitgen 直接拒绝：

```
BIT-8123 ERROR: Bitgen is prohibitted as there is(are) unconstrained io(s) in design.
```

修法：在 `elaborate` 之后显式 `read_adc constraints/pin.adc`，再读 SDC。
加进去后 `key1=B2 / key2=C1 / key3=B1 / dip_sw=C8,C7,C6,C5 / clk=R7 / led=A4,A3,C10,B12`
全部落位，位流正常生成。

### 坑二：音频时钟没有跨域约束

接上 WAV 播放后，音频主时钟（`u_audio_pll/pll_inst.clkc[2]`）第一次与
`sd_card_clk`、`video_clk` 之间出现真实路径。原 `constraints/timing.sdc` 明确
拒绝宽泛的 clock group，于是 TD 按同步关系去算这些相位无关的路径，报出：

| 路径组 | 违例 |
|---|---|
| `sd_card_clk` → 音频时钟 | SWNS −2.347 ns（32 端点） |
| `video_clk` → 音频时钟 | SWNS −1.870 ns（75 端点） |
| 音频时钟 → `sd_card_clk` | HWNS −1.540 ns |
| `video_clk` → `ext_mem_clk` | HWNS −1.528 ns |
| `video_clk` → `sd_card_clk` | HWNS −1.327 ns |

逐个查端点，跨域点全部是构造性安全的：
`frame_read_write/read_buf/rd_to_wr_cross_inst/primary_addr_gray_reg → sync_r1_reg`
是格雷码指针 + 两级同步器；WAV 侧 PCM 数据过双时钟 FIFO，`I_loop` 两级同步，
WAV 头信息（采样率/总帧数）解析后保持恒定。保持违例全部落在同步器第一级输入上，
两级同步器本身就能吸收。

修法：新增 `workbuddy_change/constraints/project_cdc.sdc`，把
`sd_card_clk` / `ext_mem_clk(+sft)` / `video_clk(+hdmi_5x)` / 音频时钟 分成四组
互相异步；`video_clk` 与 `hdmi_5x_clk` 仍留同一组（像素/串行关系不变），
`clk`（50 MHz 输入）不纳入分组，输入建立保持照旧检查。

同时把该文件登记进 `project.al` 的 `<SDC_FILE>`（CompileOrder=5），
保证图形界面直接跑综合时也能复现。

## 5. 需要注意

- `sd_card_clk` 只有 **+0.016 ns** 余量，等于贴着 100 MHz 的边界。换工具版本、
  改一处逻辑、甚至重新跑一次布局，都可能翻成负值。若要留余量，得从
  `frame_read_write → bmp_read` 那条 8 级逻辑的长路径下手（时序报告里它占
  63% 的布线延迟），而不是加约束。
- 本次 `read_adc` 让 PAD 从 39 增到 52：`ext_keys_n` / `depth_sw_n` 这些在
  未启用模式下本被优化掉的端口，落位后也被保留下来，属正常现象。
