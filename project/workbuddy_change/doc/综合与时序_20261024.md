## 1. 这次跑的是什么

`rtl/audio` 下的 WAV 播放链（SD 扇区读 → RIFF 头解析 → PCM FIFO → 播放器）
加上新写的 `wave_painter`，由 `audio_tmg_top` 包起来：

```
I_sd_clk 100MHz ──┬─ u_sd (vendor sd_card_top) ─ u_audio/u_path (wav_audio_path)
                  │      └ sd_card_cmd / sd_card_sec_read_write / spi_master
                  └─ wav_reader（RIFF / fmt / data 头解析）
I_mclk 12.288MHz ─── pcm_frame_tick + pcm_player
I_video_clk 25.175MHz ─ pcm_fifo 读侧 + toggle 跨域 + wave_painter + 扫描计数器
```

- 13 个 Verilog 文件（11 个来自 `rtl/audio` + `vendor/SD`，另 2 个在 `rtl/`）
- 三路时钟**直接从端口给**，不经 PLL —— 约束干净，也便于和历史工程对照
- 视频侧自带 640×480@60 扫描计数器（800×525 @25.175MHz = 59.94Hz），
  因为 `wave_painter` 是「每像素问一次」的接口，不产生时序

## 2. 约束要点

| 项 | 写法 |
|---|---|
| 三时钟 | `create_clock` 10.000 / 81.380 / 39.722 ns |
| 跨域 | `set_clock_groups -asynchronous` 三组互切 |
| SD 4 线 | `set_output_delay 5.0` + `set_multicycle_path 4 -setup / 3 -hold` |
| 音频/像素输出 | `set_output_delay 3.0 -clock vid_clk`（真机是片内连线） |
| 准静态 | `I_ctrl[*]`、`I_rst_n` 走 `set_false_path`；`O_dbg[*]` 同理 |

跨域点是构造性正确的（`pcm_fifo` 格雷码指针 + 2 级同步、toggle 标志 + 3 级同步、
SD 状态为准静态），所以 `-asynchronous` 不是「藏违例」，是设计前提。

SD 那 4 根线为什么用多周期：SD SPI 实际只跑 25 MHz（= sd_clk/((0+2)*2)），
若按 10 ns 硬卡，光输出 pad 自身的 clk→pad 延迟就超过半周期，必然假违例。

## 3. 时序结果（布线后，Confidence: Routed）

```
SWNS: 0.193ns, STNS: 0.000ns.        HWNS: 0.038ns, HTNS: 0.000ns.
STA coverage: 100%
```

| 时钟 | 约束频率 | 实测 fmax | SWNS | HWNS | 端点 | 违例 |
|---|---|---|---|---|---|---|
| sd_clk | 100.000 MHz | 101.968 MHz | **+0.193 ns** | +0.038 ns | 2703 | 0 |
| vid_clk | 25.175 MHz | 35.239 MHz | +11.344 ns | +0.054 ns | 1005 | 0 |
| mclk | 12.288 MHz | 79.949 MHz | +68.872 ns | +0.046 ns | 615 | 0 |

三个域全过，`Max-Level` 分别 8 / 23 / 15。

### 最差路径（sd_clk 域）

| 项 | 值 |
|---|---|
| 起点 | `u_audio/u_path/S_stop_sd_cnt_reg[1]`（stop 计数，sd_clk 域） |
| 终点 | `u_audio/u_path/u_wav_reader/S_fmt_reg[144]` 的 `mi[0]`（fmt 头寄存器的 mux 输入） |
| Slack | +0.193 ns |
| 数据路径 | 9.527 ns（cell 1.809 ns / 18%，net 7.718 ns / 82%） |
| 逻辑级数 | 5（LUT4×4 + LUT2×1） |
| 最大扇出 | 55 |
| 时钟偏斜 | 0.064 ns |
| 时钟不确定度 | 0.100 ns（SDC 未写，用工具默认） |

特征：**cell 只占 18%，net 占 82%**。也就是说逻辑级数已经不高（5 级），
剩下的时间花在布线上——再拆逻辑收益有限，真正能改善的是布局/扇出，
或者把这条 `S_stop` 计数到 `S_fmt` mux 的路径在 RTL 上切成两拍。

### 综合后 vs 布线后（重要）

| 阶段 | SWNS | 说明 |
|---|---|---|
| opt_gate（综合后估算） | **−0.493 ns** | 最差路径 net 估算 6.838 ns，偏悲观 |
| opt_route（实际布线） | **+0.193 ns** | 同一逻辑，实际 net 缩短 |

结论：**别在 gate 阶段就判"违例要降频"**。综合后的线延迟是统计估算，
这份设计在 gate 阶段报 −0.493，布线后翻正 +0.193，差 0.686 ns。

| 项 | 综合后（gate） | 布线后（route） | 占比 |
|---|---|---|---|
| LUT | 3705 | 3789 | 19.33%（19600） |
| REG | 1858 | 1915 | 9.77% |
| LE | — | 4084 | — |
| BRAM9K | 6 | 6 | 9.38%（64） |
| DSP | 1 | 1 | 3.45%（29） |
| PAD | 136 | 136 | 72.34%（188） |
| PLL | 0 | 0 | 0% |

- 6 块 BRAM9K 的来源：`pcm_fifo` 的存储、`sd_card_top` 内部的块缓冲、
  `wave_painter` 的两个 bank（256×24，各 1 块）
- 1 个 DSP：`audio_arc_calculate` 的乘加
- 136 个 PAD：9 入 / 127 出（64 位音频数据 + 48 位 ACR + 24 位 RGB + 状态归约）
- **PAD 72% 是这份顶层特有的**：独立 STA 顶层把所有内部总线都引出 pad 了，
  上板版本只有真正需要的引脚，资源占用不受影响

## 6. 和历史工程的关系（不要直接对比数字）

之前 `wb_audio_code` 里的纯音频网表是 +0.134 ns（1854 端点），上板顶层是 +0.898 ns
（2036 端点）。本次 +0.193 ns / 2703 端点，差异来自**边界不同**，不是设计退步：

1. 本次多了 `wave_painter`（2 块 BRAM + 两列比较逻辑）和它到像素时钟域的握手
2. 本次是「三时钟直给 + IO 全引出」的 STA 顶层，IO 路径与 pad 延迟算进来
3. 端点从 2036 涨到 2703，时序收敛的搜索空间变大

真正可比的是同一顶层、同一 SDC 下改动前后的差。

## 7. 后续

1. **补引脚约束**：现在 PAD 是 TD 自动分配的。上板前要写 `.adc/.cst`，
   补完后 IO 时序要重算一遍（尤其 `O_sd_dclk` 的 clk→pad，多周期数字要按实际核）。
2. **端到端仿真**：需要一个 SD 卡行为模型（SPI 模式、CMD17 单块读）才能把
   「换卡 → 读扇区 → 解析头 → 出声 → 画波形」整链跑通；目前只到模块级。
3. **sd_clk 保持余量**：+0.038 ns 太薄。若换器件/换 TD 版本，先看这条。
   要加余量的话，把 `S_stop_sd_cnt → wav_reader S_fmt` 那条路径在 RTL 上切两拍
   （写使能判据寄存一拍），比改时钟代价小。
4. **`S_fmt_reg[144]` 的 mux**：终点落在 fmt 头 144 位寄存器的 mux 输入上，
   说明 fmt 头的写使能是组合出来的。若要动，把它提成独立的 `ce` 寄存器即可。
