# 总工程（top / project.al）音频播放控制与引脚映射

> 适用工程：`D:/ANLU/code/cpr-fpga-2026/project/project.al`（顶层 `top`）
> 音频通路：SD 卡 WAV → PCM FIFO → HDMI 数据岛（不走蜂鸣器）
> 更新日期：2026-10-24

## 1. 播放器的四个控制口

`wav_audio_sd_top` 对外暴露四个控制信号，语义如下（来自 `rtl/audio/pcm_player.v`、`rtl/audio/wav_audio_path.v`）：

| 信号 | 极性 | 语义 |
|---|---|---|
| `I_play` | 电平，1=播放 | 0 时暂停：不消耗 FIFO，帧节拍照常走、样本发 0（HDMI 仍有音频流，电视不会报错） |
| `I_stop` | 单拍脉冲 | 清进度、清缓冲、回到文件开头；WAV 读取器由上层重启 |
| `I_mute` | 电平，1=静音 | 帧节拍照常走，样本清 0 |
| `I_loop` | 电平，1=循环 | 播完从头再来 |

## 2. 当前实际映射

| 板上资源 | 引脚 | 接到哪个信号 | 效果 |
|---|---|---|---|
| **SW4** | **C5**（`dip_sw[3]`） | `I_play` / `I_mute` / `I_stop` | **拨动一次切换一次：播放 ↔ 停止（并回到文件开头）**。上电固定为播放，与开关停在哪一侧无关 |
| **SW1** | **C8**（`dip_sw[0]`） | `I_loop` | 单文件循环 |
| SW2 / SW3 | C7 / C6 | `contrast_controls` | 已被对比度档位占用，不做播放控制 |
| KEY2 | B2 | `key1` → 手动下一张 | 页面导航 |
| KEY3 | B1 | `key3` → 上一张 | 页面导航 |
| KEY4 | C1 | `key2` → 模式切换 | 页面导航 |
| KEY1 | A2 | `rst_n` | 硬复位 |

SW4 经 `input_filter`（20 ms 稳定过滤）消抖，再延迟一拍做边沿检测：

- `wav_play_en`：拨动一次翻转一次，复位值为 1（播放）
- `wav_sw4_edge`：翻转当拍的单拍脉冲 → `I_stop`（回到文件开头）
- `I_play = wav_play_en`、`I_mute = ~wav_play_en`

**为什么用“拨动切换”而不是固定极性**：板卡 DEMO `2_Example/.../8_key_sw/key_sw.adc` 把
C8/C7/C6/C5 四位拨码和 A2/B2/B1/C1 四个按键接在同一组带上拉的输入上，注释写
"when the keydown, the value is 0"，即闭合 = 低；但拨码“拨上”是闭合还是断开，资料里
没有唯一结论（本工程旧注释写 `active high`，与上拉电路矛盾）。若按固定极性判断，
一旦判反，上电就是静音。边沿切换对两种极性都成立，上电永远从播放开始。

上电 50 ms 内不响应拨动（`wav_ctrl_ready`），用来跳过 `input_filter` 的稳定过程，
避免开关停在某一侧时开机瞬间把状态翻掉。

## 3. 为什么不占用板载按键

板载只有 4 个独立按键，其中 KEY1（A2）是硬复位，KEY2/KEY3/KEY4 在本工程里已经承担
翻页与模式切换（`key1` / `key3` / `key2`）。要再挂播放/停止就得改页面交互逻辑，
代价远大于收益，所以改用空闲的 SW4。

## 4. 相关引脚（未改动）

HDMI 四对差分线在 `constraints/pin.adc` 中早已存在，音频走数据岛**不需要新增任何引脚**：

| 信号 | 引脚 |
|---|---|
| HDMI_CLK_p / _n | C3 / C2 |
| HDMI_D0 / D1 / D2 | G5 / F1 / E1 |
| HDMI_DDC_SDA / SCL | P2 / R2 |
| HDMI_HPD | J6 |
| SD（TF 卡） | A12 / A14 / A13 / B14 |

## 5. 听不到声音时的排查顺序

1. 先拨一下 SW4（不要管它原来停在哪一侧），确认是不是被上一次拨动切到了停止态
2. TF 卡里的 WAV 必须烧在 **LBA 12000**，与 `START_SECTOR` 一致；烧卡后不要格式化
3. WAV 必须是 **24bit PCM**、采样率与 `pcm_frame_tick` 的 48 kHz 匹配
4. HDMI 线两端插紧；部分显示器/电视对音频数据岛支持差，换一台试
5. 切页瞬间 WAV 会欠载约 160 ms（SD 总线被 BMP 独占），属已知现象
