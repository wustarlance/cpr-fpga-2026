## 〇、预备知识（不熟 SPI 就先读这一节）

### 0.1 SPI 是什么

**SPI = Serial Peripheral Interface，串行外设接口。**

> **一根时钟线 + 两根数据线，让两个芯片一位一位地交换数据。**

Motorola 在 1980 年代搞出来的，**不是 IEEE 标准**，但简单好用成了事实标准——**SD 卡、Flash、传感器、小屏幕几乎都支持**。

**为什么用串行**：传 8 位，并行要 8 根数据线，串行只要 2 根。芯片引脚很贵，**串行靠时钟频率高把速度补回来**。

| 线 | 全称 | 方向 | 干什么 |
|---|---|---|---|
| **DCLK**（SCLK） | Serial Clock | **主机 → 从机** | **节拍器**：主机敲一下，双方各传一位 |
| **MOSI** | **M**aster **O**ut **S**lave **I**n | 主机 → 从机 | 主机说的话 |
| **MISO** | **M**aster **I**n **S**lave **O**ut | 从机 → 主机 | 从机说的话 |
| **nCS**（CS） | Chip Select，**低有效** | 主机 → 从机 | "点谁的名"，拉低谁才响应 |

**本工程里**：主机 = **FPGA**（产生时钟），从机 = **SD 卡**。

> ⚠️ **时钟只能由主机产生**。**你不敲时钟，从机一个字都吐不出来**——这就是"读数据也要发 `0xFF`"的原因。

**一个字节怎么传**：

```
nCS   ‾‾‾‾\_________________________________/‾‾‾‾‾
                        （拉低 = 选中）
DCLK  _____/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\______
           1   2   3   4   5   6   7   8      ← 8 个周期
MOSI  -----<b7 ><b6 ><b5 ><b4 ><b3 ><b2 ><b1 ><b0 >---
MISO  -----<b7 ><b6 ><b5 ><b4 ><b3 ><b2 ><b1 ><b0 >---
```

**每个时钟周期，双方同时各送出 1 位、各收进 1 位。16 个时钟沿 = 8 位 × 2。**

**全双工**：MOSI 和 MISO 是两根独立的线，**同一时刻既能发也能收**。所以：

```verilog
input  [7:0] data_in;    // 要发的字节
output [7:0] data_out;   // 同时收回来的字节
```

**发一个字节的代价，就是顺便收一个字节。** 读 SD 卡时 FPGA 一直发 `0xFF`（空操作）——内容无所谓，**关键是逼着时钟继续敲**。

**CPOL / CPHA**：空闲电平与采样相位，组合出 4 种模式，**双方必须一致**。本工程 `CPOL=1, CPHA=1`（**Mode 3**）。

**和另外两种串行总线对比**：

| | **SPI** | I²C | UART |
|---|---|---|---|
| 线数 | **4** | 2 | 2 |
| 时钟 | **独立时钟线** | 独立时钟线 | **没有**（约定波特率） |
| 速度 | **快**（几十 MHz） | 中 | 中 |
| 挂多设备 | 每个从机一根 nCS | 靠地址 | 只能点对点 |
| 全双工 | **是** | 半双工 | 是 |

> **一句话记住 SPI**：**线多、速度快、靠 nCS 点将。**

### 0.2 ⚠️ SD 模式 vs SPI 模式

**结论：板子的卡座两种模式都支持；参考工程用的是 SPI 模式。两者不冲突。**

开发板手册原文：

> 「TF卡(Secure Digital Memory Card)**有两种模式，一种是SD模式，一种是SPI模式**」

**同一批物理引脚，两套用途**：

| 引脚 | SD 模式的名字 | SPI 模式的名字 |
|---|---|---|
| **A12** | SD_DAT3 | **CS** |
| **A13** | SD_CMD | **DI / MOSI** |
| **A14** | SD_CLK | **SCLK** |
| **B14** | SD_DAT0 | **DO / MISO** |
| A11 | SD_DAT2 | *保留，不用* |
| B15 | SD_DAT1 | *保留，不用* |

**模式怎么选——不需要跳线，卡自己认**：

> **CMD0（复位命令）发出时，如果 CS（DAT3）被拉低 → 卡进入 SPI 模式。**
> 卡上电后默认 SD 模式，靠协议切换，硬件不用动。

**两种模式差多少**：

| | **SD 模式** | **SPI 模式**（本工程） |
|---|---|---|
| 用几根线 | 6 根 | **4 根** |
| 数据宽度 | 1 位或 **4 位** | 只能 1 位 |
| 速度 | 50MHz × 4bit = **25 MB/s** | 25MHz × 1bit = **3.125 MB/s** |
| 协议复杂度 | **高**（CRC7/CRC16、多种响应、双向 IO + 三态） | **低**（发字节收字节，只有 R1） |

**证据：参考工程确实是 SPI 模式**——`pin.adc` 里 SD 的约束是 `sd_dclk→A14 / sd_miso→B14 / sd_mosi→A13 / sd_ncs→A12`，**正是 SPI 模式那 4 根，引脚号与手册一致**。

**要不要改用 SD 4-bit 模式？→ 不建议**：要写完整 SD 协议栈、CMD 和 DAT 都是双向的要处理三态、**而双缓冲已经把慢的那 0.49 秒藏起来了**。W1 的目标是"能读出扇区"，SPI 照抄就能过。

> **代价**：A11/B15 空着；速度慢 8 倍（被双缓冲掩盖）。
> **换来**：四层代码直接搬，零风险。**建议一路走到底，赛前别动。**
> ⚠️ 注意范围：能直接搬的是**这四层**；它们在调用树上的上层 `sd_card_bmp` 是应用调度器，**你们要自己写**（见第十节）。

注意：**除了这 4 个文件，还要算上外面的 `sd_card_bmp.v`**——它是"包在外面的调度器"，不搞 SD 通信，但负责决定"什么时候读哪张图"。

### 2.2 五个文件的分工表

| 文件 | 行数 | 一句话角色 | **谁调用它** | **它调用谁** | 它看得懂什么 | 它看不懂什么 |
|---|---|---|---|---|---|---|
| `sd_card_bmp.v` | 395 | **内容调度器**（"导演"） | 顶层 | `bmp_read`、`sd_card_top` | 图片编号、按键、缓冲区 | SD 协议、SPI、BMP 格式 |
| `bmp_read.v` | 322 | **BMP 解析**（第4站） | `sd_card_bmp` | 无（只发信号） | BMP 文件头格式 | SPI、SD 命令 |
| `sd_card_top.v` | 127 | **外壳**（层4） | `sd_card_bmp` | 下面三个 | 什么都不知道（只是接线板） | 一切 |
| `sd_card_sec_read_write.v` | 255 | **协议层**（层3） | `sd_card_top` | 发命令给层2 | "初始化要发哪些命令""读扇区用 CMD17" | **位**怎么发、扇区内容是什么 |
| `sd_card_cmd.v` | 353 | **命令层**（层2） | `sd_card_top` | 发字节给层1 | "命令是 6 个字节""响应是 1 个字节""数据块 512 字节" | 命令**为什么**要这么发 |
| `spi_master.v` | 137 | **物理层**（层1） | `sd_card_top` | 直接驱动引脚 | **只会"发一个字节、收一个字节"** | **完全不知道 SD 卡存在** |

### 2.3 关键认识：分层的意义

**看第1层的"看不懂"那一栏**：

> `spi_master.v` 完全不知道 SD 卡存在。它只是一个通用的 SPI 移位器。

**这意味着**：
- 换一个 SPI 器件（Flash、SPI 屏幕），**层1 可以原封不动复用**
- 你们板上的 **W25Q64 Flash 也能用它**——同一份代码，两种器件

**看"谁看不懂谁"这一列**：

| 层 | 它不需要知道 |
|---|---|
| 层1 | 上面在传什么内容 |
| 层2 | 这些命令是干嘛的 |
| 层3 | 位是怎么变成电平的 |
| 层4 | 一切 |

**每层只跟相邻层打交道**——这就是分层的价值。

## 三、模块之间到底接了什么线

四个接口，"由外到内"逐组看。

### 3.1 第①组：`sd_card_bmp` ↔ `sd_card_top`（**本站的对外接口**）

这就是本站**唯一需要你们关心的接口**：

| 信号 | 方向 | 类型 | 含义 |
|---|---|---|---|
| `clk` / `rst` | 进 | — | 时钟（100MHz）/ 复位 |
| **`sd_sec_read`** | **进** | **电平** | "我要读一个扇区"。**保持高电平直到读完** |
| **`sd_sec_read_addr`** | **进** | 电平 | 读哪个扇区（32 位扇区号） |
| `sd_init_done` | 出 | 电平 | SD 卡初始化完成（下游的使能闸门） |
| **`sd_sec_read_data`** | **出** | 电平 | 当前这个字节（8 位） |
| **`sd_sec_read_data_valid`** | **出** | **脉冲** | "这一拍的 `data` 有效" |
| **`sd_sec_read_end`** | **出** | **电平** | "这个扇区读完了"（持续到下一次请求） |
| `SD_nCS` / `SD_DCLK` / `SD_MOSI` | 出 | — | 三根线出去到卡 |
| `SD_MISO` | 进 | — | 一根线从卡回来 |
| `sd_sec_write` / `sd_sec_write_*` | — | — | **写功能，用不到，接 0 / 悬空** |

> ⚠️ **`_valid` 是脉冲、`_end` 是电平、`sd_sec_read` 是电平**——三个信号的时序性质完全不同，**这是理解下一节的前提**。

### 3.2 第②组：`sd_card_top` 内部，层3 ↔ 层2（**命令接口**）

| 信号 | 方向 | 含义 |
|---|---|---|
| `cmd_req` | 层3→层2 | "我要发一条命令"（电平，保持到 ack） |
| `cmd_req_ack` | 层2→层3 | "命令发完了"（**电平**，在 `S_END` 状态期间） |
| `cmd_req_error` | 层2→层3 | "发命令失败了"（超时/异常响应） |
| `cmd[47:0]` | 层3→层2 | **6 个字节的命令**：命令号 + 4 字节参数 + CRC |
| `cmd_r1[7:0]` | 层3→层2 | **期望的响应值**（如 CMD17 期望 `0x00`） |
| `cmd_data_len` | 层3→层2 | 命令后面还要跟着读几个字节（CMD8 要读 4 字节） |
| `block_read_req` | 层3→层2 | "请读一个 512 字节数据块" |
| `block_read_req_ack` | 层2→层3 | "数据块读完了" |
| `block_read_valid` | 层2→层3 | "这一拍的字节有效"（**脉冲**） |
| `block_read_data[7:0]` | 层2→层3 | 数据字节 |
| `block_write_*` | — | 写功能，用不到 |

### 3.3 第③组：层2 ↔ 层1（**字节接口**）

| 信号 | 方向 | 含义 |
|---|---|---|
| `spi_wr_req` | 层2→层1 | "发一个字节"（电平，保持到 ack） |
| `spi_wr_ack` | 层1→层2 | "发完了"（**脉冲，只高一个时钟**） |
| `spi_data_in[7:0]` | 层2→层1 | 要发的字节 |
| `spi_data_out[7:0]` | 层1→层2 | **同时收回来的字节**（SPI 是全双工） |
| `clk_div[15:0]` | 层2→层1 | SPI 时钟分频值（决定快慢） |
| `nCS_ctrl` | 层2→层1 | 片选（低有效） |

> **这一层只有"字节"，没有"命令"**——层1 完全不知道字节的含义。

### 3.4 第④组：层1 ↔ SD 卡（**物理引脚**）

| 信号 | 方向 | 说明 |
|---|---|---|
| `SD_DCLK` | FPGA→卡 | SPI 时钟（本来就是 `DCLK_reg`，一个寄存器输出） |
| `SD_MOSI` | FPGA→卡 | 就是 `MOSI_shift[7]` |
| `SD_MISO` | 卡→FPGA | 直接进移位寄存器最低位 |
| `SD_nCS` | FPGA→卡 | 就是 `CS_reg` |

## 四、★ 跟着一次"读扇区"走一遍

**这是把上面所有东西串起来的一节。** 场景：`bmp_read` 要读 **第 1800 号扇区**。

### 阶段 0：上电初始化（**只做一次**，约几百毫秒）

| 谁在动 | 干什么 |
|---|---|
| 层3 | 走 `S_IDLE → S_CMD0 → S_CMD8 → S_CMD55 → S_CMD41 → S_CMD16`，把卡初始化好 |
| 层3 | 初始化用 **200 kHz**（`SPI_LOW_SPEED_DIV=248`） |
| 层3 | 初始化成功后切到 **25 MHz**（`SPI_HIGH_SPEED_DIV=0`），并拉高 **`sd_init_done`** |
| 层3 | 进入 `S_WAIT_READ_WRITE`，**等上层下命令** |

> `sd_init_done` 是**使能闸门**：它为 0 时，`bmp_read` 和 `sd_card_bmp` 都被按在复位状态。

### 阶段 1：上层提出请求

| 谁在动 | 信号变化 |
|---|---|
| `bmp_read` | **`sd_sec_read <= 1'b1`**（拉高）、**`sd_sec_read_addr <= 1800`** |

**注意**：`sd_sec_read` 是**电平**，不是脉冲——它会**一直保持高**，直到收到 `sd_sec_read_end`。

### 阶段 2：协议层（层3）收到请求，组出命令

| 谁在动 | 干什么 |
|---|---|
| 层3 | 在 `S_WAIT_READ_WRITE` 看到 `sd_sec_read == 1` |
| 层3 | `sec_addr <= sd_sec_read_addr`（**锁存地址**）→ 进 `S_CMD17` |
| 层3 | 设 `cmd <= {8'd17, sec_addr, 8'hff}`（**CMD17 = 单块读**）<br>设 `cmd_r1 <= 8'h00`（**期望响应**）<br>**拉高 `cmd_req`** |

**这一步的关键**：协议层把"读扇区"这个意图，翻译成了"**CMD17 + 地址**"这条 SD 命令。

### 阶段 3：命令层（层2）发命令、等响应

| 谁在动 | 干什么 |
|---|---|
| 层2 | 在 `S_WAIT` 看到 `cmd_req == 1` → 进 `S_CMD_PRE` |
| 层2 | `S_CMD_PRE`：先发一个 `0xFF`（**给卡提供时钟**） |
| 层2 | → `S_CMD`：把 **`nCS` 拉低**，逐字节发 **6 个字节**：<br>`0x51`（=17\|0x40）、地址4字节、CRC |
| 层2 | 6 字节发完，继续发 `0xFF`，**轮询收到的字节**直到 `data_recv == cmd_r1`（=`0x00`） |
| 层2 | 收到期望响应 → 进 `S_END`，此时 **`cmd_req_ack = 1`** |

**每一字节都要经过层1**：层2 拉 `spi_wr_req` + 给 `spi_data_in` → 层1 移 8 位 → 拉 `spi_wr_ack` → 层2 发下一个。

### 阶段 4：协议层放行 → 命令层收 512 字节数据

| 谁在动 | 干什么 |
|---|---|
| 层3 | 看到 `cmd_req_ack & ~cmd_req_error` → 进 `S_READ`，`cmd_req = 0` |
| 层3 | 在 `S_READ` 拉高 **`block_read_req`** |
| 层2 | 在 `S_WAIT` 看到 `block_read_req == 1` → 进 `S_READ_WAIT` |
| 层2 | `S_READ_WAIT`：发 `0xFF`，等收到 **`0xFE`（起始令牌）** |
| 层2 | 收到 `0xFE` → 进 `S_READ`，开始收 **512 个字节** |
| 层2 | 每收一个字节：**`block_read_valid = 1`（一拍）、`block_read_data = 该字节`** |
| 层3 | 把这两个信号**转发出去**：`sd_sec_read_data_valid = block_read_valid`、`sd_sec_read_data = block_read_data` |
| `bmp_read` | 每个字节都收下，攒成像素 |

> **⭐ 这一段就是数据的"出货口"**：512 个字节从这里流向 `bmp_read`。
> 注意 `_valid` 是**脉冲**——每 8 个 SPI 位（一个字节）来一拍。

### 阶段 5：收尾

| 谁在动 | 干什么 |
|---|---|
| 层2 | 512 字节收完（`byte_cnt == 513`）→ 进 `S_READ_ACK`，拉高 `block_read_req_ack` |
| 层3 | 看到 ack → 进 `S_READ_END`，撤销 `block_read_req` |
| 层3 | **`sd_sec_read_end = (state == S_READ_END)` 变成 1** |
| `bmp_read` | 看到 `sd_sec_read_end` → 本扇区完成 → 决定读下一个扇区还是收工 |
| 层3 | → `S_WAIT_READ_WRITE`，回去等下一次请求 |

**如果 `bmp_read` 还要读下一个扇区**：它把 `sd_sec_read_addr` 改成 1801，重复阶段 1~5。

### 4.1 一张表总结这 6 个阶段

| 阶段 | 谁发起 | 谁响应 | 走过的接口 |
|---|---|---|---|
| 0 初始化 | 层3 自己 | 卡 | 层3 → 层2 → 层1 → 卡 |
| 1 请求 | `bmp_read` | — | 第①组接口 |
| 2 组命令 | 层3 | — | 层3 内部 |
| 3 发命令等响应 | 层3 | 层2 | 第②组 → 第③组 → 第④组 |
| 4 收数据 | 层3 | 层2 | 第②组 → 第③组 → 第④组，**数据反向流回** |
| 5 收尾 | 层2 | 层3，再通知 `bmp_read` | 反向逐级上报 |

### 4.2 三个"请求-应答"嵌套在一起

**这是最容易看晕的地方**——同一次读操作里，**三层各有一次握手**，而且是嵌套的：

```
层3 ←→ 层2：  cmd_req      / cmd_req_ack        （发命令）
层3 ←→ 层2：  block_read_req / block_read_req_ack （读数据块）
层2 ←→ 层1：  spi_wr_req    / spi_wr_ack         （发一个字节，重复 500+ 次）
```

**看代码时的办法**：看到一个 `_req`，就问自己"**这是哪一层的请求？它的 `_ack` 在哪一层产生？**"

## 五、三种信号性质（看波形和写代码都要分清）

| 性质 | 行为 | 例子 | 怎么用 |
|---|---|---|---|
| **电平（举着等）** | 保持高，直到条件满足才放下 | `sd_sec_read`、`cmd_req`、`spi_wr_req` | `if (sig == 1)` 当**条件**用 |
| **重复脉冲** | 只高 **1 个时钟**，但一次事务里会**反复出现** | `sd_sec_read_data_valid`（一次读出现 512 次）、`block_read_valid`、`spi_wr_ack` | `if (sig)` 当**事件计数**用 |
| **一次性脉冲** | 只高 **1 个时钟**，且一次事务里**只出现一次** | `sd_sec_read_end`、`cmd_req_ack`、`block_read_req_ack`、`scan_found_valid` | `if (sig)` 当**完成 / 结束**用 |

> ⚠️ **勘误（2026-09-18）**：本表原先把第三类写成"电平·一次性结束"，检查题里也说"`sd_sec_read_end` 是电平" —— **不准确**。
>
> 依据源码：`assign sd_sec_read_end = (state == S_READ_END);`，而状态机里 `S_READ_END: state <= S_WAIT_READ_WRITE;` —— **下一拍就走**，所以它只高 **1 个时钟，是脉冲**（同理 `cmd_req_ack = (state == S_END)`、`block_read_req_ack = (state == S_READ_ACK)`，那些状态也都只停 1 拍）。
>
> **真正的区别不在"电平 vs 脉冲"，而在"一次事务里出现几次"**：重复脉冲要**累加计数**，一次性脉冲要当**结束条件**。这个区别直接决定你写 `if` 还是 `if/else if`。

> **为什么"请求"用电平、"应答"用脉冲？**
> **请求方不知道对方什么时候能做完**，所以要把请求**举着**等；而**应答是"我做完了"的通知，只发生一次**，用脉冲就够。
> 这就是 `cmd_req` 要"保持到 ack"的原因（第2站 `frame_read_write` 的注释也写了同一句话）。

## 六、逐层细读

### 6.1 层1：`spi_master.v` —— 只会移位

**接口就四个方向**：

```verilog
input      wr_req;      // "发一个字节"
output     wr_ack;      // "发完了"（脉冲）
input[7:0] data_in;     // 要发的字节
output[7:0] data_out;   // 同时收回来的字节
```

**状态机（6 个状态）**：

```
IDLE ──wr_req──▶ DCLK_IDLE ──┐
                    ▲        │ 数到 clk_div
                    │        ▼
                    └──── DCLK_EDGE ──数到 16 个沿──▶ LAST_HALF_CYCLE
                                                            │
                                                            ▼
                                                          ACK ──▶ ACK_WAIT ──▶ IDLE
```

| 关键点 | 说明 |
|---|---|
| **16 个时钟沿 = 8 位 × 2** | 每个 bit 需要一升一降两个沿 |
| **`wr_ack` 是脉冲** | `assign wr_ack = (state == ACK);` |
| **`ACK_WAIT` 多等一拍** | 让上游看到 `wr_ack` 后有时间撤销 `wr_req` |

**两个移位寄存器**：

```verilog
assign MOSI = MOSI_shift[7];                            // 最高位送出去
assign data_out = MISO_shift;                            // 收回来的整字节
MOSI_shift <= {MOSI_shift[6:0], MOSI_shift[7]};          // 循环左移
MISO_shift <= {MISO_shift[6:0], MISO};                   // 从右边挤进来
```

**CPOL=1 / CPHA=1** → SPI Mode 3，SD 卡要求的模式。

### 6.2 层2：`sd_card_cmd.v` —— SD 协议的"手"

**17 个状态，抓主干**：

```
S_IDLE → S_INIT ──▶ S_WAIT ──┬── cmd_req ────────▶ S_CMD_PRE → S_CMD ──┬─▶ S_END
  上电发 88 个         等上层   │                    （先发一个 0xFF）    │
  时钟给卡            指令     ├── block_read_req ─▶ S_READ_WAIT → S_READ → S_READ_ACK
                              └── block_write_req▶ S_WRITE_TOKEN → ... → S_WRITE_ACK
```

**① 上电必须"喂"至少 74 个 SPI 时钟**

```verilog
// send 11 bytes on power (at least 74 SPI clocks)
if (byte_cnt >= 16'd10) ... state <= S_WAIT;
```

发 11 个 `0xFF` = 88 个时钟（**规范要求"至少 74 个"**，多给几个更保险）。

⚠️ **别把因果说反**：卡进入 SPI 模式靠的是 **CMD0 期间把 CS 拉低**，不是靠这 74 个时钟。这 74 个时钟的作用是让卡内部完成上电准备。规范 6.4.1 节原文：

> "Device **may use up to 74** clocks for preparation before receiving the first command."
> "…start to supply **at least 74 SD clocks** to the SD card with keeping CMD line to high. **In case of SPI mode, CS shall be held to high during 74 clock cycles.**"

注意最后一句：**SPI 模式下这 74 个时钟期间 CS 必须保持高**。参考工程正好如此 —— `S_INIT` 状态里没有给 `CS_reg` 赋值，而进入前的 `S_IDLE` 已把它置成 `1'b1`。

**② 命令 = 6 个字节**

```verilog
send_data <= (cmd[47:40] | 8'h40);   // 第1字节 = 命令号 | 0x40
```

| 字节 | 内容 |
|---|---|
| 0 | `0x40 \| 命令号` —— bit7=0 起始位、**bit6=1 传输位**、低 6 位命令号 |
| 1~4 | 32 位参数（如扇区地址） |
| 5 | CRC（SPI 模式下只有 CMD0/CMD8 必须正确） |

**③ 响应轮询必须有超时**

```verilog
if((byte_cnt == 16'hffff) || (data_recv != cmd_r1 && data_recv[7] == 1'b0))
    state <= S_ERR;                    // 超时，或收到非期望响应
else if(data_recv == cmd_r1) ...       // 期望响应到了
else byte_cnt <= byte_cnt + 1;          // 继续等
```

| 条件 | 含义 |
|---|---|
| `byte_cnt == 16'hffff` | **超时**——等了 65535 个字节还没回应，报错退出 |
| `data_recv[7] == 1'b0` | **这是不是一个响应字节**（R1 的 bit7 固定为 0） |
| `data_recv == cmd_r1` | 响应值是不是上层期待的 |

**④ 数据有效信号是"闸门"**

```verilog
else if(state == S_READ && byte_cnt < 16'd512)  block_read_valid <= spi_wr_ack;
else                                            block_read_valid <= 1'b0;
```

**只在 `S_READ` 且 `byte_cnt < 512` 时有效** → **把后面的 2 字节 CRC 挡在门外**。

### 6.3 层3：`sd_card_sec_read_write.v` —— 管"什么时候发什么命令"

**初始化序列**：

```
S_IDLE → S_CMD0 → S_CMD8 → S_CMD55 → S_CMD41 ──┬─(成功)─▶ S_CMD16 → S_WAIT_READ_WRITE
                          ▲         │           │
                          └─────────┘ 未就绪就重来
```

| 命令 | 参数 | 期望响应 | 干什么 |
|---|---|---|---|
| **CMD0** | 0 | `0x01` | 复位到 SPI 模式（CRC 必须 `0x95`） |
| **CMD8** | `0x000001AA` | `0x01` | 查电压（CRC 必须 `0x87`） |
| **CMD55** | 0 | `0x01` | "下一条是 ACMD" |
| **CMD41** | `0x40000000` | **`0x00`** | **初始化**（HCS 位=支持高容量卡） |
| **CMD16** | 512 | `0x00` | 设块长度 = 512 字节 |
| **CMD17 / CMD24** | 扇区地址 | `0x00` | 单块读 / 单块写 |

**⭐ CMD41 要"反复发"**：

```verilog
end else if(cmd_req_ack) begin
    state <= S_CMD55;        // ← 失败了，回去重发 CMD55！
end
```

SD 卡初始化需要时间。第一次发 CMD41 往往返回 `0x01`（还在忙），**必须循环 CMD55+CMD41 直到返回 `0x00`**。只发一次就往下走，卡永远初始化不了。

**⭐ 先慢后快**：

| 参数 | 值 | SPI 时钟 | 阶段 |
|---|---|---|---|
| `SPI_LOW_SPEED_DIV` | 248 | 100M/(250×2) = **200 kHz** | 初始化（协议要求 ≤400kHz） |
| `SPI_HIGH_SPEED_DIV` | **0** | 100M/(2×2) = **25 MHz** | 读数据 |

### 6.4 层4：`sd_card_top.v` —— 纯连线（0 个 `always`）

和第2站的 `frame_read_write.v` 一样：**只例化和连线**。所有逻辑交给子模块。

## 七、四个额外的细节

### 细节1：SPI 时钟分频公式

```verilog
// spi clk speed = clk speed / ((SPI_LOW_SPEED_DIV + 2) * 2)
```

**换时钟频率就要重算这两个参数。**

### 细节2：一次读一张图要多久

**单个扇区**（512 字节 @ 25MHz）：`512×8 ÷ 25MHz = 163.84 µs`，加命令开销 ≈ **175 µs/扇区**。

| 分辨率 | 文件大小 | 扇区数 | **读取耗时** |
|---|---|---|---|
| 640×480 | 921,654 B | 1800 | **≈ 0.32 秒** |
| **800×600** | 1,440,054 B | 2813 | **≈ 0.49 秒** |
| 1024×768 | 2,359,350 B | 4608 | **≈ 0.81 秒** |

> **这就是为什么双缓冲是必须的**，不是加分项。没有它，切图会黑屏半秒。

### 细节3：⚠️ 上电扫描的代价

`SCAN_MAX_SECTOR = 131071`（64MB），扫描是**逐个扇区读**的。

| 图片放在哪 | 扫描耗时 |
|---|---|
| 从**扇区 0** 开始连续放 | **< 1 ms** ✅ |
| 从扇区 10,000 开始 | ≈ 1.8 秒 ⚠️ |
| 从扇区 **100,000** 开始（典型 FAT32 数据区） | **≈ 17.5 秒** ❌ |
| 一直没找到 | **≈ 22.9 秒** ❌ |

> **建议：W2 之前写一个"烧卡脚本"**，把四张 BMP 裸写到扇区 0 开始的位置。**这条要写进素材规范。**

### 细节4：⭐ 扫描可以快 9 倍

扫描为了看**前 54 字节的头**，却**读完整 512 字节**（要等 `sd_sec_read_end`）：

```
需要 54 字节 / 实读 512 字节 → 浪费 9.5 倍
```

**优化**：读到第 54 字节后头不匹配就立刻中止。**收益**：22.9 秒 → 约 2.5 秒。代价是要给 `bmp_read` 加"提前中止"，并让 `sd_card_cmd` 支持中途放弃块读。**建议列为 W7 优化项。**

## 八、一个"坏味道"

**状态编号跳号**：`S_ERR=14`、`S_WRITE_END=15`、`S_READ_END=16`、`S_WAIT_READ_WRITE=17`、`S_CMD16=18`——前面 0~8 连续，**9~13 被跳过了**。

功能没问题（5 位够用），但**看波形时分不清 9~13 到底存不存在**。

## 九、能学到什么

1. **分层设计**：底层不知道上层在干什么，所以底层可复用（层1 换个 SPI 器件照样用）
2. **全双工**：发 `0xFF` 收数据，是 SPI 的常态
3. **命令-响应协议 + 超时保护**：没有超时，卡一拔就死等
4. **先慢后快**：协议要求，不是设计者偷懒
5. **"反复重试"是协议的一部分**（CMD41），不是 bug
6. **三种信号性质**（电平/脉冲/一次性结束）要分清，否则看波形会晕
7. **多层握手嵌套**：看到 `_req` 先问"这是哪一层的"

## 十、你们的实现会不会用这个电路？

### 分两半看：**四层 SD 通信链照搬；`sd_card_bmp.v` 必须自己写。**

本站讲了 5 个文件，但**只有 4 个属于"SD 通信链"**，第 5 个是应用层 —— 两者性质完全不同：

| 层 | 文件 | 行数 | 做法 |
|---|---|---|---|
| 层1 | `spi_master.v` | 137 | ✅ **直接搬**（纯 SPI 移位器，连"SD"这个词都没出现；`CPOL` 是输入端口） |
| 层2 | `sd_card_cmd.v` | 353 | ✅ **直接搬**（SD SPI 命令层；`spi_clk_div` 是输入端口，**不硬编码**） |
| 层3 | `sd_card_sec_read_write.v` | 255 | ✅ **直接搬**（扇区读写引擎；分频是 `parameter`） |
| 层4 | `sd_card_top.v` | 127 | ✅ **直接搬**（纯连线，0 个 `always`），写侧接 0 |
| 应用层 | `sd_card_bmp.v` | 395 | ❌ **必须重写** —— 它是内容调度器，不是 SD 通信 |

**合计：872 行可直接搬，395 行要自己写。**

> ⚠️ 术语澄清：本文档上文说的"整条链"= **上面四层**。`sd_card_bmp` 在调用树上是它们的**上层**（它自己实例化 `sd_card_top`），不算"链"的一部分。

### ⚠️ 唯一要检查的参数（只针对那 4 层）

`SPI_LOW_SPEED_DIV = 248` / `SPI_HIGH_SPEED_DIV = 0`，按 `spi clk = clk / ((DIV + 2) × 2)` 配出来：

| `clk` | 低速（上电初始化） | 高速（读数据，卡的上限） |
|---|---|---|
| **100 MHz（本板 `sd_card_clk`）** | 248 → **200 kHz** ✅ | 0 → **25 MHz** ✅ |

你们的 PLL 是同一路，`sd_card_clk` 也是 100 MHz，所以**默认值直接可用**，一个字都不用改。换了时钟才需要改这两个 `parameter`，其余逻辑不受影响。

### ❌ 为什么 `sd_card_bmp.v` 不能照搬

它把**参考工程自己的应用语义**写死了，和你们要做的不是一回事：

| 写死的东西 | 在哪 | 你们的方案需要什么 |
|---|---|---|
| `SCAN_TARGET_COUNT = 3'd4` | parameter | 三组素材，张数不同 |
| `img_sector0~3` + `sector_lut()` | 内部 reg + 函数 | 自己的素材扇区表 |
| `key_next` / `key_auto` 两个按键 | 端口 | 4 个板载键，还要切 3 种模式 |
| `bmp_width`/`bmp_height` 固定传 **640×480** | 顶层实例化 | 素材要统一分辨率，但未必 640×480 |
| `state_code[3:0]` 直接喂数码管 | 端口 | 你们要 OSD / 字幕，不是数码管 |
| `key_press_debounce` 内嵌 ×2 | 内部实例 | 按键逻辑要在自己的模式状态机里 |

**但它里面有 3 块"零件"值得抄**（抄零件 ≠ 抄整体）：

1. **双缓冲指针交换 + 跨时钟域通知**：`write_buf_idx` / `disp_buf_idx` 两个 2 位索引，配 `write_finish_toggle` 三级同步 —— 这是"写缓冲写完了"通知显示侧的标准写法，**你们一定要用**。
2. **`sector_lut()` 的思路**：扇区号 → 图片索引的查表函数，三种模式都要类似的东西。
3. **扫描结果的三段式信号设计**：`scan_done`（一次性结束）/ `scan_found_valid`（脉冲）/ `scan_found_sector`（数据）—— 就是第五节讲的"三种信号性质"的实例。

### 配套还要一起搬的三站

四层链只负责"把扇区读出来"，要真显示出图片，还需要另外三站的文件：

| 站 | 文件 | 作用 |
|---|---|---|
| 第2站 | `frame_read_write.v` | 双缓冲 + 三时钟域换乘（`sd_card_bmp` 的 `write_*` 侧就接在这里） |
| 第3站 | `video_delay.v` | 读延迟补偿 |
| 第4站 | `bmp_read.v` | BMP 头解析 + 像素打包（⚠️ 要求宽高精确匹配、**宽度必须 4 的倍数**） |

| # | 影响 | 行动 |
|---|---|---|
| 1 | 一张图 0.3~0.5 秒（640×480） | **双缓冲必须做**（你们方案已有 ✅） |
| 2 | 扫描耗时取决于图片位置（最坏 22.9 秒） | **W2 前写裸写烧卡脚本**，让素材从扇区 0 开始 |

## 十一、检查题
