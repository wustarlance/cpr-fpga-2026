## 一、需求依据（先有依据，再谈技术）

### 1.1 法律依据：《中华人民共和国无障碍环境建设法》

2023 年 9 月 1 日起施行。**第三章「无障碍信息交流」有多条直接支持本作品**：

| 条款 | 原文（节选） |
|---|---|
| **第二十九条** | 各级人民政府及其有关部门应当为残疾人、老年人获取公共信息提供便利；发布突发事件信息时，条件具备的**同步采取语音、大字**、盲文、手语等无障碍信息交流方式 |
| **第三十三条** | 音视频以及多媒体设备……应当逐步具备**语音、大字等无障碍功能**。<br>**银行、医院、城市轨道交通车站、民用运输机场航站区、客运站、客运码头、大型景区等的自助公共服务终端设备，应当具备语音、大字、盲文等无障碍功能。** |
| **第四十条** | 行政服务机构、社区服务机构以及供水、供电、供气、供热等公共服务机构……应当配备**电子信息显示屏、手写板、语音提示**等设备 |
| **第四十七条** | 应急避难场所……视情况设置**语音、大字、闪光**等提示装置 |

**最有分量的是第三十三条**——它直接规定了"自助公共服务终端设备应具备语音、大字功能"。

> ✅ **本作品正是对该法条的技术实现样本。**

来源：[中国政府网 · 中华人民共和国无障碍环境建设法](https://www.gov.cn/yaowen/liebiao/202306/content_6888910.htm)

### 1.2 现实痛点：1700 万人的"最后的 30 米"

青年报 2024 年 12 月实地跟访 00 后视障人士的报道，几个关键事实：

| 事实 | 数据/描述 |
|---|---|
| **视障人群规模** | 截至 2023 年，我国有**超过 1700 万视障人士**（中国残疾人联合会统计） |
| **核心痛点** | 独自乘坐公交"仍差**最后的 30 米**"——必须靠路人或司机才能弄清面前是哪路车 |
| **最难场景** | "最大困难在于**多辆车一起进站**" |
| **心理负担** | 有视障人士"**因为担心询问会耽误别人时间而不好意思乘车**" |
| **现有方案的矛盾** | 车外喇叭播报能解决，但**外放扰民遭居民投诉**，多地取消 |

**报道里一位业内人士的建议，几乎就是我们作品的定位：**

> "可以由高科技企业作为公益项目设计一种**视障人士专用提醒设备**，这样**既不会扰民**，也能帮助到视障人士。"

来源：[青年报 · 视障人士如何"听见"公交？](http://www.why.com.cn/epublish/qnb/html/2024-12/03/content_121_28462.htm)

### 1.3 由此提炼的两条设计原则

```
① 多通道冗余：信息不能只通过视觉呈现，必须同时有语音通道
   （法律与调研共同指向"语音 + 大字"）

② 个性化终端：公共外放会扰民，所以"个人化、近场"的设备形态更合理
   （这就是本作品区别于传统信息屏的地方）
```

## 三、各技术点详细设计

### 技术点 1：点阵字模渲染引擎 ⭐ 本作品的核心

**解决什么问题**

640×480 分辨率下要显示"超大汉字"。假设一行放 4 个字，每个字需 160×160 像素。**普通字库（16×16）直接放大就是马赛克**，必须用大点阵字模。

**怎么实现**

```
① TF 卡中存放点阵字库文件（如 GB2312 编码的 48×48 点阵字库）
② FPGA 根据待显示字符的编码，计算字模在字库中的字节偏移
③ 按偏移从 TF 卡（或预载至 SDRAM 的字库区）读出字模数据
④ 将字模点阵写入帧缓存的指定位置
⑤ 经 HDMI 输出
```

**关键技术细节**

| 环节 | 要点 |
|---|---|
| **寻址** | GB2312 区位码 → 字库偏移量。公式：`offset = ((区码-1)×94 + (位码-1)) × 字节数` |
| **字库大小** | GB2312 共 6763 个汉字。48×48 点阵 = 288 字节/字 → **约 1.9 MB** |
| **存放位置** | 太大放不进 BRAM，**必须存 TF 卡，按需加载或预载到 SDRAM** |

**为什么这是核心**

- ✅ 它让作品从"图片轮播器"变成"**有渲染能力的显示终端**"
- ✅ 符合赛题"算法、控制逻辑及数据处理流程应在 FPGA 中自主编程实现"
- ✅ **直接命中扩展项 ①「图层叠加与字幕效果」**

**⚠️ 绝对不要走的路**：用 PC 把文字渲染成 BMP 图片。那属于赛题明令禁止的"算法预处理"（"不得带有额外处理器，无论用于辅助控制还是算法预处理"），而且作品会失去技术含量。

---

### 技术点 2：字形硬件缩放

**解决什么问题**

不同视力程度需要不同字号。低视力用户可能要 96×96，陪护人员看 48×48 就够。**同一套字库要能输出多种字号。**

**怎么实现**

| 方案 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **最近邻放大** | 每个像素复制 N×N | 简单、无需行缓存 | 边缘锯齿 |
| **双线性插值** | 4 邻域加权平均 | 平滑 | 需要行缓存，逻辑复杂 |

**建议**：先做**最近邻**（2 倍放大），跑通后再考虑双线性。

**顺带命中扩展项 ③「图片缩放适配」**——同一套缩放逻辑可以复用到图片上。

---

### 技术点 3：图层叠加 + 文字底衬

**解决什么问题**

文字叠在照片背景上会看不清。需要给文字加**半透明底衬**（像字幕条），保证任何背景下都能读。

**怎么实现**

```
背景图（帧缓存A） ──┐
                    ├──► 图层混合 ──► 输出
文字图层（帧缓存B） ─┘
```

混合公式（Alpha 混合）：

```
输出 = 前景 × α + 背景 × (1 - α)
```

- α = 0：完全透明（纯背景）
- α = 1：完全不透明（纯文字）
- 中间值：半透明底衬

**简化实现**：底衬可以做成固定灰度条（α 固定），不一定要动态计算。

**命中扩展项 ①「图层叠加与字幕效果」**——本题明确提到"多图层混合"。

---

### 技术点 4：色彩查表（LUT）与对比度增强

**解决什么问题**

低视力用户对**对比度**比对亮度更敏感。研究显示，低视力学生在文字与背景对比度低时会明显产生阅读困难。

**怎么实现**

在像素通路上插入一级查找表：

```
像素值 ──► [LUT] ──► 输出像素
```

- **高对比模式**：LUT 映射成"黑底黄字"或"黑白极值"
- **亮度调节**：LUT 整体缩放

**LUT 的妙处**：**不需要乘除法器，一个查找表搞定**。对于 EG4S20 这种没有 DSP 硬核的器件，这是最经济的方案。

**命中扩展项 ④「实时参数调节与 OSD 信息叠加」**（调节 + 画面上显示参数）。

---

### 技术点 5：音画同步播报

**解决什么问题**

全盲用户完全依赖语音。**每一页信息必须有一段对应的语音**，且切换页面时语音同步切换。

**怎么实现**

```
TF 卡 ──► PCM 音频文件
              │
   页面描述符表 ├──► 当前页 → 对应音轨
              │
              ▼
         I2S 打包 ──► HDMI 数据岛 ──► 显示器/音箱
```

**关键技术细节**

| 问题 | 解决 |
|---|---|
| **音画不同步** | 用统一的"页面索引"控制图和音，切换时同时更新 |
| **切换爆音** | 加音量包络（淡入淡出），避免突变 |
| **重复收听** | 加"重播"按键（视障用户可能没听清） |

**命中基础要求第 4 条「HDMI 音频输出」+ 1.3 节的"音视频联动展示"**。

---

### 技术点 6：双模式切换

**解决什么问题**

公共信息屏是给所有人看的，不能只服务视障人群。需要**一块屏两种模式**。

| 模式 | 显示 | 音频 |
|---|---|---|
| **普通模式** | 常规图文信息 | 静音或轻提示音 |
| **无障碍模式** | 超大字号 + 高对比 + 底衬 | 语音播报 |

**怎么实现**

用**参数寄存器组**统一管理两种模式的差异：

```
模式寄存器 ──┬──► 字号选择
             ├──► 对比度 LUT 选择
             ├──► 底衬开关
             └──► 语音播报开关
```

一个按键切换模式，所有参数同步变化。

**好处**：参数集中管理，后续扩展（UART/ADC 调参）只需往寄存器组里加。

---

### 技术点 7：可靠性设计

**解决什么问题**

公共设施**常年无人值守**。死机一次就是事故。

**怎么实现**

| 措施 | 解决什么 |
|---|---|
| **分级复位释放** | 等 PLL 锁定、时钟稳定后再启动数据通路，避免上电花屏 |
| **TF 卡读取超时** | 遇到损坏/非标准文件时自动跳过并恢复，不卡死 |
| **状态机超时保护** | 任何等待状态都有超时退出，避免死锁 |
| **SDRAM 刷新保障** | 保证刷新优先级，避免数据丢失 |

**参考例程里就有现成经验**——`lab_ex4_tf` 的说明文档明确提到：

> 具备完善的**上电防抖复位（POR）机制**：确保所有 PLL 完全锁定且稳定后才启动系统
> 具备 **SD 卡读取防死锁机制**：底层状态机将在 1 秒超时后自动强制中止并恢复控制权

**这条对应基础要求第 2 条的"显示稳定性与鲁棒性"**——是评分维度之一，必须做好。

---

### 技术点 8：淡入淡出转场

**解决什么问题**

画面突然切换对低视力用户是视觉冲击。**缓动过渡更友好**，观感也更好。

**怎么实现**

复用技术点 3 的 Alpha 混合通路，让 α 随时间渐变：

```
α: 0 → 1  （新页面淡入）
```

用计数器控制 α 的步进速度。

**命中扩展项 ②「图片切换与转场特效」**。

## 四、系统架构

```
  TF 卡
   ├── BMP 背景图/图标
   ├── 点阵字库（HZK 格式）
   └── PCM 语音文件
        │ SPI
  ┌─────▼──────────────────────────────────┐
  │ ① 媒体读取层                            │
  │    FAT32 目录解析 + 文件描述符表         │
  └─────┬──────────────────────────────────┘
        │
  ┌─────▼──────────────────────────────────┐
  │ ② 帧缓存层（片内 SDRAM 8MB）            │
  │    背景帧缓冲 + 文字图层缓冲 + 字库缓存   │
  └─────┬──────────────────────────────────┘
        │
  ┌─────▼──────────────────────────────────┐
  │ ③ 渲染处理层  ★ 本作品核心              │
  │    字模读取 → 字形缩放 → 图层混合 → LUT  │
  └─────┬──────────────────────────────────┘
        │
  ┌─────▼──────────────────────────────────┐
  │ ④ HDMI 输出层                           │
  │    视频时序 + 音频数据岛 + TMDS          │
  └─────┬──────────────────────────────────┘
        │
     HDMI ──► 显示器 / 音箱

  按键 ──► ⑤ 交互控制层
            · 上一页 / 下一页
            · 普通模式 ↔ 无障碍模式
            · 语音重播
```

## 五、与赛题要求的对应

### 基础要求

| 要求 | 对应 |
|---|---|
| 本地媒体资源读取 | ① 媒体读取层 |
| 稳定图像缓存与 HDMI 显示 | ② + ④ |
| 多图片交互切换 | ⑤ 交互控制层 |
| HDMI 音频输出 | ⑤ 音画同步播报 |

### 扩展要求（安路版 5 项）

| 扩展项 | 对应技术点 | 是否覆盖 |
|---|---|---|
| ① 图层叠加与字幕效果 | 技术点 3（图层叠加）+ 技术点 1（字模渲染） | ✅ |
| ② 图片切换与转场特效 | 技术点 8（淡入淡出） | ✅ |
| ③ 图片缩放适配 | 技术点 2（硬件缩放） | ✅ |
| ④ 实时参数调节与 OSD | 技术点 4（LUT）+ 技术点 6（模式切换） | ✅ |
| ⑤ 音频可视化 | — | ❌ 主动放弃 |

**覆盖 4/5 项扩展要求。** 而⑤音频可视化需要 FFT 或滤波器组，在无 DSP 硬核的 EG4S20 上性价比低，**主动放弃是理性选择**。

> **而且注意**：技术点 1、2、3 是**核心功能必需的**，做完核心功能就顺带完成了扩展项①②③。**这是选对场景的红利。**
