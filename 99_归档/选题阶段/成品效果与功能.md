# 成品效果与功能

> 本作品最终交付时，它是什么样、能做什么
> 场景：视障人士无障碍信息终端 | 平台：安路 HX4S20C（EG4S20BG256）

---

## 一、硬件形态

```
      ┌──────────────────┐
      │                  │        HDMI 线
      │   HDMI 显示器     │◄──────────────────┐
      │   （带喇叭）      │                   │
      └──────────────────┘                   │
                                             │
                              ┌──────────────┴────────┐
                              │   HX4S20C 开发板        │
                              │   ┌─────────┐          │
                              │   │ EG4S20  │  TF 卡槽 │
                              │   └─────────┘   ▲      │
                              │   [按键][按键]  │      │
                              └─────────────────┼──────┘
                                      USB 供电   │
                                              TF 卡
                                    （图片 + 字库 + 语音）
```

**整套设备**：一块开发板 + 一根 HDMI 线 + 一台带喇叭的显示器 + 一张 TF 卡 + USB 供电。

**不需要电脑，不需要网络，不需要操作系统。**

---

## 二、开机表现

插上 USB 供电后：

| 时间 | 现象 |
|---|---|
| 0.0s | 板载配置指示灯亮起 |
| 约 1~2s | **显示器出现画面**，直接开始播放第一页信息 |

**没有开机画面，没有加载进度条，没有"正在启动"。**

这是纯 FPGA 方案的核心特征——**没有操作系统，上电即显示**。

> 对比：安卓盒子开机约 30 秒，工控机约 1 分钟，且存在卡在开机画面的风险。

---

## 三、普通模式：一块正常可用的公共信息屏

默认进入普通模式，屏幕上显示一页图文信息：

```
┌────────────────────────────────────────┐
│                                        │
│   [背景图片 / 图标]                     │
│                                        │
│   3 号窗口   办理社保卡                 │
│   开放时间   9:00 - 17:00              │
│                                        │
│                                        │
│  ● ○ ○ ○                     1 / 4     │
└────────────────────────────────────────┘
```

**特点**：

- **文字由 FPGA 实时渲染**，不是预先做好的图片
- **每 5 秒自动翻页**，循环播放（周期可配置）
- 翻页采用**淡出淡入**过渡，画面连续无跳变
- 普通人、健全人看到的是一块正常的信息屏

---

## 四、无障碍模式：按一个键，整块屏幕为视障者改变

按下「无障碍模式」键后，**三项变化同时发生**：

### ① 显示变化

```
┌────────────────────────────────────────┐
│████████████████████████████████████████│
│████████████████████████████████████████│
│██                                    ██│
│██   ３ 号 窗 口                       ██│
│██                                    ██│
│██   办 理 社 保 卡                    ██│
│██                                    ██│
│████████████████████████████████████████│
└────────────────────────────────────────┘
        黑底黄字，字号放大至占满半个屏幕
```

| 变化 | 作用 |
|---|---|
| 背景简化为纯色 | 去除视觉干扰 |
| 字号放大 3~4 倍 | 低视力用户可辨认 |
| 对比度提升至最高 | 低视力对**对比度**比对亮度更敏感 |

### ② 语音同步播报

音箱中同步开始播报：

> "3 号窗口，办理社保卡。开放时间，9 点到 17 点。"

### ③ 音画严格同步

切换页面时，**画面与语音同时切换**，不会出现"画面是第 3 页、声音念的是第 2 页"。

---

## 五、交互操作

三个按键：

| 按键 | 功能 |
|---|---|
| **上一页 / 下一页** | 切换信息页 |
| **模式切换** | 普通模式 ↔ 无障碍模式 |
| **重播** | 语音重新播报当前页（视障用户可能没听清） |

---

## 六、演示脚本（约一分钟）

| 步骤 | 操作 | 现象 |
|---|---|---|
| ① | 插电 | 显示器 2 秒内亮起，开始自动轮播 |
| ② | 按键切页 | 页面淡出淡入，流畅切换 |
| ③ | 按「无障碍」键 | 屏幕变为大字高对比，**语音同步响起** |
| ④ | 按下一页 | 大字页面切换，语音自动切换到新内容 |
| ⑤ | 按「重播」键 | 语音重新播报当前页 |
| ⑥ | 切回普通模式 | 恢复常规显示，普通人同样可用 |
| ⑦ | 静置观察 | 连续运行不花屏、不卡死 |

**第 ⑦ 步是评分关键**——对应基础要求中的「显示稳定性与鲁棒性」。

## 七、技术指标

| 项目 | 指标 |
|---|---|
| 分辨率 | 640×480 @ 60Hz |
| 媒体来源 | TF 卡（FAT32 文件系统） |
| 图片 | ≥ 4 幅，自动扫描、识别与装载 |
| 字库 | GB2312 点阵字库，**FPGA 内实时渲染** |
| 缩放 | 字形硬件放大（最近邻 2~3 倍） |
| 音频 | PCM 经 I2S 打包，随 HDMI 数据岛输出 |
| 显示效果 | 图层叠加、文字底衬、淡入淡出转场 |
| 参数调节 | 字号 / 对比度 / 模式，按键实时切换 |
| 可靠性 | 上电分级复位、SD 读超时保护、异常自恢复 |
| 资源占用 | 待实测 |

## 八、技术含量体现在哪里

**外行看到的**：一个能显示大字、会说话的屏幕。

**行内评委能看到的**：

| # | 技术点 | 含金量 |
|---|---|---|
| 1 | **字模是 FPGA 实时渲染的**，不是做好的图片 | 有真实的**渲染引擎** |
| 2 | **图层是硬件叠加的** | 有**像素处理通路** |
| 3 | **音画严格同步** | 有统一的**资源调度机制** |
| 4 | **上电分级复位、异常自恢复** | 考虑了**工程可靠性** |
| 5 | **全程没有第二颗处理器** | 符合赛题硬性要求 |

## 九、与赛题要求的对应

### 基础要求（全部覆盖）

| 要求 | 实现 |
|---|---|
| 本地媒体资源读取 | TF 卡 + FAT32 + BMP 解码 |
| 稳定图像缓存与 HDMI 显示 | SDRAM 帧缓存 + TMDS 输出 |
| 多图片交互切换 | 三按键控制状态机 |
| HDMI 音频输出 | PCM + I2S + 数据岛 |

### 扩展要求（覆盖 4/5）

| 扩展项 | 实现 | 覆盖 |
|---|---|---|
| ① 图层叠加与字幕效果 | 字模渲染 + 图层混合 | ✅ |
| ② 图片切换与转场特效 | 淡入淡出 | ✅ |
| ③ 图片缩放适配 | 字形硬件缩放 | ✅ |
| ④ 实时参数调节与 OSD | LUT 对比度 + 模式切换 | ✅ |
| ⑤ 音频可视化 | — | ❌ 主动放弃 |

> **说明**：扩展项 ①②③ 的实现在本项目里是**核心功能必需的**（没有字模渲染，无障碍场景不成立），因此属于"做核心功能顺带完成扩展项"。

## 十、作品的社会价值

```
法律要求      《无障碍环境建设法》第 33 条：
               自助公共服务终端应具备语音、大字功能
                        ↓
现实痛点      1700 万视障人士；公共信息屏对他们完全无效
                        ↓
现有方案缺陷  外放喇叭能解决，但扰民遭投诉，多地取消
                        ↓
本作品        个人化终端 + 语音大字双通道 + 近场播放
              → 既不扰民，又能帮助视障人士
```

**一句话**：

> 普通人看，它是一块正常的公共信息屏；
> 按一下键，它就为视障人士变成"大字 + 语音"的无障碍终端。
> 全部逻辑在一颗 FPGA 内运行，没有操作系统，不怕死机，插电就用。
