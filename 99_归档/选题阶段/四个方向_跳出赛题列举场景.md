# 四个方向：跳出赛题列举场景，但天然覆盖全部要求

> 赛题 1.2 列举了五个场景（数字广告牌、商业展陈终端、应急信息发布、车载辅助显示、教育演示）。
> 本文**全部避开这五个**，但不跑偏——靠的是一条选场景的原则，而不是换题材。

---

## 一、选场景的原则（这才是"创新"的地方）

不要先想"要做什么产品"，而是先找**本来就需要"画面 + 文字 + 声音"同时在场**的场景。

理由很直接：

| 扩展要求 | 在"只有画面"的场景里 | 在"画面+文字+声音"的场景里 |
|---|---|---|
| ① 图层叠加与字幕 | 要**硬凑**一个理由加字幕 | **本来就该有字幕** |
| ⑤ 音频可视化 | 要**硬凑**一个理由放音乐 | **本来就在放音乐** |
| ④ 亮度调节 + OSD | 要编"为什么要调" | 环境光真在变 / 模式真在切 |
| ③ 缩放 | 不一定用得上 | 要看细节 |
| ② 转场 | 锦上添花 | 内容切换天然需要 |

**一句话**：选一个"声音和画面本来就绑在一起"的场景，五项扩展全部变成刚需，不用为凑分硬塞功能。

下面四个方向都是按这条原则筛出来的。

---

## 二、方向一：舞台演出提词与画面终端 ★ 推荐

| 项 | 内容 |
|---|---|
| **场所** | 校园晚会、婚礼现场、企业年会、小型剧场、会议室 |
| **用户** | 主持人、演讲者、演出团队、会务人员 |
| **现在怎么做** | 笔记本接投影：接线多、开机慢、现场断电就黑屏；提词器还要另配一台设备 |
| **痛点** | 忘词；节目背景画面要跟着换；舞台灯光来回变；没人有空盯电脑 |

**为什么它天生适合**

| 要求 | 在舞台场景里是什么 |
|---|---|
| 基础1 核心功能 | 背景画面多幅播放 + HDMI 输出 + 按键控制 |
| 基础2 稳定性 | 无操作系统，**上电即出画面**；演出现场断电来电立刻恢复，不用等人开机 |
| 基础3 **音频输出** | 背景音乐经 I2S/HDMI 输出 |
| 基础4 工程规范 | 模块化 + 时序约束 + 双缓冲 |
| 扩展① | **提词就是滚动字幕**——这是滚动字幕最自然、最刚需的形态，还要支持**速度可调与暂停** |
| 扩展② | 节目之间淡入淡出 / 滑动切换 |
| 扩展③ | 看不清就把字号放大 |
| 扩展④ | **舞台灯光从全暗到全亮反复变化**，亮度对比度必须可调，OSD 显示当前档位 |
| 扩展⑤ | **背景音乐的频谱随节奏起伏**，本身就是演出氛围的一部分 |

**FPGA 优势体现**：**提词的滚动延迟必须确定**——通用方案里滚动一卡顿，演讲者立刻跟丢。FPGA 由像素时钟直接驱动滚动位置，**每一帧位移严格相等**，不存在软件调度抖动。这正是赛题说的"更确定的时序、更低的显示延迟"。

**难度**：中低（提词滚动 = 地址偏移；画面 = 多图层合成）

**名称候选**：`舞台提词与画面终端`（9字）／`演出提词显示终端`（8字）／`提词与画面合成终端`（9字）

## 三、方向二：乐谱与节拍显示终端

| 项 | 内容 |
|---|---|
| **场所** | 琴行、音乐教室、合唱团排练厅、社区文艺队 |
| **用户** | 音乐教师、学生、合唱团员 |
| **现在怎么做** | 纸质乐谱手工翻页；节拍器另配一台；音准靠耳朵 |
| **痛点** | 翻谱打断演奏；节拍器与谱子分离；排练时看不清小节 |

**为什么它天生适合**

| 要求 | 在音乐教学场景里是什么 |
|---|---|
| 基础1/2/3/4 | 多幅乐谱播放、HDMI 输出、音频输出、长期运行 |
| 扩展① | **乐谱自动滚动翻页 + 歌词字幕**——翻页就是滚动，教学刚需 |
| 扩展② | 曲目切换转场 |
| 扩展③ | 放大某一个小节或某一行 |
| 扩展④ | 排练厅光线不同，亮度对比度可调，OSD 显示档位 |
| 扩展⑤ | **音频频谱 / 节拍指示**——这直接就是教学工具，不是装饰 |

**FPGA 优势体现**：**音画同步**——赛题原话里的"音画同步及多源信息融合"。频谱必须与正在播放的音频**严格同拍**，通用方案里音频缓冲与视频渲染在不同线程，对不上；FPGA 可以把音频数据流与视频时序挂在同一套计数基准上，天然同步。

**技术提示**：不需要音频输入。直接从"送往 I2S 的 PCM 数据流"上抽一路做滤波器组即可。

**难度**：中（滤波器组是唯一的"新东西"）

**名称候选**：`乐谱与节拍显示终端`（9字）／`音乐排练显示终端`（8字）／`乐谱滚动显示终端`（8字）

## 四、方向三：社区健身教学显示终端

| 项 | 内容 |
|---|---|
| **场所** | 社区广场、公园、健身步道、乡镇文体站 |
| **用户** | 社区居民、广场舞领队、文体站管理员 |
| **现在怎么做** | 领队自带音响和纸质动作图；动作要领靠口传 |
| **痛点** | 户外光线从早到晚变化极大；无人值守，设备要能常年开；供电不方便 |

**为什么它天生适合**

| 要求 | 在社区健身场景里是什么 |
|---|---|
| 基础1/2/3 | 动作分解图多幅播放、HDMI 输出、音乐输出；**无人值守长期运行** |
| 扩展① | 动作要领**滚动字幕** + 关键部位**标注层**叠加在动作图上 |
| 扩展② | 动作分解图轮播转场 |
| 扩展③ | 放大看某个动作细节 |
| 扩展④ | **户外光线从清晨到夜晚跨度极大**，亮度对比度必须可调 |
| 扩展⑤ | **音乐节拍可视化**，帮队员跟节拍 |

**FPGA 优势体现**：**低功耗 + 高可靠性**——无操作系统意味着常年不关机也不会死机；功耗低，可配太阳能板与蓄电池，解决户外供电问题。

**难度**：低

**名称候选**：`社区健身教学显示终端`（10字）／`户外健身指导终端`（8字）／`广场健身教学终端`（8字）

## 五、方向四：门店叫号与菜单显示终端

| 项 | 内容 |
|---|---|
| **场所** | 快餐店、茶饮店、单位食堂、社区食堂 |
| **用户** | 店员、顾客 |
| **现在怎么做** | 叫号靠喊；菜单贴在墙上，更新要重印；音响单独一台 |
| **痛点** | 嘈杂环境听不见叫号；菜单换季就要重做；柜台上设备越堆越多 |

**为什么它天生适合**

| 要求 | 在门店场景里是什么 |
|---|---|
| 基础1/2/3 | 菜单图多幅播放、HDMI 输出、音频输出；**营业时间全程开机** |
| 扩展① | **叫号号码与提示语滚动/闪烁**——嘈杂环境下必须靠"看得见"补"听不见" |
| 扩展② | 菜单图轮播转场 |
| 扩展③ | 放大某个菜品图 |
| 扩展④ | 白天与夜间亮度不同，可调并显示档位 |
| 扩展⑤ | 背景音乐频谱，商业氛围 |

**FPGA 优势体现**：**多图层并行合成**——叫号层、菜单层、字幕层、频谱层四层同时在线，FPGA 逐像素并行取层合成，不受图层数量拖累。

**难度**：低

**名称候选**：`门店叫号与菜单显示终端`（11字）／`叫号与菜单合成终端`（9字）／`门店信息显示终端`（8字）

| **① 舞台提词与画面** | ✅ **提词刚需** | ✅ | ✅ | ✅ **灯光剧变** | ✅ **氛围刚需** | **5** | **高** | 中低 |
| **② 乐谱与节拍** | ✅ **翻页刚需** | ✅ | ✅ | ✅ | ✅ **教学工具** | **5** | **高** | 中 |

## 七、推荐

| 想要什么 | 选它 | 理由 |
|---|---|---|
| **最创新、FPGA 优势最好讲** | **① 舞台提词与画面** | "滚动延迟必须确定"是通用方案做不到、FPGA 天然擅长的点；评委一听就懂，不需要背景知识 |
| **技术最有含量** | **② 乐谱与节拍** | 音画同步是赛题原话里的优势项；音频滤波器组是真功夫 |
| **风险最低** | **③ 社区健身** 或 **④ 门店叫号** | 功能与"最小可行方案"几乎重合，素材也好准备 |
| **社会意义最强** | **③ 社区健身** | 面向社区居民与文体站，公共文化服务属性 |

**我的建议：① 舞台提词与画面终端。**

三个理由：

1. **一句话就能讲清 FPGA 的价值**：*提词的滚动不能抖，通用方案会抖，FPGA 不会。* 不用解释什么是并行流水线。
2. **完全避开赛题列举的五个场景**，而且不撞车——提词器是真实产品，但没人用 FPGA 做，更没人把提词和舞台画面合到一台设备上。
3. **五项扩展全部是场景刚需**，答辩时不需要为任何一项找理由。

## 八、共同技术底座（四个方向完全一样）

| 模块 | 来源 | 对应要求 |
|---|---|---|
| PLL 时钟 | IP | 基础 |
| HDMI 发送 + 视频时序 | 加密 IP + 官方例程 | 基础1 |
| SD 卡 SPI + FAT32 | 参考工程改写 | 基础1 |
| BMP 解析 | 自己写 | 基础1 |
| SDRAM 控制器 + 双缓冲 | IP + 参考工程 | 基础1/2 |
| **多图层合成器** | 自己写 | 扩展① |
| **滚动字幕生成** | 自己写（地址偏移） | 扩展① |
| 转场控制 | 自己写 | 扩展② |
| 缩放引擎（相位累加） | 自己写 | 扩展③ |
| 亮度 / 对比度 + OSD | 自己写 | 扩展④ |
| I2S 音频输出 | 参考工程 | 基础3 |
| 音频滤波器组 + 频谱绘制 | 自己写 | 扩展⑤ |
| 按键消抖 | 参考工程 | 基础1 |

> **换方向 = 换 SD 卡素材 + 换宣传口径，代码基本不动。**
> 所以可以先用风险最低的场景（③或④）打通全流程，再切到最想讲的方向（①）参赛。
