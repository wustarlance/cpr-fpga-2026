# 最简可行方案：把功能砍到只剩必要的

> 前面几版把功能越加越多（曲线、仪表、流程图、时间轴回放、多成像融合），确实超出了一个 7 周项目的合理范围。
> 本文把复杂度拆开，指出**哪些绕不过去、哪些可以砍**，并给出一个最简方案和三段式计划。

---

## 一、先看清：复杂在哪

### 1.1 基础设施（绕不过去，但参考工程已有）

| 模块 | 来源 | 难度 |
|---|---|---|
| 时钟（PLL） | IP，配置即可 | 低 |
| HDMI 发送 | **加密 IP + 官方例程**，照抄 | 低 |
| 视频时序（hs/vs/de） | 参考工程有现成代码 | 低 |
| SD 卡 SPI 读取 | 参考工程有现成代码 | 中 |
| FAT32 文件定位 | 参考工程有现成代码 | 中 |
| 图像缓存（片内 SDRAM 控制器） | IP，配置即可 | 低 |
| 双缓冲 / 异步 FIFO | IP + 参考工程封装 | 中 |
| 按键消抖 | 参考工程有现成代码 | 低 |

> **关键结论**：这些**全部有参考**。参考工程 `lab_ex5_i2s` 里都有对应模块，照结构改写、IP 用 TD 6.2.3 重新生成即可。
> **从零写的只有一样：图像缩放。** 那才是真正的工作量。

### 1.2 我们之前加的功能（这些才是"复杂"的来源）

| 功能 | 要写什么 | 建议 |
|---|---|---|
| 实时缩放 / 平移 | 行缓存 + 插值 + 坐标计算 | **保留**（唯一的技术亮点） |
| 双层透明叠加 | 透明色键控 + 混合 | **保留**（赛题明确要求） |
| 音频播放 | I2S，参考工程有 | 可保留（成本低） |
| 音频可视化 | 滤波器组 + 渲染 | **砍** |
| 趋势曲线 | 环形缓存 + 逐列绘制 | **砍** |
| 仪表指针 | 三角函数 + 圆弧绘制 | **砍** |
| 工艺流程图 | 多图层 + 报警联动 | **砍** |
| 时间轴回放 | 状态缓存 + 重放逻辑 | **砍** |
| 多成像融合 | 多通道配准 + 伪彩映射 | **砍** |

**砍完之后剩下的是**：多幅图像播放 + 双层透明叠加 + 按键 + 实时缩放平移 + 音频。
**这恰好完整覆盖赛题要求**（多幅播放 ✅ 透明叠加/透明色处理 ✅ ≥2 按键 ✅ 扩展项平移/局部放大 ✅）。

## 二、最简方案

### 2.1 一句话

> 一台**没有操作系统的离线影像阅览器**：从 SD 卡读图，HDMI 输出，按键切换、叠加比对、放大看细节。

### 2.2 功能清单（就这四项）

| # | 功能 | 按键 | 说明 |
|---|---|---|---|
| 1 | 多幅图像轮播 | 按键 1：上一幅 / 下一幅 | 覆盖赛题"多幅播放" |
| 2 | 双层透明叠加 | 按键 2：叠加层开关 | 图层 2 以**透明色键控**叠加到图层 1，覆盖赛题"透明叠加 / 透明色处理" |
| 3 | 实时缩放 | 按键 3：放大 / 缩小 | 覆盖赛题扩展项"局部放大" |
| 4 | 实时平移 | 按键 4：上下左右移动 | 覆盖赛题扩展项"平移" |

**就这些。** 没有曲线、没有仪表、没有时间轴、没有音频可视化。

### 2.3 技术难度（诚实评估）

| 部分 | 难度 | 说明 |
|---|---|---|
| HDMI 点亮 | 低 | 加密 IP + 例程，照抄 |
| 显示第一张图 | 中 | 打通 SD → 缓存 → 输出链路，**这是第一个里程碑** |
| 多图切换 | 低 | 参考工程的双缓冲机制 |
| 透明叠加 | 中 | 透明色键控逻辑简单 |
| **实时缩放** | **中高** | **全项目唯一没有参考的部分**，也是唯一的亮点 |

**风险集中在一处**：实时缩放。其余都能照参考工程改。

## 三、三段式计划（保底 → 完整 → 加分）

这样安排的好处是：**每一段结束都有一个能演示的成果**，不会到最后什么都交不出来。

### 第一段：点亮与单图显示（保底线）
- 目标：HDMI 输出彩条 / 单张图片
- 交付：**能上电演示**
- 用到的都是现成模块（PLL、HDMI、时序）

### 第二段：满足赛题（及格线）
- 目标：SD 卡读多幅图 + 按键切换 + 双层透明叠加
- 交付：**完整覆盖赛题硬性要求**
- 参考工程的双缓冲与图层结构直接复用

### 第三段：加分项（冲刺线）
- 目标：实时缩放与平移
- 交付：**唯一的技术亮点**
- 若时间不足，可退而求其次做"固定倍率切换"（2×/4×）而不是无级缩放，实现难度立刻下降一半

> **重要建议**：第三段如果吃紧，**优先保证第二段扎实**。赛题硬性要求全部满足 + 演示稳定，比"有亮点但跑不起来"得分高得多。

## 四、场景：换个 SD 卡就换个场景

这套功能集**不绑定场景**——硬件和逻辑完全一样，只换 SD 卡里的内容：

| 场景 | SD 卡里放什么 | 按键 2 的叠加层是什么 |
|---|---|---|
| 展馆 / 博物馆 | 文物高清图 | 线图或拓片 |
| 教室 | 教学挂图 | 标注层 |
| 办公 | 产品外观图 | 尺寸标注层 |
| 家庭 | 照片 | 说明文字 |

**这本身就是"内容与硬件解耦"的演示**：换一张卡，同一台设备变成另一个产品。答辩时这是很好讲的一点。

**建议的包装**：主推 **展馆 / 博物馆的文物影像阅览**（有行业调研支撑，且内容好找），其余场景作为"可复用性"的说明。

## 六、作品简介（上限 500 字，**含换行符**，已逐字核算）

### ★ A_推荐版 —— 约 350 字

```
本作品是一台离线影像阅览终端，用一台没有操作系统的设备播放高清图像并支持细节查看。以国产安路EG4S20为核心，从SD卡读取图像文件，经HDMI直驱显示设备。
终端提供四项按键操作：切换图像、开关第二图层、放大与缩小画面、上下左右平移。第二图层以透明色键控方式叠加在原图上，可用于显示线图、标注或文字说明；缩放与平移全部在FPGA内逐帧实时完成，放大后的画面依然清晰，不存在播放器放大发虚的问题。
设备不含任何处理器，不依赖操作系统与网络，上电即出画面，功耗低。更换内容只需替换SD卡中的图片与说明文件，无需重新综合与烧写——换一张卡，同一台设备即可服务于展馆、教室或办公场景。
作品完整覆盖题目要求的多幅图像播放、透明叠加与透明色处理、按键交互，并实现了图片的实时缩放与平移。
```
