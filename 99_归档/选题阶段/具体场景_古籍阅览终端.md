# 具体应用场景规格：古籍阅览室的离线影像阅览终端

> 给最简功能集（多图轮播 / 透明叠加 / 缩放 / 平移 / 按键）配一个**具体到场所、人、动作、素材**的场景。
> 结论：**古籍阅览**比"博物馆"更具体，而且依据更硬——官方平台的说明里直接写了"放大镜、局部细看"。

---

## 一、场景一句话

> **图书馆古籍阅览室里，一台不用电脑、不用网络、上电就亮的屏，把古籍影像放大到笔画级别，并把现代释文叠在原影上逐字对照。**

---

## 二、场所与人

| 项 | 内容 |
|---|---|
| **场所** | 图书馆古籍阅览室（阅览台 / 展柜旁）、博物馆古籍专题展厅、高校文史专业教室 |
| **用户** | 查阅古籍的研究者与学生；展厅里的普通参观者 |
| **使用时间** | 开馆时段，**无人值守** |
| **设备形态** | 一块带 HDMI 的显示屏 + 一个四按键盒 + SD 卡槽，嵌入阅览台或装在展柜侧面 |
| **供电** | 5V 适配器；展柜无插座时可用 USB 电源或太阳能 + 蓄电池 |

## 三、现在怎么做，问题在哪（引官方原文）

### 3.1 古籍数字化的供给已经很足

- 全国已累计发布古籍及特藏文献影像资源 **超 16.1 万部/件**
- 国家图书馆牵头、联合 **全国 180 余家古籍收藏单位**建设的「中华古籍智慧化服务平台」，已发布 **1.3 万余种 14 万余册**，**网站访问量突破 1000 万次**，并上线了自动句读、文白对照翻译等功能
- 自 2017 年起已进行 **11 次**古籍数字资源联合发布

来源：[人民日报海外版 2026-01-22《足不出户畅游古籍海》](http://paper.people.com.cn/rmrbhwb/pc/content/202601/22/content_30134713.html)

### 3.2 但阅览方式被绑在"电脑 + 网络"上

北京大学中文系张剑教授在描述国家图书馆「中华古籍资源库」时写道：

> 「采用 **web 浏览**的方式，免注册登录，不给看书设任何技术门槛，可以直接在线阅读，也可以在线比勘多种、多册古籍；**可以设置放大镜，以便局部细看**……」

来源：[中国古籍保护网 · 名家讲坛](https://www.nlc.cn/pcab/zy/pxjz/20240827_2640900.shtml)

**两个关键信息**：

1. **「放大镜、局部细看」是官方平台自己标出来的核心功能** —— 说明这个需求是真实且被认可的，不是我们编的
2. **它依赖浏览器、电脑和网络** —— 在阅览室、展厅、教室这些地方，多一台电脑就多一份采购、维护和故障

### 3.3 而且古籍最需要的恰恰是"看清"

同一篇里另有一段：

> 「大部分近代日记属于**书写潦草的稿本**；且个人书写习惯和行草字体的变化多端，**现有的数字化技术尚不能对其进行有效的文字识别**。」

也就是说：**机器认不出来，只能靠人眼看**——那"看得清"就成了唯一的技术出路。

## 四、我们的屏和"电脑网页端"的差别

| | 电脑 + 网页端 | 本终端 |
|---|---|---|
| 联网 | 必须 | **不需要** |
| 启动 | 开机 + 打开浏览器 + 登录/检索 | **上电即出画面** |
| 放大 | 网页缩放，放大到一定倍数就发虚 | **硬件级实时缩放，逐帧重算** |
| 释文对照 | 需要切页面或另开窗口 | **原影 + 释文同屏透明叠加，逐字对齐** |
| 维护 | 系统、补丁、病毒、授权 | **无操作系统，无这些失效路径** |
| 功耗 | 数十瓦至上百瓦 | **低一个数量级** |
| 更新书目 | 后台/网络 | **换一张 SD 卡** |

## 五、一次完整的使用动作（这是"具体"的核心）

设备待机时显示当前书目的封面与页码。四个按键：

| 按键 | 动作 | 屏幕变化 |
|---|---|---|
| **翻页** | 上一页 / 下一页 | 切换古籍影像，页面淡入 |
| **放大** | 2× → 4× → 8× → 1× 循环 | 以画面中心为基准逐级放大，各倍数间平滑过渡 |
| **方向** | 上 / 下 / 左 / 右 | 放大后平移视野，查看页面任意局部 |
| **叠加** | 释文层 开 / 关 | 现代楷书释文以半透明方式浮在原影上，与原字逐字对齐 |

**一条真实的读者路径**：

> 读者翻到第三页 → 有个字认不出 → 按【放大】两次到 4× → 笔画清楚了但还不确定 → 按【叠加】，释文层浮上来，对着原字确认是"遽" → 按【方向】往右推，继续读下一句 → 按【叠加】关掉释文，继续看原影。

**全部动作都在四个按键里完成，不需要鼠标、不需要键盘、不需要联网。**

## 六、答辩现场演示脚本

| 时间 | 操作 | 观众看到 |
|---|---|---|
| 0:00 | 上电 | **屏幕立刻亮起**（对比电脑开机要几十秒） |
| 0:05 | 按【放大】×3 | 行草手稿放大到 8×，某个认不出的字的起笔、转折、收笔逐层显出 |
| 0:15 | 按【叠加】 | 楷书释文层淡入，与原字**逐字对齐** |
| 0:25 | 按【方向】 | 画面平移到下一句，释文层同步跟随 |
| 0:35 | 按【翻页】 | 切到另一部古籍，展示多幅播放 |
| 0:45 | 按【叠加】数次 | 演示透明色键控与图层开关 |

> **一个动作证明技术**：按【放大】的瞬间画面**逐帧重算**，没有任何视频能做到"任意倍数、任意位置"。

## 七、素材来源（可操作清单）

| 素材 | 来源 | 备注 |
|---|---|---|
| **古籍影像** | **中华古籍资源库**（国家图书馆，**免注册登录**） | 可直接在线阅览，取图方便 |
| 更多影像 | 各省级图书馆古籍数字资源、国家珍贵古籍名录相关资源 | 多地已免费开放 |
| **释文文本** | 公开的整理本、标点本；或自己录入 | **只需文本，不需要图片** |

### ⚠️ 关键做法：释文层必须"实时渲染"，不能贴图

**不要**把释文做成一张透明底的 PNG 贴上去。正确做法：

> SD 卡里只存**释文文本 + 逐字坐标表**，由 FPGA 用**片内点阵字库实时渲染**出释文层，再叠加到原影上。

这样做的三个好处：

1. **完全符合赛题红线**（"不得算法预处理"）——释文是算出来的，不是预先渲染的
2. **释文字号可以随放大倍数调整**，放大后更清晰
3. **换书只需换文本文件**，素材准备量极小

> 建议演示 1 部古籍、约 10~20 页，配 2~3 页释文即可，不必贪多。

## 十一、同一台设备的其他场景（换卡即换）

硬件与逻辑完全不变，只换 SD 卡内容：

| 场景 | SD 卡内容 | 叠加层 |
|---|---|---|
| **古籍阅览**（推荐） | 古籍影像 + 释文文本 | 现代释文 |
| 博物馆文物 | 文物高清图 | 线图 / 拓片 |
| 文史教学 | 教学挂图 | 标注层 |
| 工业现场 | 设备图纸 | 尺寸 / 零件标注 |

**这本身就是"内容与硬件解耦"的最好证明**：一台设备，换一张卡，就是一个新产品。答辩时这是很好讲的一点。
