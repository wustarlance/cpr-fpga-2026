还有：`子卡需自行购买，只提供主平台`——扩展子卡自费。

## 二、参赛内容简述（详细版，可直接粘贴）

> 表单要求"需详细描述，如太简单可能会影响申请"。
> 下面这版约 750 字，覆盖了资格审查的全部五个维度。

```
本队申请安路赛道选题一（HX4S20C 平台），拟设计并实现一套面向数字
展陈场景的 FPGA 音视频多媒体播放终端。

【系统方案】
系统采用分层解耦架构，自上而下分为五层：

① 媒体读取层：通过 SPI 接口读取 TF 卡，解析 FAT32 目录结构，自动
扫描并装载多幅 640×480 24bit 图像，完成 BMP 格式解码；

② 帧缓存层：以片内 SDRAM（2M×32bit）作为整帧缓存，设计缓冲区调
度策略，保证图片切换过程连续、无撕裂；

③ 像素处理层：在帧缓存与显示输出之间插入可配置的像素处理流水线，
为转场特效、亮度对比度调节等扩展功能预留结构；

④ HDMI 输出层：生成 640×480@60Hz 视频时序，完成 TMDS 编码输出；
音频数据经 I2S 打包后以数据岛形式随 HDMI 输出，实现音视频一体播放；

⑤ 交互控制层：板载按键经消抖处理后驱动控制状态机，实现手动切换
与自动轮播，且轮播周期可配置。

【关键技术点】
· 时钟与复位：设计分级复位释放机制，确保各时钟域稳定后再启动数据
  通路，从源头规避上电花屏问题；
· 跨时钟域处理：视频、音频、存储等不同时钟域之间采用异步 FIFO 隔离，
  保证数据传输可靠；
· 异常鲁棒性：TF 卡读取设置超时保护，遇到损坏或非标准格式图片时自动
  跳过并恢复控制权，不阻塞主流程。

【团队基础与已完成工作】
本队三名队员均为"一生一芯"（YSYX）芯片设计培养计划学员，系统学习
数字系统设计，具备 Verilog RTL 设计、功能仿真验证与逻辑综合实现的
完整流程经验。

备赛前期，团队已完成以下准备工作：
1. 完成安路 TangDynasty（TD）6.2.3 工具链在 Linux 平台的完整部署，
   包括工具链安装、许可证配置与下载器权限配置；
2. 使用安路官方示例工程，完整跑通"引脚约束→时序约束→综合优化→
   布局布线→位流生成"的全流程，已成功生成可下载的位流文件；
3. 完成主时钟时序约束的设计与验证，掌握了 SDC 约束的基本方法。

团队已具备立即进入功能开发的条件，不存在工具链层面的未知风险。

【预期成果】
确保完成全部基础要求（媒体读取、稳定 HDMI 显示、按键交互、HDMI
音频输出），并力争实现"图片切换与转场特效""实时调节与信息叠加"
两项扩展功能。
```

## 三、这份简述对应资格审查的哪一条

| 审查维度 | 在简述里对应哪部分 |
|---|---|
| **创新性** | 分层解耦架构、帧缓存调度、像素处理流水线自主设计 |
| **科学性** | 五层架构划分、"各层独立设计与验证"的思路 |
| **工程可行性** | ⭐「团队基础与已完成工作」——已跑通全流程至位流生成 |
| **设计难度** | SDRAM 帧缓存管理、HDMI 时序生成、音视频一体、跨时钟域 |
| **平台适用度** | 系统整体基于 FPGA 实现，涉及并行处理与确定性时序 |

**"已完成工作"这一段是这份申请最值钱的地方**——它把"我们计划做"变成了"我们已经开始做，并且跨过了工具链这道坎"。
