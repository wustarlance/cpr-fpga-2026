## 三、系统架构与实现思路

> 说明：以下为本队的总体设计思路。具体模块的详细设计将在研读安路官方资料与参考例程后细化。

### 3.1 总体架构

系统采用**分层解耦**的架构，各层之间通过明确定义的接口通信：

```
  ┌─────────┐
  │  TF 卡  │
  └────┬────┘
       │ SPI
  ┌────▼─────────────────┐
  │  ① 媒体读取层         │  扇区读取 + FAT32 目录解析 + BMP 解码
  └────┬─────────────────┘
       │ 像素流
  ┌────▼─────────────────┐
  │  ② 帧缓存层           │  SDRAM 帧缓存管理 + 缓冲调度
  └────┬─────────────────┘
       │
  ┌────▼─────────────────┐
  │  ③ 像素处理层         │  可配置的像素处理流水线
  └────┬─────────────────┘
       │
  ┌────▼─────────────────┐
  │  ④ HDMI 输出层        │  视频时序生成 + 音频打包 + TMDS 输出
  └────┬─────────────────┘
       │
    HDMI ──► 显示器

  按键 ──► ⑤ 交互控制层 ──► 指挥 ①~④
  音频 ──► I2S 打包 ──────► 汇入 ④
```

**分层的好处**：每一层可以独立设计、独立验证，出问题容易定位。

### 3.2 分阶段实施计划

| 阶段 | 目标 | 判据 |
|---|---|---|
| **一** | 环境与流程打通 | ✅ **已完成** |
| **二** | 视频通路点亮 | 显示器出现画面 |
| **三** | 媒体读取与帧缓存 | 显示 TF 卡中的图片 |
| **四** | 交互控制与音频 | 按键切图 + HDMI 出声 |
| **五** | 稳定性与扩展功能 | 连续运行不花屏 + 完成扩展项 |

### 3.3 关键技术路线

**时钟与复位**：设计分级复位释放机制，确保各时钟域稳定后再启动数据通路，从源头规避上电花屏问题。

**帧缓存管理**：以片内 SDRAM（2M×32bit）作为整帧缓存，配合缓冲区调度策略实现图片切换过程连续无撕裂。

**像素处理**：在帧缓存到 HDMI 之间插入可配置的像素处理流水线，为扩展功能（转场特效、参数调节）预留结构。

**音频通路**：音频数据与图片资源关联管理，通过 I2S 接口打包后以数据岛形式随 HDMI 输出。

> ⚠️ 以上路线会在研读安路官方参考例程后**进一步细化并调整**。

### 3.4 目标成果

- **确保完成**：全部基础要求（媒体读取、稳定 HDMI 显示、按键交互、HDMI 音频输出）
- **力争完成**：扩展要求中的「图片切换与转场特效」与「实时调节与信息叠加」两项
